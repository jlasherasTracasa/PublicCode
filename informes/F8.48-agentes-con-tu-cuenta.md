# F8.48
## Hecho
- `Config::backend(name)` y `BUILTIN_AGENTS`: `claude-code`, `copilot`, `gemini` y `opencode` funcionan sin declararlos en `[backends]`; lo declarado manda.
- `pcode run --backend <agente> --aplicar`: aplica los cambios de la sandbox si el agente termina bien (y pasa `--acepta`, si se da), con punto de control para `/deshacer`. La sandbox deja escribir el estado de cada agente (`~/.copilot`, `~/.claude`, `~/.gemini`, opencode), y Copilot se lanza con `-s`.
- `settings.get` devuelve `agents`: instalado y ruta (`pcode_tools::which_in`), orden de instalación para Linux o Windows, inicio de sesión, primera variable de token definida, modelo de `[backends.*]` y los backends propios lanzables. `pcode config proveedores` los lista y `pcode config proveedor copilot` explica cómo usarlo.
- Studio: sección «Agentes con tu cuenta» en Ajustes (estado, «Copiar» la orden de instalación, «Usar en una conversación», guía oficial) y plantilla «GitHub Copilot». El selector de modelo del panel del agente tiene el grupo «Agentes con tu cuenta», con modelo opcional, y recuerda la elección. El demonio lanza esas sesiones con `--aplicar`.
- Se puede seguir la conversación con el agente: el demonio guarda con qué se lanzó y cada mensaje nuevo lo relanza con lo hablado como contexto (`follow_up_task`, los mensajes más recientes hasta 6 000 caracteres).
- e2e de Studio: 11 comprobaciones nuevas con un `copilot` falso en el PATH, incluida una conversación de dos mensajes cuyos cambios llegan al proyecto con el modelo elegido.

## Decisiones
- Copilot entra como **agente**, no como proveedor por URL: GitHub Models, la API oficial compatible con OpenAI, se retiró el 30 de julio de 2026, y no hay otra vía oficial para llamar a los modelos de Copilot desde herramientas de terceros. No se usan endpoints no documentados.
- `doctor::which` se mueve a `pcode_tools::which` (con `which_in` para probarlo sin tocar el `PATH`); doctor lo reexporta.
- Las órdenes de instalación y de inicio de sesión salen de la guía oficial de Copilot CLI (npm con Node.js 22+, `winget install GitHub.Copilot`, `/login` o `COPILOT_GITHUB_TOKEN`/`GH_TOKEN`/`GITHUB_TOKEN` con el permiso «Copilot Requests»).
- `GITHUB_TOKEN` definido no garantiza el permiso de Copilot: la tarjeta solo dice que la variable está definida.
