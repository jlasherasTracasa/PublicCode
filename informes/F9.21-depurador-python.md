# F9.21-depurador-python
## Hecho
- El cliente DAP (`crates/pcode-dap`) ya estaba. Ahora el demonio lo usa: `crates/pcode-server/src/debug.rs` (`DebugManager`, una sesión por proyecto) y los métodos `debug.start`, `debug.setBreakpoints`, `debug.continue`, `debug.next`, `debug.stepIn`, `debug.stepOut`, `debug.variables` y `debug.stop`.
- Protocolo: eventos `debugStopped` (con la pila, rutas relativas al proyecto), `debugOutput` y `debugExited`, y los tipos `DebugFrameDto` y `DebugVariableDto` (TypeScript regenerado).
- IDE nativo: módulo `crates/pcode-ide/src/debug.rs` (puntos de ruptura, pila, variables, salida) y panel «Depuración»; F9 pone un punto de ruptura, F5 depura el `.py` abierto o continúa, F10/F11/Mayús+F11 dan pasos y Mayús+F5 detiene; menú «Ejecutar». La línea parada y las que tienen punto de ruptura se colorean en el margen.
- El programa y los puntos de ruptura tienen que estar dentro del proyecto (`safe_path`).

Prueba real contra el demonio con debugpy 1.x (`pcode daemon` + curl):
```
debug.start {"program":"prog.py","breakpoints":{"prog.py":[2]}} → true
evento debugStopped reason=breakpoint frames=[doble prog.py:2, <module> prog.py:6]
debug.variables {"frameId":2} → [{"kind":"int","name":"n","value":"21"}]
debug.next → evento debugStopped reason=step (prog.py:3)
debug.continue → debugOutput "resultado 42" → debugExited code=0
debug.next → error «no hay ninguna depuración en marcha»
```
## Decisiones
- `debugStopped` lleva ya la pila, para ahorrar una llamada al cliente.
- La prueba real destapó dos fallos que se corrigieron: debugpy manda telemetría como salida (se descarta) y la salida llega en trozos que no coinciden con las líneas (el IDE los une).
- Solo Python por ahora; si falta debugpy, el error dice cómo instalarlo.
