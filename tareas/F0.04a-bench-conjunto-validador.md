## Objetivo

1. Crea `conjunto.py` (ejecutable, `#!/usr/bin/env python3`, solo biblioteca estándar) con las funciones de
   abajo. Un conjunto es un archivo JSONL: una línea JSON por tarea con los campos de texto obligatorios `id`,
   `acepta`, `tarea`, `base`, `aceptada_en` y el opcional `cadena`. Se admiten campos de más.
2. `validar_linea(obj)`: problemas de un objeto ya parseado: `falta <campo>` (ausente, no es texto o vacío);
   `tarea debe ser un .md`; `base no es un commit` / `aceptada_en no es un commit` (deben ser hexadecimales de
   7 a 40 caracteres); `base y aceptada_en son iguales`.
3. `validar(texto, n=None)`: recorre las líneas no vacías; cada problema va precedido de `línea <k>: `
   (k empieza en 1). Añade `línea <k>: no es JSON`, `línea <k>: id repetido <id>` y, si se da `n` y el número
   de líneas es otro, `se esperaban <n> tareas y hay <m>`.
4. `validar_git(texto, repo)`: por cada línea válida comprueba con `git -C repo cat-file -e <sha>^{commit}`
   que `base` y `aceptada_en` existen: `línea <k>: no existe el commit <sha>`.
5. `main(argv)`: `conjunto.py [--n N] [--git] [--repo R] ARCHIVO`; problemas a stderr, código 1 si hay alguno.
6. Crea `test_conjunto.py` con los tests de la lista; el de git crea un repo temporal con
   `subprocess.run(["git", "init", …])` y un commit.

## Ejemplo (entrada y resultado esperado)

```
ok = {"id": "F1.09-tool-leer", "acepta": "cargo test -p pcode-tools read", "tarea": "tareas/F1.09-tool-leer.md",
      "base": "a1b2c3d", "aceptada_en": "e4f5a6b"}
validar_linea(ok) → []
validar_linea({**ok, "base": "zzz"}) → ["base no es un commit"]
validar(json.dumps(ok) + "\n" + json.dumps(ok) + "\n", n=20)
  → ["línea 2: id repetido F1.09-tool-leer", "se esperaban 20 tareas y hay 2"]
```

## Tests (con estos nombres)

- `test_linea_valida`: el objeto del ejemplo no da problemas
- `test_falta_campo`: sin `acepta` da `falta acepta`
- `test_commit_no_hexadecimal`: base `zzz` da `base no es un commit`
- `test_id_repetido_y_numero`: las dos líneas del ejemplo dan los dos problemas del ejemplo
- `test_linea_que_no_es_json`: una línea `{` da `línea 1: no es JSON`
- `test_git_commit_inexistente`: en un repo temporal, un sha inventado da `no existe el commit`
- `test_main_codigos`: main devuelve 0 con un archivo válido y 1 con uno inválido
