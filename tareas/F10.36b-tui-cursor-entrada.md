# F10.36b-tui-cursor-entrada — TUI: cursor movible en la entrada (flechas, Inicio/Fin, Ctrl+A/E/W/K)

## Contexto (lee esto y nada más)

- crates/pcode-tui/src/edit.rs (todas las funciones: `insert`, `backspace`, `left`, `up`, `row_col`…)
- crates/pcode-tui/src/app.rs (funciones `key`, `key_main`, `act`, `browse`, `complete_mention`, `refresh_suggestions`, `leader_key` y `submit`: todos los sitios que cambian `self.input`)
- crates/pcode-tui/src/render.rs (función `render`, sección «Entrada»: el cálculo de `(cx, cy)` y `f.set_cursor_position`)

## Objetivo

1. `app.rs`: añade a `App` `pub cursor: usize` (doc: «Posición del cursor en `input`, en bytes»), 0 en `App::new`.
2. `app.rs`, al principio de `key`: si `self.cursor > self.input.len()` o
   `!self.input.is_char_boundary(self.cursor)`, pon `self.cursor = self.input.len()`.
3. `app.rs`: sustituye la edición por el final por las funciones de `crate::edit` (con
   `&mut self.input, &mut self.cursor`): `self.input.push(c)` → `edit::insert`; el `pop` del brazo
   `Backspace` → `edit::backspace`; los `push('\n')` → `edit::insert(.., '\n')`; `push_str("    ")` →
   `edit::insert_str`. El brazo «Intro con `\` al final» solo aplica si además
   `self.cursor == self.input.len()` (quita la barra con `edit::backspace` e inserta `\n`).
4. `app.rs`: en TODOS los demás sitios que cambian `self.input` entero (búscalos con
   `grep -n "self.input" crates/pcode-tui/src/app.rs`: `clear()`, asignaciones `self.input = …`, `truncate`
   y `push`/`push_str` de `complete_mention`), añade justo después `self.cursor = self.input.len();`.
5. `app.rs`, `key_main`, brazos nuevos (antes del de `Char(c) if !ctrl`): `Left` → `edit::left`; `Right` →
   `edit::right`; `Home` y `Char('a') if ctrl` → `edit::home`; `End` y `Char('e') if ctrl` → `edit::end`;
   `Delete` → `edit::delete`; `Char('w') if ctrl` → `edit::delete_word_back`; `Char('k') if ctrl` →
   `edit::kill_to_end`; `Left`/`Right` con `KeyModifiers::ALT` → `edit::word_left` / `edit::word_right`.
   Todos devuelven `vec![]`.
6. `app.rs`, brazos `Up` / `Down`: quita la condición `!self.input.contains('\n')`. Nuevo comportamiento: si
   la entrada contiene `\n` y `edit::up` (o `edit::down`) devuelve `true`, no hagas nada más; en otro caso
   llama a `self.browse(..)` como ahora.
7. `app.rs`, `refresh_suggestions`: si `self.cursor != self.input.len()`, vacía las sugerencias y vuelve.
8. `render.rs`: el cursor se dibuja donde está `app.cursor`: calcula las líneas ajustadas de
   `&app.input[..app.cursor]` igual que `input_lines` (partir por `\n` y `wrap` con `inner_w`); `cx` = ancho
   de la última, `cy` = número de líneas − 1 − `skip` (con `saturating_sub`).

Sin firmas: Solo añade el campo `cursor` a App; el resto cambia el manejo de teclas y el dibujo del cursor

## Ejemplo (entrada y resultado esperado)

```
teclear "hola", Left, Left, teclear "X"      -> input == "hoXla", cursor == 3
teclear "a b", Ctrl+A, teclear "z"           -> input == "za b"
teclear "git commit", Ctrl+W                 -> input == "git "
input "uno\ndos" con el cursor al final: Up  -> cursor == 3 (final de "uno"), input sin cambiar, no se toca el historial
input "una línea" + Up con historial ["x"]   -> input == "x" y cursor == 1
pantalla 80×24 con input "hola" y cursor 2: la posición del cursor del terminal es (3, 21)
```

## Tests (con estos nombres)

- `cursor_inserta_en_medio`: el primer caso del ejemplo
- `cursor_inicio_fin_y_borrados`: el segundo y el tercer caso del ejemplo; y con `a b` y el cursor en 1 (Ctrl+A, Right), Ctrl+K deja `a`
- `cursor_arriba_en_multilinea_no_toca_el_historial`: el cuarto caso del ejemplo
- `cursor_arriba_en_una_linea_recorre_el_historial`: el quinto caso del ejemplo
- `cursor_al_final_tras_completar_y_borrar`: tras completar una mención con Tab y tras Ctrl+U, `cursor == input.len()`
- `cursor_render_80x24_en_su_sitio`: con `input = "hola"` y `cursor = 2`, `term.get_cursor_position()` del `TestBackend` es `(3, 21)`
