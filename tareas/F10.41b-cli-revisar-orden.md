## Objetivo

1. Crea `revisar.rs` con `ReviewArgs` (firma abajo) y `pub async fn review(a: ReviewArgs) -> anyhow::Result<i32>`.
2. `review`: el objetivo es `Staged` si `a.staged`; `Base(rama)` si `a.base` es `Some`; si no, `Worktree`.
   Llama a `pcode_server::assist::review_prompt_for(&cwd, &objetivo)`. Con `Err(e)`: escribe `e` en stderr y
   devuelve `Ok(2)` (sin llamar al modelo).
3. Con el prompt: carga la configuración, el proveedor y el modelo igual que `ask`
   (`Config::load_layered`, `build_provider`, `pick_model`) y envía un `ChatRequest` con dos mensajes:
   `Message::system("Eres un revisor de código exigente y concreto. Responde en español.")` y
   `Message::user(prompt)`; `tools: vec![]`, `max_tokens: Some(a.max_tokens)`.
4. Salida, igual que `ask`: en `texto`, el texto en streaming y un salto de línea final; en `json`, una línea
   `{"texto": …, "entrada": …, "salida": …}`. Devuelve `Ok(0)`.
5. `main.rs`: `mod revisar;`, variante `Revisar(revisar::ReviewArgs)` en `Cmd` con el doc
   `/// Revisa con el modelo los cambios sin commit (o lo preparado, o la rama) antes de publicarlos.` y el
   brazo `Some(Cmd::Revisar(a)) => std::process::exit(revisar::review(a).await?),`.
6. Crea `tests/revisar.rs` con los ayudantes `resp` y `pcode` de `tests/chat.rs` y uno `git(dir, args)` que
   ejecute `git -C dir …` y compruebe que sale bien. Prepara el repositorio con `git init -q`,
   `git config user.email t@t`, `git config user.name t`, un archivo, `git add -A` y `git commit -qm base`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-cli/src/revisar.rs
/// Argumentos de `pcode revisar`.
#[derive(Debug, clap::Args)]
pub struct ReviewArgs {
    /// Revisa solo lo preparado con `git add`.
    #[arg(long = "staged", conflicts_with = "base")]
    pub staged: bool,
    /// Revisa los commits de la rama actual que no están en esta rama base (p. ej. `main`).
    #[arg(long = "base")]
    pub base: Option<String>,
    /// Modelo.
    #[arg(long = "modelo")]
    pub model: Option<String>,
    /// Proveedor de `[proveedores]`.
    #[arg(long = "proveedor")]
    pub provider: Option<String>,
    /// Configuración del proyecto.
    #[arg(long = "config", default_value = "pcode.toml")]
    pub config: std::path::PathBuf,
    /// `texto` (en streaming) o `json` (`{"texto", "entrada", "salida"}`).
    #[arg(long = "formato", default_value = "texto")]
    pub format: String,
    /// Tokens de salida máximos.
    #[arg(long = "max-tokens", default_value_t = 4000)]
    pub max_tokens: u32,
}

/// Ejecuta `pcode revisar` y devuelve el código de salida.
pub async fn review(a: ReviewArgs) -> anyhow::Result<i32>;
```

## Ejemplo (entrada y resultado esperado)

```
(repositorio con un commit y lib.rs cambiado sin `git add`; mock que responde «🟡 falta un test. No está listo.»)
$ pcode revisar                   -> stdout contiene «falta un test», código 0
$ pcode revisar --formato json    -> {"texto":"🟡 falta un test. No está listo.","entrada":3,"salida":2}
$ pcode revisar --staged          -> stderr «no hay cambios preparados (git add) que revisar», código 2
$ pcode revisar  (en una carpeta sin git) -> stderr «el proyecto no es un repositorio git», código 2
```

## Tests (con estos nombres)

- `revisar_los_cambios_sin_commit`: con un cambio sin `git add`, `pcode revisar` sale con 0 y stdout contiene el texto del mock
- `revisar_formato_json`: `--formato json` da una línea JSON con `texto`, `entrada` y `salida`
- `revisar_staged_sin_nada_preparado_sale_con_2`: código 2 y stderr contiene `no hay cambios preparados`
- `revisar_sin_git_sale_con_2`: en un directorio temporal sin repositorio, código 2 y stderr contiene `no es un repositorio git`
- `revisar_respecto_a_una_rama`: tras `git branch base`, un cambio y un commit, `pcode revisar --base base` sale con 0
