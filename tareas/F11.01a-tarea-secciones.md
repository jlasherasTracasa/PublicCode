# F11.01a-tarea-secciones — Flujos: leer las secciones de una tarea (`Brief`) desde su Markdown

**Fase** F11 · **Ejecutor** haiku · **Hito** 1.4 · **Talla** M · **Depende de** F3.10-cli-flow

> Generado desde `tareas/plan/`. Sigue `AGENTS.md` y la skill `tarea-haiku`.

## Toca (los únicos archivos que puedes crear o modificar, más tu informe)

- `crates/pcode-flow/src/brief.rs`
- `crates/pcode-flow/src/lib.rs`
- `informes/F11.01a-tarea-secciones.md`

## Contexto (lee esto y nada más)

- crates/pcode-flow/src/task.rs (`TaskDef` y `parse_task`: `body` es el texto entero de la tarea cuando no hay frontmatter)
- tareas/F3.10-cli-flow.md (un archivo de tarea real: ficha, `## Toca`, `## Contexto`, `## Objetivo`)

## Objetivo

1. Crea `brief.rs` con `Brief` y `parse_brief` (firmas abajo). No uses `regex`: recorre las líneas a mano.
2. Ficha: la primera línea que empieza por `**Fase**` se parte por ` · `; cada trozo es `**Clave** valor`.
   `Ejecutor` → `executor`, `Talla` → `size`, `Hito` → `milestone`. Si no hay ficha, `executor = ""`.
3. Una línea que empieza por `> **Por qué es del coordinador:**` da `coordinator_reason` (el resto, sin
   espacios). Una línea que empieza por `Sin firmas:` pone `no_signatures = true`.
4. Secciones: una línea `## Título…` abre sección hasta la siguiente `## `. Se reconoce por cómo empieza el
   título en minúsculas: `toca`, `contexto`, `objetivo`, `firmas`, `ejemplo`, `tests`, `notas`, `subtareas`.
   - `toca`: cada línea `- ` aporta la ruta entre el primer par de comillas invertidas. Si la línea contiene
     `(configuración)` va a `extra`; si la ruta empieza por `informes/` se ignora; el resto va a `touches`.
   - `contexto`: cada línea `- ` (sin el guion) va a `context`, salvo `(nada)`.
   - `objetivo` y `notas`: el texto de la sección, con `trim()`.
   - `firmas` y `ejemplo`: las líneas de la sección que no empiezan por tres comillas invertidas, unidas con
     `\n` y con `trim()`.
   - `tests`: cada línea `- ` se guarda sin el guion y sin comillas invertidas (`- `a`: b` → `a: b`).
   - `subtareas`: pone `closing = true`.
5. `lib.rs`: añade `pub mod brief;` (orden alfabético) y `pub use brief::{Brief, parse_brief};`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/brief.rs
/// Secciones de una tarea escrita en Markdown (lo que necesita el lint y el control de `toca`).
#[derive(Debug, Clone, Default, PartialEq)]
pub struct Brief {
    pub executor: String,
    pub size: Option<String>,
    pub milestone: Option<String>,
    pub coordinator_reason: Option<String>,
    pub closing: bool,
    pub touches: Vec<String>,
    pub extra: Vec<String>,
    pub context: Vec<String>,
    pub objective: String,
    pub signatures: String,
    pub no_signatures: bool,
    pub example: String,
    pub notes: String,
    pub tests: Vec<String>,
}

/// Lee las secciones del cuerpo de una tarea (`TaskDef::body`).
pub fn parse_brief(body: &str) -> Brief;
```

## Tests (con estos nombres)

- `lee_la_ficha`: la entrada del ejemplo da ejecutor haiku, talla S y milestone None
- `toca_separa_configuracion_e_informe`: la entrada del ejemplo da touches con una ruta y extra con Cargo.toml
- `firmas_sin_las_vallas`: una sección Firmas con un bloque de código devuelve solo el código
- `tests_sin_comillas_invertidas`: la línea del ejemplo queda como `saluda: entra «Ana» y sale «hola Ana»`
- `subtareas_marca_cierre`: una sección `## Subtareas` pone closing a true
- `cuerpo_vacio`: la cadena vacía da Brief::default()
