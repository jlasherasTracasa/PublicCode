## Objetivo

1. Crea `board.rs` con las firmas de abajo.
2. `board`: una fila por tarea, en el orden de `tasks`. La celda se decide en este orden:
   a) el id está en `done` o `state.state(id)` es `TaskState::Integrated` → `Done`;
   b) `TaskState::Blocked(m)` → `Stuck(m)`;
   c) `TaskState::Running(_)` o `Accepted` → `Running`;
   d) alguna dependencia no está `Done` (según a) → `Waiting(esas dependencias, ordenadas)`;
   e) `Mode::Coordinator` → `Coordinator`;
   f) si no → `Ready`.
   `attempts` sale de `state.attempts` (0 si no consta). `unblocks` = cuántas tareas no hechas dependen de
   esta directa o indirectamente (recorrido con una pila; las dependencias que no existen se ignoran).
3. `next`: las filas `Ready`, ordenadas por `unblocks` de mayor a menor y, a igualdad, por id; como mucho `n`.
4. `render_board`: primera línea
   `hechas A · en marcha B · listas C · esperando D · coordinador E · atascadas F`, una línea vacía y una
   línea por fila que no esté hecha: `▶ id` (lista), `⏳ id (intento N)`, `… id — espera a x, y`,
   `⚠ id — la hace el coordinador`, `✗ id — motivo`. Sin filas pendientes, tras el resumen: `Todo hecho.`.
5. `lib.rs`: añade `pub mod board;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/board.rs
use crate::events::FlowState;
use crate::task::TaskDef;
use std::collections::HashSet;

/// Situación de una tarea en el tablero.
#[derive(Debug, Clone, PartialEq, serde::Serialize)]
pub enum Cell { Done, Running, Ready, Waiting(Vec<String>), Coordinator, Stuck(String) }

/// Fila del tablero.
#[derive(Debug, Clone, PartialEq, serde::Serialize)]
pub struct BoardRow { pub id: String, pub cell: Cell, pub attempts: u32, pub unblocks: usize }

/// Calcula el tablero.
pub fn board(tasks: &[TaskDef], done: &HashSet<String>, state: &FlowState) -> Vec<BoardRow>;
/// Las `n` tareas listas que más desbloquean.
pub fn next(rows: &[BoardRow], n: usize) -> Vec<&BoardRow>;
/// Tablero en texto.
pub fn render_board(rows: &[BoardRow]) -> String;
```

## Ejemplo (entrada y resultado esperado)

```
Tareas A, B (depende de A), C (depende de B), D (coordinador); done = {}; estado vacío:
  board → A Ready (unblocks 2), B Waiting(["A"]) (unblocks 1), C Waiting(["B"]), D Coordinator
  next(rows, 5) → [A]
  render_board → "hechas 0 · en marcha 0 · listas 1 · esperando 2 · coordinador 1 · atascadas 0\n\n▶ A\n… B — espera a A\n… C — espera a B\n⚠ D — la hace el coordinador\n"
Con done = {A}: B pasa a Ready.
```

## Tests (con estos nombres)

- `lista_y_esperando`: las tareas del ejemplo dan A lista y B esperando a A
- `hecha_por_informe_o_integrada`: un id en done y otro con evento Integrada salen como Done
- `bloqueada_lleva_el_motivo`: un evento Bloqueada da Stuck con su motivo
- `desbloquea_cuenta_transitivas`: en la cadena A, B, C la fila A tiene unblocks 2
- `siguiente_ordena_por_desbloqueo`: entre dos listas sale primero la que más desbloquea y luego por id
- `coordinador_no_es_lista`: la tarea de coordinador no aparece en next
- `render_resume_y_explica`: el texto del ejemplo coincide carácter a carácter
