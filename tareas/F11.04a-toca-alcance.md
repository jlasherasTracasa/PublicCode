# F11.04a-toca-alcance — Flujos: rutas permitidas de una tarea y cambios fuera de alcance (lógica pura)

## Objetivo

1. Crea `scope.rs` con las tres funciones de abajo.
2. `allowed_paths`: si `task.touches` no está vacío, devuelve eso; si no, `parse_brief(&task.body)` y devuelve
   `touches` seguido de `extra`. Una tarea sin lista devuelve vacío.
3. `outside_scope`: devuelve, ordenadas y sin repetir, las rutas de `changed` que no están permitidas. Una
   ruta está permitida si: es igual a una entrada de `allowed`; o una entrada acaba en `/` y la ruta empieza
   por ella; o es `Cargo.lock`; o empieza por `informes/<task_id>` y acaba en `.md`. Si `allowed` está vacío
   no hay restricción: devuelve vacío.
4. `overlap`: true si alguna ruta de `a` choca con alguna de `b`: son iguales, o una acaba en `/` y la otra
   empieza por ella. Con cualquiera de las dos listas vacía, false.
5. `lib.rs`: añade `pub mod scope;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/scope.rs
use crate::task::TaskDef;

/// Rutas que la tarea puede crear o modificar (vacío = sin lista: no se restringe).
pub fn allowed_paths(task: &TaskDef) -> Vec<String>;
/// Rutas cambiadas que quedan fuera de `allowed`.
pub fn outside_scope(changed: &[String], allowed: &[String], task_id: &str) -> Vec<String>;
/// ¿Comparten algún archivo dos listas de rutas?
pub fn overlap(a: &[String], b: &[String]) -> bool;
```

## Ejemplo (entrada y resultado esperado)

```
outside_scope(["src/a.rs", "src/b.rs", "informes/T1.md", "Cargo.lock"], ["src/a.rs"], "T1") → ["src/b.rs"]
outside_scope(["web/x.js"], ["web/"], "T1") → []
outside_scope(["cualquiera"], [], "T1") → []
overlap(["src/a.rs"], ["src/"]) → true      overlap(["a.rs"], ["b.rs"]) → false
```

## Tests (con estos nombres)

- `fuera_de_la_lista`: la primera línea del ejemplo devuelve solo src/b.rs
- `carpeta_cubre_su_contenido`: una entrada que acaba en / permite lo que cuelga de ella
- `sin_lista_no_se_restringe`: allowed vacío devuelve vacío aunque haya cambios
- `informe_de_otra_tarea_no_vale`: informes/T2.md queda fuera para la tarea T1
- `permitidas_del_frontmatter`: una tarea con touches no vacío devuelve eso sin leer el cuerpo
- `permitidas_de_la_seccion_toca`: una tarea sin frontmatter devuelve las rutas de `## Toca` más las de configuración
- `solape_por_carpeta_y_por_igualdad`: los dos casos del ejemplo
