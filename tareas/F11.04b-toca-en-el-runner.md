## Objetivo

1. `runner.rs`: añade a `RunnerCfg` el campo `pub enforce_scope: bool` con su comentario `///` («Rechazar los
   intentos que cambian archivos fuera de `toca`.»).
2. `runner.rs`: añade la función pública `scope_failure` (firma abajo). Si `enforce` es false devuelve None.
   Si no, calcula `outside_scope(rutas de changes, &allowed_paths(task), &task.id)`; vacío → None; si no →
   `Some("fuera de toca: a, b")` (rutas separadas por `, `).
3. En `Runner::execute`, después de `let key = …` y antes de `let ok = …`: llama a
   `sandbox.changes()` (propaga el error con `map_err(|e| e.to_string())?`) y a `scope_failure(t, &changes,
   self.cfg.enforce_scope)`. Si la aceptación pasó (`st.code == 0`) pero hay fallo de alcance: `ok = false` y
   `key = vec![mensaje]`, de modo que el relevo (`build_handoff`) y `summary` lleven ese mensaje y el intento
   se trate como una aceptación fallida (la sandbox se descarta en `tick`, como ya ocurre).
4. Actualiza TODAS las construcciones `RunnerCfg { … }` (búscalas con `grep -rn "RunnerCfg {" crates/`): en
   los tests de `runner.rs`, `enforce_scope: true`; en `flow_cmd.rs`, rama `Run`: `enforce_scope: !sin_toca`,
   con el flag nuevo `--sin-toca` (bool, «No rechazar los cambios fuera de la lista `toca` de cada tarea.»).
5. Tests en el módulo `tests` de `runner.rs`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/runner.rs
/// Mensaje de rechazo si `changes` toca rutas fuera de la lista de la tarea (None = todo en regla).
pub fn scope_failure(task: &TaskDef, changes: &[pcode_sandbox::Change], enforce: bool) -> Option<String>;
```

## Ejemplo (entrada y resultado esperado)

```
Tarea con frontmatter `toca: [permitido.txt]`; cambios: permitido.txt (Added) y otro.txt (Added):
  scope_failure(&t, &changes, true)  → Some("fuera de toca: otro.txt")
  scope_failure(&t, &changes, false) → None
En el runner (test con MockBackend que escribe otro.txt y `acepta` = `true`): el intento acaba en
`failed`, nada se integra y `otro.txt` no aparece en el repo.
```

## Tests (con estos nombres)

- `fuera_de_toca_da_mensaje`: la tarea del ejemplo devuelve el mensaje con otro.txt
- `fuera_de_toca_desactivado`: con enforce a false devuelve None
- `fuera_de_toca_sin_lista_no_restringe`: una tarea sin toca devuelve None aunque haya cambios
- `runner_fuera_de_toca_no_integra`: con MockBackend que escribe otro.txt, la tarea falla y el repo no cambia (se salta sin namespaces de usuario, como los demás tests del runner)

## No hagas

- No cambies `integrate.rs`
- No conviertas el rechazo en un error del `tick`: es un intento fallido más, con relevo
- No toques los tests existentes salvo para añadir el campo nuevo a `RunnerCfg`

## Notas

En los tests, `Change` se construye con `pcode_sandbox::Change { path: "otro.txt".into(), kind:
pcode_sandbox::ChangeKind::Added }`. El auxiliar `t(...)` de los tests deja `touches` vacío: para estos
tests crea la tarea con `touches: vec!["permitido.txt".into()]`.
