## Objetivo

El problema: si el proceso muere con una tarea en marcha, al reconstruir el estado esa tarea queda `Running`
para siempre (nadie la relanza) y, si se pidió parar, `stop` queda a true para siempre.
1. `events.rs`: añade a `FlowEvent` las variantes `Interrumpida { tarea: String, intento: u32 }` («El proceso
   se cortó con la tarea en marcha.») y `Reanudada` («El flujo se retoma tras una parada.»).
2. En `FlowState::replay`: `Interrumpida` deja la tarea en `TaskState::Pending` y pone
   `attempts[tarea] = intento.saturating_sub(1)` (el intento cortado no cuenta). `Reanudada` pone
   `stop = false`.
3. Añade `FlowState::orphans` (firma abajo): las tareas en `Running(n)` → `(id, n)` y las `Accepted` →
   `(id, intentos que constan)`, en orden de id.
4. `runner.rs`: añade `Runner::recover` (firma abajo): lee el estado; emite `Interrumpida` por cada huérfana;
   si `state.stop` es true emite `Reanudada`; devuelve los ids de las huérfanas.
5. Tests: los de eventos en el módulo `tests` de `events.rs` y el del runner en el de `runner.rs`
   (con `Store::open_in_memory()`, `persist` de un `Lanzada` y un `Runner` sin backends).

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/events.rs
impl FlowState {
    /// Tareas que quedaron a medias (en marcha o aceptadas sin integrar) con su intento.
    pub fn orphans(&self) -> Vec<(String, u32)>;
}

// crates/pcode-flow/src/runner.rs
impl Runner {
    /// Devuelve a pendientes las tareas que un proceso anterior dejó a medias y levanta la parada.
    pub fn recover(&mut self) -> Result<Vec<String>, String>;
}
```

## Ejemplo (entrada y resultado esperado)

```
eventos: [Lanzada{A,1,"m"}, Lanzada{B,2,"m"}, Parada]
  replay → A Running(1), B Running(2), stop = true; orphans() → [("A",1), ("B",2)]
recover() → ["A","B"] y añade Interrumpida{A,1}, Interrumpida{B,2}, Reanudada
  replay → A Pending (attempts 0), B Pending (attempts 1), stop = false
```

## Tests (con estos nombres)

- `reanudar_interrumpida_no_gasta_intento`: tras Lanzada intento 2 e Interrumpida, la tarea está Pending con attempts 1
- `reanudar_levanta_la_parada`: Parada seguida de Reanudada deja stop a false
- `reanudar_huerfanas_en_orden`: los eventos del ejemplo dan A y B con sus intentos
- `reanudar_recover_emite_eventos`: con un Lanzada guardado, recover devuelve la tarea y el estado queda Pending
- `reanudar_sin_huerfanas_no_emite`: con solo un Integrada guardado, recover devuelve vacío y no añade eventos
