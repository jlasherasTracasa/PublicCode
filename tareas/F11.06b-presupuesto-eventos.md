## Contexto (lee esto y nada más)

- crates/pcode-flow/src/budget.rs (`Spent` y `Spent::add`)

## Objetivo

1. En `events.rs`, añade a `FlowEvent`:
   - `Consumo { tarea: String, intento: u32, entrada: u64, salida: u64, segundos: u64 }` («Tokens y tiempo
     gastados por un intento.»);
   - `PresupuestoAgotado { motivo: String }` («El flujo se paró por presupuesto.»).
2. Añade a `FlowState` los campos `pub spent: crate::budget::Spent` («Gasto acumulado.»),
   `pub spent_by_task: BTreeMap<String, crate::budget::Spent>` («Gasto por tarea.») y
   `pub budget_stop: Option<String>` («Motivo si se paró por presupuesto.»). `FlowState` ya deriva `Default`.
3. En `FlowState::replay`: `Consumo` suma `Spent { tokens_in: entrada, tokens_out: salida, seconds:
   segundos }` a `spent` y a `spent_by_task[tarea]`. `PresupuestoAgotado` pone `stop = true` y
   `budget_stop = Some(motivo)`. En la rama de `Reanudada`, además de `stop = false`, pon
   `budget_stop = None` (el gasto acumulado NO se borra).
4. Tests en el módulo `tests` de `events.rs`, con nombres que empiezan por `presupuesto_evento_`.

Sin firmas: solo añade variantes a `FlowEvent` y campos a `FlowState`; están descritos en el objetivo

## Ejemplo (entrada y resultado esperado)

```
replay([Consumo{A,1,100,20,30}, Consumo{A,2,50,10,5}, Consumo{B,1,1,1,1}])
  → spent = Spent{151, 31, 36}; spent_by_task["A"] = Spent{150, 30, 35}
replay([PresupuestoAgotado{"x"}]) → stop true, budget_stop Some("x")
replay([PresupuestoAgotado{"x"}, Reanudada]) → stop false, budget_stop None
```

## Tests (con estos nombres)

- `presupuesto_evento_acumula_consumo`: los tres Consumo del ejemplo dan los totales y el gasto de A
- `presupuesto_evento_para_el_flujo`: PresupuestoAgotado pone stop y guarda el motivo
- `presupuesto_evento_reanudar_limpia_el_motivo`: tras Reanudada no hay parada ni motivo y el gasto sigue
- `presupuesto_evento_json_ida_y_vuelta`: un Consumo serializado con serde_json se lee igual
