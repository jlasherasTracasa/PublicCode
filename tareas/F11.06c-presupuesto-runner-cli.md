## Objetivo

1. `runner.rs`: añade a `RunnerCfg` el campo `pub budget: crate::budget::FlowBudget` («Presupuesto del flujo
   entero.») y a `TickSummary` el campo `pub budget_stop: Option<String>` («Motivo si el flujo se paró por
   presupuesto.»).
2. En `Runner::execute`: mide el tiempo con `std::time::Instant::now()` desde antes de `backend.run` hasta
   después de la aceptación. Añade a `Done` los campos `tokens_in`, `tokens_out` (de `res.usage`, 0 si es
   None) y `seconds`.
3. En `Runner::tick`, al recorrer `results`, lo primero para cada `Ok(d)` es emitir
   `FlowEvent::Consumo { tarea, intento, entrada, salida, segundos }`.
4. Al principio de `tick`, tras leer `state`: si `!state.stop` y `self.cfg.budget.exceeded(&state.spent)`
   devuelve `Some(m)`: emite `FlowEvent::PresupuestoAgotado { motivo: m.clone() }` y devuelve
   `TickSummary { budget_stop: Some(m), ..Default::default() }` sin lanzar nada. En `run_until_idle`, copia
   `budget_stop` al total si viene (el bucle ya termina porque no se lanza nada).
5. Actualiza todas las construcciones `RunnerCfg { … }` (`grep -rn "RunnerCfg {" crates/`): en los tests,
   `budget: Default::default()`.
6. `flow_cmd.rs`, rama `Run`: flags `--max-tokens` (`Option<u64>`), `--max-euros` (`Option<f64>`),
   `--max-minutos` (`Option<u64>`), `--precio-entrada` y `--precio-salida` (`f64`, por defecto 0.0, euros por
   millón de tokens); con ellos se construye `FlowBudget`. Si el resumen trae `budget_stop`, imprime en stderr
   `parado: <motivo>` y devuelve 3 (el código de «presupuesto»).

Sin firmas: añade campos a `RunnerCfg`, `TickSummary` y `Done` y flags a `Run`; no hay funciones públicas nuevas

## Ejemplo (entrada y resultado esperado)

```
Runner con budget.max_tokens = Some(10) y un evento guardado Consumo{A,1,8,5,1} (13 tokens):
  tick() → TickSummary { budget_stop: Some("presupuesto de tokens agotado: 13 de 10"), launched: [], .. }
  state() → stop true, budget_stop Some(..)
  un segundo tick() → no vuelve a emitir PresupuestoAgotado (state.stop ya es true) y no lanza nada
```

## Tests (con estos nombres)

- `presupuesto_runner_agotado_no_lanza`: el caso del ejemplo devuelve budget_stop y launched vacío (runner sin sandbox, con Store en memoria)
- `presupuesto_runner_no_repite_el_evento`: tras dos tick solo hay un PresupuestoAgotado guardado
- `presupuesto_runner_sin_limites_sigue`: con FlowBudget::default() y el mismo Consumo, budget_stop es None
