# F11.07b-informe-flujo-cli — CLI: `pcode flow informe` y `.pcode/informe-flujo.md` al terminar `flow run`

## Contexto (lee esto y nada más)

## Objetivo

1. En `flow_cmd.rs`, variante nueva `Informe { tareas: PathBuf, salida: Option<PathBuf> }` («Informe final del
   flujo: qué se integró, intentos, coste y bloqueos.») con `--tareas` (por defecto `tareas`) y `--salida`.
2. Rama `Informe`: `let (tasks, events) = load_flow(&tareas)?;` y
   `pcode_flow::report::flow_report(&tasks, &events, &FlowBudget::default())`. Con `--salida` lo escribe en
   ese archivo (creando la carpeta) e imprime `informe: <ruta>`; sin él lo imprime en stdout. Devuelve 0.
3. Rama `Run`: después de escribir `.pcode/estado.md`, escribe también `.pcode/informe-flujo.md` con
   `flow_report` usando el `FlowBudget` de la ejecución (para que salga el coste) y los eventos de
   `load_flow(&tareas)`; imprime en stderr `informe: .pcode/informe-flujo.md`.
4. Añade a `tests/flow.rs` los tests de la lista.

Sin firmas: solo añade una variante de `FlowCmd` y su rama; la API está en `pcode_flow::report`

## Ejemplo (entrada y resultado esperado)

```
tareas/a.md = "<!-- acepta: true -->\n<!-- modo: aislado -->\n# a\n"   (sin .pcode/flow.db)
$ pcode flow informe                 → stdout contiene "# Informe del flujo", "- Integradas: 0 de 1" y "| a | pendiente | 0 | — | — | 0 |"
$ pcode flow informe --salida out/i.md → crea out/i.md y stdout es "informe: out/i.md"
```

## Tests (con estos nombres)

- `informe_sin_flujo_lista_pendientes`: la primera orden del ejemplo imprime el título, el resumen y la fila de a
- `informe_a_un_archivo`: con --salida se crea el archivo con el mismo contenido
