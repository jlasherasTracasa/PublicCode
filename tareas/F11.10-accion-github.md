# F11.10-accion-github — Acción de GitHub (`action.yml`) para ejecutar `pcode run` o `pcode flow` en CI

**Fase** F11 · **Ejecutor** haiku · **Hito** 1.4 · **Talla** S · **Depende de** F11.09-flow-escalado-configurable

> Generado desde `tareas/plan/`. Sigue `AGENTS.md` y la skill `tarea-haiku`.

## Toca (los únicos archivos que puedes crear o modificar, más tu informe)

- `action.yml`
- `docs/accion-github.md`
- `informes/F11.10-accion-github.md`

## Contexto (lee esto y nada más)

- install.sh (cabecera: variables `PCODE_VERSION` y `PCODE_DIR`; instala el binario `pcode` de una release)
- .github/workflows/ci.yml (estilo de los workflows del repo)

## Objetivo

1. Crea `action.yml` en la raíz del repo: una acción **compuesta** (`runs.using: composite`) con el esqueleto
   de abajo. Entradas: `orden` (argumentos de `pcode`, por defecto `flow comprobar`), `version` (etiqueta de
   release, por defecto vacía = la última), `directorio` (por defecto `.`). Salida: `codigo` (código de salida
   de `pcode`).
2. Pasos, todos con `shell: bash`: (a) «Instalar pcode»: ejecuta `"${{ github.action_path }}/install.sh"` con
   `PCODE_VERSION: ${{ inputs.version }}` y `PCODE_DIR: ${{ runner.temp }}/pcode-bin`, y añade esa carpeta a
   `$GITHUB_PATH`; (b) «Ejecutar pcode» con `id: pcode` y `working-directory: ${{ inputs.directorio }}`:
   `set +e; pcode ${{ inputs.orden }} --formato json > "$RUNNER_TEMP/pcode-salida.json"; codigo=$?`, escribe
   `codigo=$codigo` en `$GITHUB_OUTPUT`, vuelca el archivo en `$GITHUB_STEP_SUMMARY` dentro de un bloque de
   código y termina con `exit $codigo`.
3. Las claves de modelo NO son entradas de la acción: llegan como variables de entorno del job
   (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`) desde `secrets`. No escribas ningún secreto.
4. Crea `docs/accion-github.md` (en español, con tablas): qué hace, tabla de entradas y salida, tabla de
   códigos de salida (0 hecho, 2 fallo, 3 presupuesto, 4 atasco) y dos ejemplos de workflow completos: uno
   que solo valida el plan (`orden: flow comprobar`, sin claves) y otro que ejecuta
   `orden: flow run --backend modelo --max-euros 2` con `env: ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}`.

## Firmas (cópialas tal cual)

```yaml
# action.yml
name: PublicCode
description: Ejecuta pcode (run, flow comprobar, flow run…) en un workflow y publica el resultado
inputs:
  orden:
    description: Argumentos de pcode
    required: false
    default: flow comprobar
  version:
    description: Etiqueta de la release de pcode (vacío = la última)
    required: false
    default: ""
  directorio:
    description: Carpeta del proyecto
    required: false
    default: "."
outputs:
  codigo:
    description: Código de salida de pcode
    value: ${{ steps.pcode.outputs.codigo }}
runs:
  using: composite
  steps: []   # los dos pasos del objetivo
```

## Tests (con estos nombres)
