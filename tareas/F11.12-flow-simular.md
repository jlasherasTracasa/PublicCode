## Objetivo

1. Crea `waves.rs` con `DryRun`, `dry_run` y `render_dry_run` (firmas abajo). Lógica pura.
2. `dry_run`: parte de `completadas = done`. Repite como mucho `tasks.len() + 1` veces: candidatas = tareas
   (por orden de id) que no están completadas, no son `Mode::Coordinator` y tienen todas sus dependencias
   completadas; de ellas elige hasta `max_parallel.max(1)`, con una sola `Mode::Kernel` por ola; si no elige
   ninguna, termina; si no, añade la ola y marca las elegidas como completadas (la simulación supone que
   todas se aceptan). Al final: `coordinator` = tareas `Mode::Coordinator` que no están en `done`;
   `waiting` = las demás que no llegaron a completarse (dependen de una de coordinador).
3. `render_dry_run`: una línea `Ola <n>: a, b` por ola; después `Coordinador: x, y` y
   `Esperan al coordinador: z` (cada una solo si no está vacía); si no hay ninguna ola ni nada pendiente:
   `Nada que hacer.`.
4. `lib.rs`: añade `pub mod waves;`.
5. `flow_cmd.rs`: variante `Simular { tareas: PathBuf, paralelo: usize, format: String }` («Muestra qué se
   lanzaría y en qué orden, sin ejecutar nada.») con `--tareas` (por defecto `tareas`), `--paralelo` (por
   defecto 4) y `--formato` (por defecto `texto`). Rama: `load_flow`, `done_ids` (añade a `done` los ids
   integrados: `FlowState::replay(&events).done()`), `dry_run` y `render_dry_run` (texto) o el JSON de
   `DryRun`. Devuelve 0.
6. `tests/flow.rs`: los tests `simular_*`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/waves.rs
use crate::task::TaskDef;
use std::collections::HashSet;

/// Resultado de simular el flujo.
#[derive(Debug, Clone, Default, PartialEq, serde::Serialize)]
pub struct DryRun {
    #[serde(rename = "olas")]
    pub waves: Vec<Vec<String>>,
    #[serde(rename = "coordinador")]
    pub coordinator: Vec<String>,
    #[serde(rename = "esperan")]
    pub waiting: Vec<String>,
}

/// Simula el flujo suponiendo que cada tarea se acepta a la primera.
pub fn dry_run(tasks: &[TaskDef], done: &HashSet<String>, max_parallel: usize) -> DryRun;
/// Texto de la simulación.
pub fn render_dry_run(d: &DryRun) -> String;
```

## Ejemplo (entrada y resultado esperado)

```
Tareas (todas Mode::Isolated salvo d): a; b (depende de a); c; d (coordinador); e (depende de d)
dry_run(tareas, {}, 2) → waves [["a","c"],["b"]], coordinator ["d"], waiting ["e"]
render → "Ola 1: a, c\nOla 2: b\nCoordinador: d\nEsperan al coordinador: e\n"
dry_run(tareas, {}, 1) → waves [["a"],["b"],["c"]]
Dos tareas Mode::Kernel sin dependencias y max_parallel 4 → waves [["k1"],["k2"]]
```

## Tests (con estos nombres)

- `olas_respetan_dependencias_y_paralelismo`: el primer caso del ejemplo
- `de_una_en_una`: con max_parallel 1 salen tres olas de una tarea
- `un_kernel_por_ola`: dos tareas Kernel van en olas distintas
- `las_hechas_no_se_simulan`: con a en done, la primera ola es b y c
- `render_texto_exacto`: el texto del ejemplo coincide carácter a carácter
- `simular_cli_imprime_olas`: con tareas/a.md y tareas/b.md (b depende de a), `flow simular` imprime `Ola 1: a` y `Ola 2: b`
