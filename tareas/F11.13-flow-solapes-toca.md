# F11.13-flow-solapes-toca — Flujos: no lanzar a la vez dos tareas que tocan el mismo archivo

## Objetivo

Dos tareas en paralelo que cambian el mismo archivo acaban en un conflicto al integrar: la segunda pisa a la
primera. El planificador debe dejar la segunda para el ciclo siguiente.
1. En `scheduler.rs`, función `plan`: antes del bucle `for t in ready`, crea
   `let mut busy: Vec<Vec<String>> = …` con `crate::scope::allowed_paths(tarea)` de cada tarea de `running`
   que exista en el DAG (`dag.get(id)`).
2. Dentro del bucle, justo después de la comprobación
   `if flags.stop || flags.provider_down || n_running >= limits.max_parallel { continue; }` y ANTES del bloque
   `if t.mode == Mode::Kernel`: calcula `let paths = crate::scope::allowed_paths(t);` y, si
   `busy.iter().any(|b| crate::scope::overlap(b, &paths))`, haz `continue` (la tarea queda lista y se lanzará
   en otro ciclo, cuando la otra termine).
3. Cuando la tarea se lanza (donde está `p.launch.push(...)`), añade `paths` a `busy`.
4. Una tarea sin lista de archivos (`allowed_paths` vacío) no solapa con nada: `overlap` ya devuelve false.
5. Añade los tests al módulo `tests` de `scheduler.rs`. El auxiliar `t(id, mode)` deja `touches` vacío: crea
   las tareas de estos tests con `TaskDef { touches: vec!["src/a.rs".into()], ..t("A", Mode::Isolated) }`.

Sin firmas: cambia el cuerpo de `plan` sin tocar su firma ni añadir funciones públicas

## Ejemplo (entrada y resultado esperado)

```
A y B tocan src/a.rs; C toca src/c.rs; las tres listas, max_parallel 4, nada en marcha:
  plan(...).launch → ["A", "C"]        (B espera a que A termine)
Con A en marcha (evento Lanzada) y B lista: plan(...).launch → []  si solo queda B
A toca la carpeta `web/` y B toca `web/x.js` → B tampoco se lanza con A
```

## Tests (con estos nombres)

- `solape_no_lanza_dos_con_el_mismo_archivo`: el primer caso del ejemplo lanza A y C pero no B
- `solape_con_una_en_marcha`: con A en marcha, B (mismo archivo) no se lanza
- `solape_por_carpeta`: una tarea que toca `web/` bloquea a otra que toca `web/x.js`
- `solape_sin_lista_no_bloquea`: dos tareas sin lista de archivos se lanzan a la vez

## No hagas

- No cambies la firma de `plan` ni los structs `Limits`, `Flags` y `Plan`
- No marques la tarea como bloqueada: solo se aplaza
- No toques los tests existentes
