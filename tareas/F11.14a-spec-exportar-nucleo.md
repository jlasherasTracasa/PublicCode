# F11.14a-spec-exportar-nucleo — Especificaciones: convertir `SpecTask` en archivos de tarea del flujo (lógica pura)

## Objetivo

El planificador de especificaciones escribe `specs/<nombre>/tareas.md` (una lista), pero `pcode flow` ejecuta
un archivo Markdown por tarea. Esta función hace el puente.
1. Crea `export.rs` con `export_tasks` (firma abajo). Devuelve `(archivos, omitidas)`:
   - `archivos`: por cada tarea NO hecha (`done == false`) y con `accept`, el par
     `("<spec>-<id>", contenido)`, en el orden de la lista;
   - `omitidas`: `"<id>: ya está hecha"` o `"<id>: no tiene acepta"` para las demás.
2. Contenido de cada archivo (mira el ejemplo): cabeceras `acepta`, `modo: aislado` y `depende` (ids de las
   dependencias con el prefijo `<spec>-`, separadas por `, `; se omiten las dependencias a tareas hechas);
   título `# <spec>-<id> — <title>`; ficha `**Fase** <spec> · **Ejecutor** haiku · **Talla** M · **Depende
   de** <las mismas o —>`; `## Toca` con una línea por archivo de `touches` (o `- PENDIENTE: `ruta``);
   `## Contexto` con `- specs/<spec>/spec.md (requisitos <R1, R2>: qué debe cumplir esta tarea)`;
   `## Objetivo` con `detail` (o `PENDIENTE: pasos numerados` si está vacío); `## Tests` con
   `- PENDIENTE: `nombre`: qué entra y qué se espera`.
3. `lib.rs`: añade `pub mod export;` y `pub use export::export_tasks;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-spec/src/export.rs
use crate::tasks::TaskList;

/// Convierte las tareas pendientes de una especificación en archivos de tarea del flujo:
/// (nombre de archivo sin `.md`, contenido). El segundo valor explica las que no se exportan.
pub fn export_tasks(spec_name: &str, list: &TaskList) -> (Vec<(String, String)>, Vec<String>);
```

## Ejemplo (entrada y resultado esperado)

```
spec "saludo"; T1 hecha; T2 { title: "Escribir la despedida", requirements: ["R2"], touches: ["adios.txt"],
depends: ["T1"], accept: Some("test -f adios.txt"), detail: "Crea adios.txt." }; T3 sin accept
→ archivos = [("saludo-T2", texto)], omitidas = ["T1: ya está hecha", "T3: no tiene acepta"], y texto es:

<!-- acepta: test -f adios.txt -->
<!-- modo: aislado -->
<!-- depende:  -->
# saludo-T2 — Escribir la despedida

**Fase** saludo · **Ejecutor** haiku · **Talla** M · **Depende de** —

## Toca

- `adios.txt`

## Contexto

- specs/saludo/spec.md (requisitos R2: qué debe cumplir esta tarea)

## Objetivo

Crea adios.txt.

## Tests

- PENDIENTE: `nombre`: qué entra y qué se espera
```

## Tests (con estos nombres)

- `exporta_la_pendiente_con_acepta`: el caso del ejemplo da un archivo saludo-T2 con el texto exacto
- `omite_hechas_y_sin_acepta`: las omitidas del ejemplo, en ese orden
- `dependencias_con_prefijo`: una tarea que depende de otra pendiente lleva `<!-- depende: saludo-T1 -->`
- `sin_archivos_marca_pendiente`: touches vacío da la línea con PENDIENTE en Toca
- `lista_vacia`: una TaskList sin tareas da dos vectores vacíos
