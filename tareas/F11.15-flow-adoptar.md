# F11.15-flow-adoptar — `pcode flow adoptar`: pasar los borradores a `tareas/` solo si todos pasan el lint

## Objetivo

`pcode flow desglosar` y `pcode spec exportar` dejan borradores en `<tareas>/borradores/`. Esta orden los
adopta: los mueve a `<tareas>/` solo si TODOS son válidos; nunca pisa una tarea existente.
1. Crea `drafts.rs` con `check_drafts` (firma abajo), pura. Problemas que devuelve (vacío = se pueden adoptar):
   - `<id>: ya existe una tarea con ese id` si el id está en `existing`;
   - `<id>: depende de <d>, que no existe` si la dependencia no está ni en `existing` ni en `drafts`;
   - cada problema de `lint_all(drafts, &HashSet::new(), exists)` como `<id>: [regla] mensaje`.
2. `lib.rs`: añade `pub mod drafts;`.
3. `flow_cmd.rs`: variante `Adoptar { tareas: PathBuf }` («Mueve los borradores válidos a la carpeta de
   tareas.») con `--tareas` (por defecto `tareas`). Rama:
   - si `<tareas>/borradores` no existe o no tiene `.md`: imprime `no hay borradores` y devuelve 0;
   - carga `existing = load_dir(&tareas)` y `drafts = load_dir(&borradores)`; si hay menos `drafts` que
     archivos `.md`, añade el problema `hay borradores sin cabecera acepta`;
   - `check_drafts(&drafts, &existing, &|p| root.join(p).exists())`; con problemas: uno por línea en stderr
     con `✗ ` delante y devuelve 2 sin mover nada;
   - sin problemas: `std::fs::rename` de cada `<borradores>/<id>.md` a `<tareas>/<id>.md`, imprime
     `adoptada: <ruta>` por cada una y devuelve 0.
4. `tests/flow.rs`: los tests `adoptar_*`.

## Ejemplo (entrada y resultado esperado)

```
existing = [T1]; drafts = [T1a válida, T1b válida que depende de T1a] → []
drafts = [T1 válida]                         → ["T1: ya existe una tarea con ese id"]
drafts = [T2a válida que depende de X]       → ["T2a: depende de X, que no existe"]
$ pcode flow adoptar   (con dos borradores válidos) → código 0, "adoptada: tareas/T1a.md", y tareas/borradores queda sin .md
$ pcode flow adoptar   (con un borrador de objetivo vacío) → código 2, stderr contiene "✗ " y "[objetivo]", nada se mueve
```

## Tests (con estos nombres)

- `borradores_validos_pasan`: el primer caso del ejemplo devuelve vacío
- `id_que_ya_existe`: el segundo caso devuelve el problema del id
- `dependencia_inexistente`: el tercer caso devuelve el problema de la dependencia
- `borrador_que_no_pasa_el_lint`: un borrador sin objetivo devuelve un problema con `[objetivo]`
- `adoptar_mueve_los_validos`: con dos borradores válidos, la orden sale con 0 y los archivos están en tareas/
- `adoptar_todo_o_nada`: con un borrador válido y otro malo, sale con 2 y los dos siguen en borradores/
- `adoptar_sin_borradores`: sin la carpeta, imprime `no hay borradores` y sale con 0

## No hagas

- No añadas un flag para forzar ni para sobrescribir
- No borres los borradores inválidos
- No adoptes una parte: o todos o ninguno

## Notas

Para las tareas válidas de los tests usa un auxiliar `valida(id, depende)` con la misma forma que en los tests
de `lint.rs` (cabeceras, ficha con Talla S, Toca con un archivo nombrado en el objetivo, Contexto, Objetivo de
2 pasos y más de 300 caracteres, Firmas y Tests).
