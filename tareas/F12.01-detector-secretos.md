## Objetivo

1. `Cargo.toml` del crate: añade `regex.workspace = true` en `[dependencies]` (ya está en el workspace).
2. Crea `secrets.rs` con `SecretHit`, `shannon_entropy` y `find_secrets` (firmas abajo). Puro: sin E/S.
   Compila las expresiones una sola vez (`std::sync::LazyLock<Vec<(&'static str, regex::Regex)>>`).
3. Patrones, en este orden (`kind` → expresión):
   - `clave-privada` → `-----BEGIN [A-Z ]*PRIVATE KEY-----`
   - `aws-access-key` → `\b(?:AKIA|ASIA)[0-9A-Z]{16}\b`
   - `github-token` → `\bgh[pousr]_[A-Za-z0-9]{36,}` y `\bgithub_pat_[A-Za-z0-9_]{22,}`
   - `anthropic-key` → `\bsk-ant-[A-Za-z0-9_-]{20,}`
   - `openai-key` → `\bsk-[A-Za-z0-9_-]{20,}`
   - `google-api-key` → `\bAIza[0-9A-Za-z_-]{35}`
   - `slack-token` → `\bxox[baprs]-[A-Za-z0-9-]{10,}`
   - `jwt` → `\beyJ[A-Za-z0-9_-]{10,}\.eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}`
   - `asignacion` → `(?i)\b[a-z0-9_]*(?:password|passwd|secret|token|api_?key|clave)[a-z0-9_]*\s*[:=]\s*["']?([^\s"']{12,})`:
     el acierto es SOLO el grupo 1 (el valor) y solo cuenta si `shannon_entropy(valor) >= 3.5` y el
     valor no contiene (sin distinguir mayúsculas) `{env:`, `${`, `<`, `xxxx`, `changeme`, `example`, `ejemplo`.
4. `find_secrets` devuelve los aciertos ordenados por `start`; si dos se solapan, se queda el que
   empieza antes (a igual inicio, el del patrón que va antes en la lista). `start`/`end` son
   posiciones en bytes de `text`.
5. `shannon_entropy(s)`: entropía de Shannon en bits por carácter sobre los caracteres de `s`
   (`-Σ p·log2(p)`); 0.0 para la cadena vacía.
6. `lib.rs`: `pub mod secrets;` y `pub use secrets::{SecretHit, find_secrets};`.
7. Tests (prefijo `detecta_`). IMPORTANTE: ningún token de prueba se escribe literal en el código;
   constrúyelo en tiempo de ejecución (`format!("AKIA{}", "A".repeat(16))`,
   `format!("ghp_{}", "a1B2".repeat(9))`, `format!("sk-ant-{}", "x9Z".repeat(10))`), para que el repo no
   contenga nada que parezca una clave.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-policy/src/secrets.rs
/// Un posible secreto encontrado en un texto.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct SecretHit { pub kind: &'static str, pub start: usize, pub end: usize }

/// Entropía de Shannon en bits por carácter.
pub fn shannon_entropy(s: &str) -> f64;

/// Secretos que parece contener `text` (claves, tokens, contraseñas asignadas), por orden de aparición.
pub fn find_secrets(text: &str) -> Vec<SecretHit>;
```

## Ejemplo (entrada y resultado esperado)

```
find_secrets("clave = " + "AKIA" + 16 × "A")            → [SecretHit { kind: "aws-access-key", start: 8, end: 28 }]
find_secrets("password: {env:DB_PASS}")                  → []
find_secrets("DB_PASSWORD=" + "q7Lm2Xv9Tz4Rb8Kd")        → [SecretHit { kind: "asignacion", start: 12, end: 28 }]
find_secrets("token = aaaaaaaaaaaaaaaa")                 → []      (entropía 0)
shannon_entropy("aabb")                                  → 1.0
```

## Tests (con estos nombres)

- `detecta_aws`: la cadena `AKIA` más 16 letras A da un acierto `aws-access-key` con las posiciones exactas
- `detecta_github_anthropic_y_openai`: un `ghp_…`, un `sk-ant-…` y un `sk-…` construidos en el test dan `github-token`, `anthropic-key` y `openai-key`
- `detecta_clave_privada`: la cabecera `-----BEGIN RSA PRIVATE KEY-----` (construida con `format!`) da `clave-privada`
- `detecta_asignacion_con_entropia`: `DB_PASSWORD=` más un valor aleatorio de 16 caracteres da `asignacion` que cubre solo el valor
- `detecta_que_no_es_secreto_un_marcador`: `password: {env:DB_PASS}`, `token = <tu token>` y `api_key = changeme1234` no dan aciertos
- `detecta_que_baja_entropia_no_cuenta`: `token = aaaaaaaaaaaaaaaa` no da aciertos
- `detecta_sin_solapes_y_en_orden`: un `sk-ant-…` da un solo acierto (`anthropic-key`, no también `openai-key`) y dos secretos distintos salen por orden de posición
- `detecta_entropia`: `shannon_entropy("aabb")` es 1.0 y la de la cadena vacía es 0.0
- `detecta_texto_normal_limpio`: un párrafo de código Rust corriente no da aciertos
