## Objetivo

1. `secrets.rs`: añade `redact` y `redact_json` (firmas abajo).
   - `redact(text)`: sustituye cada acierto de `find_secrets(text)` por `[SECRETO:<kind>]`. Sin
     aciertos devuelve el texto igual. Recorre los aciertos de atrás hacia delante (o construye la
     cadena por trozos) para que las posiciones sigan valiendo.
   - `redact_json(v)`: copia de `v` con `redact` aplicado a TODAS las cadenas que son valores (dentro de
     objetos y listas, a cualquier profundidad). Las claves de los objetos, los números, los booleanos
     y `null` no cambian.
2. `audit.rs`, método `AuditLog::append`: como primera línea del cuerpo,
   `let detail = crate::secrets::redact_json(&detail);`. Así el hash de la entrada se calcula ya sobre
   el detalle censurado y `AuditLog::verify` sigue funcionando sin cambios.
3. `lib.rs`: añade `redact` y `redact_json` al `pub use secrets::{…}`.
4. Tests con el prefijo `censura_`: los de `redact` en `secrets.rs` y los de la auditoría en el
   `mod audit_tests` de `audit.rs`. Los tokens de prueba se construyen en tiempo de ejecución
   (`format!("AKIA{}", "A".repeat(16))`), nunca literales.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-policy/src/secrets.rs
/// Texto con cada secreto sustituido por `[SECRETO:<tipo>]`.
pub fn redact(text: &str) -> String;

/// Igual que `redact`, sobre todas las cadenas de un valor JSON.
pub fn redact_json(v: &serde_json::Value) -> serde_json::Value;
```

## Ejemplo (entrada y resultado esperado)

```
redact("export AWS=" + "AKIA" + 16 × "A" + " # fin")   → "export AWS=[SECRETO:aws-access-key] # fin"
redact("nada que ocultar")                               → "nada que ocultar"
redact_json({"path":"a.env","content":"K=" + clave, "n": 3})
  → {"path":"a.env","content":"K=[SECRETO:aws-access-key]","n":3}
```

## Tests (con estos nombres)

- `censura_sustituye_el_secreto`: el primer ejemplo da exactamente esa cadena
- `censura_sin_secretos_no_cambia`: un texto normal se devuelve igual
- `censura_dos_secretos_en_una_linea`: dos claves distintas en el mismo texto quedan sustituidas las dos y el resto intacto
- `censura_json_recursivo`: una clave dentro de una lista dentro de un objeto queda censurada y los números no cambian
- `censura_auditoria_no_guarda_el_secreto`: tras `append` con un `detail` que contiene una clave, el archivo no contiene la clave y sí `[SECRETO:`
- `censura_auditoria_sigue_verificando`: tras tres `append` (uno con secreto), `AuditLog::verify` devuelve 3
