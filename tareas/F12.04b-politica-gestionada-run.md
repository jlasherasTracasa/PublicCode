## Objetivo

API del núcleo que se usa (ya existe en `pcode_policy`): `SYSTEM_POLICY`, `MANAGED_ENV`,
`managed_path(env_value: Option<&str>, system: &Path) -> Option<PathBuf>`,
`load_managed(path) -> Result<Option<ManagedPolicy>, String>`, y en `ManagedPolicy` el campo
`capabilities: Capabilities` y `model_allowed(&self, model: &str) -> bool`.

1. Crea `managed.rs` en la CLI con `load` y `check_model` (firmas abajo).
   - `load()`: ruta = `managed_path(std::env::var(MANAGED_ENV).ok().as_deref(), Path::new(SYSTEM_POLICY))`;
     sin ruta → `Ok(None)`; con ruta → `load_managed`; un `Err(e)` se convierte en
     `anyhow::bail!("{e} ({ruta})")` (fallo cerrado: pcode no arranca con una política rota).
   - `check_model(model)`: si hay política y `!model_allowed(model)` →
     `anyhow::bail!("el modelo {model} no está permitido por la política gestionada ({ruta})")`.
2. `main.rs`: añade `mod managed;` junto a los demás `mod`.
3. `run.rs`: función nueva `base_policy(config)`: si `crate::managed::load()?` da política,
   `Policy::new(gestionada.capabilities).child(load_capabilities(config))`; si no,
   `Policy::new(load_capabilities(config))`.
4. `run.rs`, función `run`: sustituye `let caps = load_capabilities(&a.config);` por
   `let policy = base_policy(&a.config)?;`, pasa `policy` a `Agent::new` en lugar de `Policy::new(caps)`
   y, justo después de `let model = pick_model(…);`, añade `crate::managed::check_model(&model)?;`.
5. Crea `tests/politica_gestionada.rs` con los tests de la lista (prefijo `run_`). Copia los ayudantes
   `script`, `resp` y `pcode` de `tests/run.rs`. La política se escribe en un archivo del directorio
   temporal y se pasa con `.env("PCODE_POLITICA", ruta)`. La denegación se comprueba leyendo
   `<dir>/.pcode/audit.jsonl` (contiene `"decision":"deny"`).

## Firmas (cópialas tal cual)

```rust
// crates/pcode-cli/src/managed.rs
/// Política gestionada vigente y el archivo del que sale (`None` si no hay).
pub fn load() -> anyhow::Result<Option<(std::path::PathBuf, pcode_policy::ManagedPolicy)>>;
/// Error si la política gestionada no permite este modelo.
pub fn check_model(model: &str) -> anyhow::Result<()>;

// crates/pcode-cli/src/run.rs
/// Política de las ejecuciones no interactivas: la gestionada (si hay) y encima `[politica]` del proyecto.
pub fn base_policy(config: &std::path::Path) -> anyhow::Result<pcode_policy::Policy>;
```

## Ejemplo (entrada y resultado esperado)

```
politica.toml:   [politica]
                 denegar_ordenes = ["echo *"]
guion simulado:  el modelo llama a bash {"command":"echo hola"} y después responde "listo"
$ PCODE_POLITICA=politica.toml pcode run "haz algo"
  → .pcode/audit.jsonl contiene una entrada de `bash` con "decision":"deny"

politica.toml:   modelos_permitidos = ["permitido-*"]
$ PCODE_POLITICA=politica.toml pcode run --modelo otro "x"
  → código distinto de 0; stderr contiene «no está permitido por la política gestionada»
```

## Tests (con estos nombres)

- `run_gestionada_deniega_orden`: con `denegar_ordenes = ["echo *"]` en la política gestionada, la auditoría registra `deny` para la llamada a bash
- `run_proyecto_no_relaja`: aunque el `pcode.toml` del proyecto tenga `[politica] permitir_ordenes = ["echo *"]`, la orden sigue denegada
- `run_modelo_no_permitido_falla`: con `modelos_permitidos = ["permitido-*"]`, `--modelo otro` termina con error y el mensaje de la política
- `run_modelo_permitido_pasa`: con la misma política, `--modelo permitido-1` termina con código 0
- `run_politica_rota_no_arranca`: una política con TOML inválido hace que `pcode run` termine con error que menciona `política gestionada no válida`
- `run_sin_politica_como_antes`: sin `PCODE_POLITICA`, el mismo guion ejecuta `echo hola` (auditoría con `allow`)

## No hagas

- No cambies `load_capabilities` ni la rama `--backend` de `run`
- No escribas en `/etc`: los tests usan `PCODE_POLITICA`

## Notas

Los tests sin `PCODE_POLITICA` deben pasar `.env_remove("PCODE_POLITICA")`. Si el equipo donde se
ejecutan tiene `/etc/pcode/politica.toml`, ese archivo manda: dilo en el informe.
