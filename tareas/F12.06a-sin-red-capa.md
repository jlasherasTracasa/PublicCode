# F12.06a-sin-red-capa — Política: capa `Capabilities::offline()` (sin tools de red ni órdenes que salen a la red)

## Contexto (lee esto y nada más)

- crates/pcode-policy/src/caps.rs (función `Capabilities::interactive_defaults`: cómo se construye una capa con el cierre `v`; campos `deny_commands`, `deny_effects`; y `Policy::tool_visible`)

## Objetivo

1. En `caps.rs`, dentro de `impl Capabilities`, añade `offline()` (firma abajo), con el mismo estilo que
   `interactive_defaults`.
2. La capa lleva:
   - `deny_effects: vec![Effect::Network]` (las tools con efecto de red, como las de MCP, ni se
     anuncian ni se pueden llamar);
   - `deny_commands` con exactamente estos patrones: `curl*`, `wget*`, `ssh *`, `scp *`, `sftp *`,
     `rsync *`, `nc *`, `ncat *`, `telnet *`, `ftp *`, `git push*`, `git fetch*`, `git pull*`,
     `git clone*`, `git ls-remote*`, `git submodule update*`, `pip install*`, `pip3 install*`,
     `npm install*`, `npm i *`, `npm ci*`, `npx *`, `yarn add*`, `yarn install*`, `pnpm add*`,
     `pnpm install*`, `cargo install*`, `cargo add*`, `cargo fetch*`, `cargo update*`, `go get*`,
     `go install*`, `apt *`, `apt-get *`, `brew *`, `docker pull*`, `docker push*`, `gh *`;
   - el resto de campos, por defecto (`..Default::default()`).
3. Documenta en el comentario `///` que es una lista de mejor esfuerzo: un programa arbitrario
   (`python -c …`) puede abrir un socket; el aislamiento real es la mini sandbox N1 sin red.
4. Tests en el `mod tests` de `caps.rs` con el prefijo `sin_red_`, usando
   `Policy::new(Capabilities::default()).child(Capabilities::offline())`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-policy/src/caps.rs
impl Capabilities {
    /// Capa del modo sin red: oculta las tools con efecto de red y deniega las órdenes de shell que
    /// salen a la red (mejor esfuerzo; el aislamiento real es la sandbox N1 sin red).
    pub fn offline() -> Capabilities;
}
```

## Ejemplo (entrada y resultado esperado)

```
p = Policy::new(Capabilities::default()).child(Capabilities::offline())
p.check_command("curl -s https://example.com")        → Deny(…)
p.check_command("cd /tmp && git push origin main")    → Deny(…)
p.check_command("cargo test && git status")           → Allow
p.tool_visible("mcp_x", &[Effect::Network])           → false
p.tool_visible("leer", &[Effect::Read])               → true
```

## Tests (con estos nombres)

- `sin_red_deniega_descargas`: `curl -s https://example.com` y `wget x` dan `Deny`
- `sin_red_deniega_git_remoto`: `git push origin main`, `git fetch` y `git clone https://x` dan `Deny`, también dentro de `bash -c '…'`
- `sin_red_deniega_instalaciones`: `pip install requests`, `npm install` y `cargo add serde` dan `Deny`
- `sin_red_permite_lo_local`: `cargo test`, `git status`, `git commit -m x` y `ls` dan `Allow`
- `sin_red_oculta_tools_de_red`: `tool_visible` es false con `Effect::Network` y true con solo `Effect::Read`
- `sin_red_no_cambia_escrituras`: `check_write("src/a.rs")` sigue dando `Allow`

## No hagas

- No cambies `interactive_defaults` ni `check_command`
- No toques los tests que ya existen en `caps.rs`
