## Objetivo

Ya existen: `pcode_policy::Capabilities::offline()` (capa que deniega las órdenes de red) y
`crate::managed::load() -> anyhow::Result<Option<(PathBuf, ManagedPolicy)>>` (el campo
`ManagedPolicy::offline` es `sin_red` de la política gestionada).

1. `run.rs`: función nueva `offline_requested(flag)` (firma abajo): true si `flag`, o si la variable
   `PCODE_SIN_RED` vale `1` o `true`, o si la política gestionada tiene `offline == true`.
2. `run.rs`: en `RunArgs` añade `#[arg(long = "sin-red")] pub offline: bool` («Sin red: el agente no
   puede salir a la red; solo se habla con el proveedor del modelo»). En `run`, calcula
   `let offline = offline_requested(a.offline)?;`; si es true, la política pasa a ser
   `base_policy(&a.config)?.child(Capabilities::offline())`. Pasa `offline` como último argumento nuevo
   de `run_with_backend`.
3. `backend_run.rs`, `run_with_backend`: parámetro nuevo `offline: bool` al final. Si es true, `net` es
   `Network::None` cuando el backend no necesita red y, cuando la necesita (`be.caps().needs_network`
   no vacío), termina con
   `anyhow::bail!("--sin-red: el backend {backend} necesita red; usa [sandbox] red = \"filtrar\"")`.
   Si es false, todo como hoy.
4. `chat.rs`: en `ChatArgs` añade el mismo campo `#[arg(long = "sin-red")] pub offline: bool` (y
   `offline: false` en `default_args`). En `prepare`, si `crate::run::offline_requested(a.offline)?`,
   añade `.child(pcode_policy::Capabilities::offline())` a la política que devuelve `interactive_policy`.
5. Crea `tests/sin_red.rs` con los tests de la lista (copia los ayudantes `script`, `resp` y `pcode`
   de `tests/run.rs`; la denegación se comprueba en `<dir>/.pcode/audit.jsonl`).

## Ejemplo (entrada y resultado esperado)

```
guion simulado: el modelo llama a bash {"command":"curl -s https://example.com"} y después responde "listo"
$ pcode run --sin-red "haz algo"        → la auditoría registra "decision":"deny" para esa llamada; curl no se ejecuta
$ pcode run "haz algo"                   → la auditoría registra "allow" (como hoy)
$ PCODE_SIN_RED=1 pcode run "haz algo"   → igual que con --sin-red
```

## Tests (con estos nombres)

- `sin_red_run_deniega_curl`: con `--sin-red`, la auditoría registra `deny` para la llamada `curl …` del guion
- `sin_red_por_variable`: con `PCODE_SIN_RED=1` y sin la opción, también `deny`
- `sin_red_por_politica_gestionada`: con una política gestionada `sin_red = true` (vía `PCODE_POLITICA`), también `deny`
- `sin_red_permite_ordenes_locales`: con `--sin-red`, una llamada `echo hola` se registra con `allow`
- `sin_red_chat_deniega_curl`: `pcode chat --sin-red` con el mismo guion (mensaje por la entrada estándar, como en `tests/chat.rs`) registra `deny`
- `sin_la_opcion_como_antes`: sin `--sin-red` ni variables, la llamada `curl` del guion se registra con `allow` (usa `curl --version` en el guion para no salir a la red)

## No hagas

- No hagas peticiones reales a Internet en los tests: el guion usa `curl --version` cuando la orden sí se ejecuta
- No cambies el comportamiento sin la opción

## Notas

El proveedor del modelo no pasa por la política (lo llama el propio `pcode`), por eso sigue
funcionando. Los tests deben quitar `PCODE_SIN_RED` y `PCODE_POLITICA` del entorno cuando no los usan
(`.env_remove(…)`).
