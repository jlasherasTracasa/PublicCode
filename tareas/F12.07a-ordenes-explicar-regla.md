## Objetivo

Hoy el motivo es «orden denegada: git push origin main» y el usuario no sabe qué regla de qué lista lo
causó. Las listas ya son configurables en `[politica]` (`denegar_ordenes`, `preguntar_ordenes`,
`permitir_ordenes`); falta la explicación.

1. En `caps.rs` añade la función privada `first_match(pats: &[String], text: &str) -> Option<&str>`:
   devuelve el PRIMER patrón de la lista (en su orden) cuyo glob casa con `text`
   (`Glob::new(p).ok()?.compile_matcher().is_match(text)`; los patrones inválidos se saltan).
2. En `check_command`, cambia SOLO los textos de los motivos:
   - denegada: `orden denegada: {c} (regla `{pat}` de denegar_ordenes)`
   - no permitida: `orden no permitida: {c} (no casa con ninguna regla de permitir_ordenes)`
   - pregunta: `orden con efectos difíciles de deshacer: {c} (regla `{pat}` de preguntar_ordenes)`
   donde `{pat}` es lo que devuelve `first_match` sobre la lista correspondiente. El principio de cada
   motivo NO cambia (otros sitios lo muestran tal cual).
3. La lógica de decisión no cambia: mismo resultado `Allow`/`Ask`/`Deny` para cualquier entrada.
4. Tests en el `mod tests` de `caps.rs` con el prefijo `explica_`.

## Ejemplo (entrada y resultado esperado)

```
caps: denegar_ordenes = ["git stash*", "git push*"]
check_command("cd x && git push origin main")
  → Deny("orden denegada: git push origin main (regla `git push*` de denegar_ordenes)")
interactive_defaults: check_command("git reset --hard HEAD~1")
  → Ask("orden con efectos difíciles de deshacer: git reset --hard HEAD~1 (regla `git reset --hard*` de preguntar_ordenes)")
```

## Tests (con estos nombres)

- `explica_regla_de_denegacion`: el primer ejemplo da exactamente ese motivo
- `explica_regla_de_pregunta`: el segundo ejemplo da exactamente ese motivo
- `explica_lista_de_permitidas`: con `permitir_ordenes = ["cargo *"]`, `ls` da `Deny` cuyo motivo termina en `(no casa con ninguna regla de permitir_ordenes)`
- `explica_primera_regla_que_casa`: con `["git *", "git push*"]`, `git push` cita la regla `git *`
- `explica_sin_cambiar_la_decision`: `cargo test && git status` con `interactive_defaults` sigue dando `Allow`

## No hagas

- No cambies el principio de los mensajes (`orden denegada: `, `orden no permitida: `, `orden con efectos difíciles de deshacer: `)
- No cambies `Decision` ni la firma de `check_command`
- No toques los tests que ya existen
