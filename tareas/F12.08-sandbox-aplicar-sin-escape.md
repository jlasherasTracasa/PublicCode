# F12.08-sandbox-aplicar-sin-escape — Sandbox: `aplicar` nunca trae al repo hooks ni configuración de git (escape por `.git/`)

## Contexto (lee esto y nada más)

- crates/pcode-sandbox/src/apply.rs (método `Sandbox::apply`: el bucle `for c in &changes` que copia cada cambio al repo)
- crates/pcode-sandbox/src/layer.rs (struct `Change { path, kind }`: `path` es relativo con `/`)
- crates/pcode-sandbox/src/run.rs (`Sandbox::create_n1(spec)`: crea la sandbox sin necesitar namespaces; la capa está en `<estado>/upper/`)

## Objetivo

Hoy, si un agente dentro de la sandbox escribe `.git/hooks/pre-commit` o cambia `.git/config`
(`core.hooksPath`, `core.sshCommand`…), `aplicar` lo copia al repo y ese código se ejecuta FUERA de la
sandbox en el siguiente `git commit` del usuario. Los commits del agente (objetos, refs, índice) sí
deben seguir aplicándose.

1. `layer.rs`: función pura `is_escape_path` (firma abajo). Parte la ruta por `/`; si algún componente
   es exactamente `.git`, mira lo que va DESPUÉS de él: es ruta de escape si no queda nada (el propio
   directorio `.git`), si el primer componente siguiente es `hooks`, o si lo que queda es exactamente
   `config`. Vale para repos anidados (`sub/.git/hooks/x`). En cualquier otro caso, false.
2. `apply.rs`, método `apply`: antes del bucle, separa `changes` en aplicables y bloqueados con
   `is_escape_path(&c.path)`. Los bloqueados NO se copian ni se borran en el repo; por cada uno,
   `tracing::warn!("cambio no aplicado (ruta de git protegida): {}", c.path)`. `apply` devuelve solo los
   aplicados. La capa se descarta igual al final.
3. `apply.rs`: método nuevo `blocked_changes` (firma abajo): los cambios de `self.changes()?` para los
   que `is_escape_path` es true.
4. `lib.rs`: añade `is_escape_path` al `pub use layer::{…}`.
5. Tests con el prefijo `escape_`: los puros en `layer.rs`; los de `apply` en `apply.rs` SIN
   namespaces: crea la sandbox con `Sandbox::create_n1` sobre un directorio temporal (sin `.git`),
   escribe a mano archivos bajo `<estado>/upper/` (p. ej. `upper/.git/hooks/pre-commit` y
   `upper/nuevo.txt`) y llama a `apply()`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-sandbox/src/layer.rs
/// ¿Aplicar este cambio dejaría código que git ejecuta fuera de la sandbox (hooks, config)?
pub fn is_escape_path(path: &str) -> bool;

// crates/pcode-sandbox/src/apply.rs
impl Sandbox {
    /// Cambios de la capa que `apply` no llevará al repo por ser rutas de git protegidas.
    pub fn blocked_changes(&self) -> Result<Vec<Change>, SandboxError>;
}
```

## Ejemplo (entrada y resultado esperado)

```
is_escape_path(".git/hooks/pre-commit")      → true
is_escape_path(".git/config")                → true
is_escape_path("sub/.git/hooks")             → true
is_escape_path(".git")                       → true
is_escape_path(".git/objects/ab/cdef")       → false
is_escape_path(".git/refs/heads/main")       → false
is_escape_path("src/.gitignore")             → false
is_escape_path("docs/hooks/config")          → false
```

## Tests (con estos nombres)

- `escape_rutas_protegidas`: los cuatro primeros casos del ejemplo dan true
- `escape_rutas_normales`: los cuatro últimos casos del ejemplo dan false
- `escape_apply_no_trae_el_hook`: con `upper/.git/hooks/pre-commit` y `upper/nuevo.txt`, tras `apply` existe `nuevo.txt` en el repo y no existe `.git/hooks/pre-commit`; el resultado solo lista `nuevo.txt`
- `escape_apply_no_trae_config`: con `upper/.git/config` en la capa, el repo sigue sin `.git/config`
- `escape_blocked_changes_los_lista`: `blocked_changes()` devuelve el cambio de `.git/hooks/pre-commit` y no el de `nuevo.txt`
- `escape_apply_si_trae_objetos`: un archivo `upper/.git/objects/ab/cd` sí se copia al repo

## No hagas

- No bloquees todo `.git/`: los commits que hace el agente dentro de la sandbox deben aplicarse
- No cambies `discard`, `diff` ni `changes`
- No toques los tests que ya existen
