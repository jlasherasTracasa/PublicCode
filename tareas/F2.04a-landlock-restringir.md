## Objetivo

1. `Cargo.toml` del crate: en `[target.'cfg(target_os = "linux")'.dependencies]` añade `landlock = "0.4"`
   (dependencia permitida solo en esta tarea).
2. `child_test.rs` (módulo solo de tests): `run_child` relanza ESTE binario de tests
   (`std::env::current_exe()`) con los argumentos `--exact <test> --nocapture --test-threads=1` y la
   variable `PCODE_HIJO=<role>`; devuelve el código de salida (o -1 si murió por una señal).
   `child_role` devuelve `std::env::var("PCODE_HIJO").ok()`.
3. `restrict.rs`, `landlock_abi`: en Linux,
   `libc::syscall(libc::SYS_landlock_create_ruleset, std::ptr::null::<libc::c_void>(), 0usize, 1u32)`
   (el 1 es `LANDLOCK_CREATE_RULESET_VERSION`); devuelve la versión, o 0 si el resultado es negativo.
   Fuera de Linux devuelve 0.
4. `restrict_self`: si `landlock_abi() == 0`, `tracing::warn!` y `Ok(false)`. Si no, con el crate
   `landlock` (ABI `ABI::V1`, modo por defecto «mejor esfuerzo»): maneja `AccessFs::from_all(abi)`;
   regla de lectura y ejecución (`AccessFs::from_read(abi)`) sobre `/`; regla `AccessFs::from_all(abi)`
   sobre cada ruta de `rules.writable` que exista (las que no existen se ignoran); `restrict_self()`.
   Devuelve `Ok(true)` si el estado no es `RulesetStatus::NotEnforced`. Cualquier error del crate se
   convierte en `SandboxError::Invalid(format!("landlock: {e}"))`. Fuera de Linux: `Ok(false)`.
5. `lib.rs`: `pub mod restrict;`, `#[cfg(test)] mod child_test;` y
   `pub use restrict::{LandlockRules, landlock_abi, restrict_self};`.
6. Tests en `restrict.rs` (`mod tests`). Los que restringen lo hacen SIEMPRE en el hijo (ver ejemplo):
   Landlock no se puede quitar y rompería los demás tests. Si `landlock_abi() == 0`, el test termina sin
   comprobar nada (`return`).

## Firmas (cópialas tal cual)

```rust
// crates/pcode-sandbox/src/restrict.rs
/// Qué puede escribir el proceso restringido.
#[derive(Debug, Clone, Default)]
pub struct LandlockRules { pub writable: Vec<std::path::PathBuf> }

/// Versión de la ABI de Landlock del kernel (0 = no disponible).
pub fn landlock_abi() -> i32;

/// Restringe ESTE hilo y sus hijos: lectura en todo `/`, escritura solo en `rules.writable`.
/// `Ok(false)` si el kernel no tiene Landlock.
pub fn restrict_self(rules: &LandlockRules) -> Result<bool, crate::SandboxError>;

// crates/pcode-sandbox/src/child_test.rs
pub(crate) fn child_role() -> Option<String>;
pub(crate) fn run_child(test: &str, role: &str) -> i32;
```

## Ejemplo (entrada y resultado esperado)

```
// Uso del crate landlock 0.4:
use landlock::{ABI, Access, AccessFs, Ruleset, RulesetAttr, RulesetCreatedAttr, RulesetStatus, path_beneath_rules};
let abi = ABI::V1;
let st = Ruleset::default().handle_access(AccessFs::from_all(abi))?.create()?
    .add_rules(path_beneath_rules(&["/"], AccessFs::from_read(abi)))?
    .add_rules(path_beneath_rules(&writable, AccessFs::from_all(abi)))?
    .restrict_self()?;
let enforced = st.ruleset != RulesetStatus::NotEnforced;

// Patrón de test en proceso hijo:
#[test]
fn restrict_deniega_fuera() {
    if landlock_abi() == 0 { return; }
    if let Some(role) = child_role() {            // somos el hijo
        let (w, o) = role.split_once('|').unwrap();
        restrict_self(&LandlockRules { writable: vec![w.into()] }).unwrap();
        let denegado = std::fs::write(format!("{o}/b.txt"), "x").is_err();
        std::process::exit(if denegado { 0 } else { 1 });
    }
    let (w, o) = (tempfile::tempdir().unwrap(), tempfile::tempdir().unwrap());
    let role = format!("{}|{}", w.path().display(), o.path().display());
    assert_eq!(run_child("restrict::tests::restrict_deniega_fuera", &role), 0);
}
```

## Tests (con estos nombres)

- `landlock_abi_no_es_negativo`: `landlock_abi()` devuelve un número mayor o igual que 0
- `restrict_permite_escribir_en_writable`: el hijo restringe a un directorio temporal y puede crear un archivo dentro (sale con 0)
- `restrict_deniega_fuera`: el hijo no puede crear un archivo en otro directorio temporal que no está en `writable`
- `restrict_permite_leer_fuera`: el hijo restringido puede leer un archivo que el padre creó fuera de `writable`

## No hagas

- No llames a `restrict_self` en el proceso del test (solo en el hijo): no se puede deshacer
- No uses `fork`: el hijo es el propio binario de tests relanzado
- No añadas otras dependencias; `libc` ya está en el crate
