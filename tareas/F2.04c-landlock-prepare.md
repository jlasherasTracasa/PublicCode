# F2.04c-landlock-prepare — Landlock: `prepare.sh` termina en el ayudante `pcode __sandbox-exec` si está configurado

## Objetivo

1. `run.rs`: añade `static EXEC_HELPER: std::sync::RwLock<Option<PathBuf>> = std::sync::RwLock::new(None);`
   y las funciones `set_exec_helper` y `exec_helper` (firmas abajo). Por defecto no hay ayudante.
2. `run.rs`, función `run_with`: justo después de la cadena `cmd.env("MS_DIR", …)…env("GIT_CONFIG_VALUE_0", "*")`
   y ANTES del bucle `for (k, v) in env`, añade:
   `match exec_helper() { Some(h) => { cmd.env("PCODE_BIN", h); } None => { cmd.env_remove("PCODE_BIN"); } }`.
   (`env_remove` evita que un `PCODE_BIN` heredado del entorno cuele un binario.)
3. `prepare.sh`: sustituye la última línea `exec "$@"` por exactamente:
   ```
   if [ -n "$PCODE_BIN" ]; then
     set -- -- "$@"
     for p in "$MS_DIR" $ESCRIBIBLES "$MS_TMP" /dev; do set -- --escribible "$p" "$@"; done
     exec "$PCODE_BIN" __sandbox-exec "$@"
   fi
   exec "$@"
   ```
   Así el ayudante recibe `--escribible <ruta>` por cada ruta escribible (el directorio de trabajo, las
   de `ESCRIBIBLES`, el tmp privado y `/dev` para `/dev/null`) y después `-- orden…`.
4. `lib.rs`: añade `exec_helper` y `set_exec_helper` a la línea `pub use run::{…}`.
5. Tests en `mod tests` de `run.rs`, con el prefijo `ayudante_`. NO llames a `set_exec_helper` en ningún
   test: es global y los demás tests corren en paralelo.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-sandbox/src/run.rs
/// Binario `pcode` que `prepare.sh` usa como último paso (`pcode __sandbox-exec`). `None` lo desactiva.
pub fn set_exec_helper(bin: Option<PathBuf>);
/// Ayudante configurado para este proceso.
pub fn exec_helper() -> Option<PathBuf>;
```

## Tests (con estos nombres)

- `ayudante_por_defecto_no_hay`: `exec_helper()` devuelve `None` si nadie lo ha fijado
- `ayudante_prepare_lo_usa`: la constante `PREPARE` contiene `__sandbox-exec`, contiene `--escribible` y su última línea no vacía es `exec "$@"`
