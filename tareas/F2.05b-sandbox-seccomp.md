## Objetivo

1. `Cargo.toml` del crate: en `[target.'cfg(target_os = "linux")'.dependencies]` añade
   `seccompiler = "0.4"` (dependencia permitida solo en esta tarea).
2. `seccomp.rs`, `denied_syscalls`: devuelve (nombre, número) de estas 22 syscalls, con las constantes
   `libc::SYS_*`: ptrace, process_vm_readv, process_vm_writev, mount, umount2, pivot_root, kexec_load,
   kexec_file_load, bpf, keyctl, add_key, request_key, init_module, finit_module, delete_module, setns,
   unshare, perf_event_open, userfaultfd, reboot, swapon, swapoff.
3. `install_seccomp`: primero `libc::prctl(libc::PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)` (con `// SAFETY:`).
   Construye un `seccompiler::SeccompFilter` con un mapa `BTreeMap<i64, Vec<SeccompRule>>` que tiene cada
   número de la lista con un `vec![]` vacío (= coincide siempre), acción por defecto
   `SeccompAction::Allow`, acción al coincidir `SeccompAction::Errno(libc::EPERM as u32)` y la
   arquitectura `std::env::consts::ARCH.try_into()`. Conviértelo en `BpfProgram` (`try_into`) y aplícalo
   con `seccompiler::apply_filter`. Errores: `SandboxError::Invalid(format!("seccomp: {e}"))`.
4. Todo lo anterior va tras
   `#[cfg(all(target_os = "linux", any(target_arch = "x86_64", target_arch = "aarch64")))]`. En el resto
   de plataformas `denied_syscalls` devuelve un vector vacío e `install_seccomp` devuelve `Ok(())` tras
   `tracing::warn!("seccomp no disponible en esta plataforma")`.
5. `lib.rs`: `pub mod seccomp;` y `pub use seccomp::{denied_syscalls, install_seccomp};`.
6. Tests en `seccomp.rs`: los que instalan el filtro, en proceso hijo (el filtro no se puede quitar).

## Firmas (cópialas tal cual)

```rust
// crates/pcode-sandbox/src/seccomp.rs
/// Syscalls que el filtro deniega con EPERM: (nombre, número en esta arquitectura).
pub fn denied_syscalls() -> Vec<(&'static str, i64)>;

/// Instala el filtro en este proceso. Irreversible; lo heredan los hijos.
pub fn install_seccomp() -> Result<(), crate::SandboxError>;
```

## Ejemplo (entrada y resultado esperado)

```
// Hijo de `seccomp_bloquea_unshare`: `unshare(0)` es inofensivo y normalmente devuelve 0.
install_seccomp().unwrap();
let r = unsafe { libc::unshare(0) };                      // SAFETY: sin banderas no cambia nada
let eperm = r == -1 && std::io::Error::last_os_error().raw_os_error() == Some(libc::EPERM);
std::process::exit(if eperm { 0 } else { 1 });
// Padre: assert_eq!(run_child("seccomp::tests::seccomp_bloquea_unshare", "x"), 0);
```

## Tests (con estos nombres)

- `seccomp_lista_completa`: en Linux x86_64 o aarch64, `denied_syscalls()` tiene 22 entradas, sin números repetidos, e incluye `ptrace` y `mount`
- `seccomp_bloquea_unshare`: en el hijo, tras instalar el filtro, `unshare(0)` devuelve -1 con EPERM
- `seccomp_permite_lo_normal`: en el hijo, tras instalar el filtro, escribir y leer un archivo temporal funciona y `sh -c true` sale con 0
- `seccomp_antes_del_filtro_unshare_funciona`: en el hijo, sin instalar el filtro, `unshare(0)` devuelve 0

## No hagas

- No instales el filtro en el proceso del test, solo en el hijo
- No bloquees `execve`, `clone` ni `fork`: la orden de la sandbox los necesita
- No añadas más dependencias

## Notas

Si alguna constante `libc::SYS_*` no existe en una de las dos arquitecturas, déjala tras
`#[cfg(target_arch = "…")]` y anótalo en *Decisiones* (el test de 22 entradas se ajusta a esa
arquitectura). Si un nombre de `seccompiler` no compila, mira `~/.cargo/registry/src/*/seccompiler-0.4*/src/lib.rs`.
