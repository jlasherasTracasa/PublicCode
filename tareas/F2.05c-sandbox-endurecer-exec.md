# F2.05c-sandbox-endurecer-exec — `exec_restricted` aplica Landlock, después los límites y por último seccomp

## Contexto (lee esto y nada más)

- crates/pcode-sandbox/src/limits.rs (`Limits::default()` y `apply_limits(&Limits) -> Result<(), SandboxError>`)
- crates/pcode-sandbox/src/seccomp.rs (`install_seccomp() -> Result<(), SandboxError>`)

## Objetivo

1. `exec.rs`, función `exec_restricted`: después de `restrict_self(…)` y antes del `exec`, añade en este
   orden: `crate::apply_limits(&crate::Limits::default())` y `crate::install_seccomp()`. Si cualquiera
   devuelve `Err(e)`, la función devuelve `e` y no ejecuta la orden. El orden importa: seccomp va el
   último porque los pasos anteriores usan syscalls normales y después ya nada puede cambiarlo.
2. Los tests que ya hay en `exec.rs` deben seguir pasando sin cambios.
3. `tests/sandbox_exec.rs` (ya existe; lanza el binario con `assert_cmd::Command::cargo_bin("pcode")`):
   añade los tests de la lista. El de `unshare` empieza con
   `if !pcode_sandbox::userns_available() { return; }` (así se sabe que, sin filtro, `unshare --user`
   funcionaría en esta máquina).

## Ejemplo (entrada y resultado esperado)

```
pcode __sandbox-exec -- sh -c 'ulimit -c'            → stdout «0»
pcode __sandbox-exec -- unshare --user true          → código de salida distinto de 0 (EPERM)
pcode __sandbox-exec -- sh -c 'echo ok'              → stdout «ok», código 0
```

## Tests (con estos nombres)

- `sandbox_exec_core_a_cero`: `pcode __sandbox-exec -- sh -c 'ulimit -c'` imprime `0`
- `sandbox_exec_bloquea_unshare`: `pcode __sandbox-exec -- unshare --user true` termina con código distinto de 0 (se salta sin userns)
- `sandbox_exec_sigue_ejecutando_ordenes_normales`: `pcode __sandbox-exec -- sh -c 'echo ok | cat'` imprime `ok` y sale con 0

## No hagas

- No cambies el orden Landlock → límites → seccomp
- No borres ni modifiques los tests que ya existen en `tests/sandbox_exec.rs`
