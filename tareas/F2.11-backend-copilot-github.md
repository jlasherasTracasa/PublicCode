## Objetivo

1. `trait GitHubApi` (create_issue, assign_to_copilot, find_linked_pr, pr_diff, comment) con una
   implementación real (`reqwest`, token desde la variable `GITHUB_TOKEN`) y otra falsa para tests.
2. Máquina de estados: `Creado → Asignado → PrAbierto → DiffAplicado → Verificado | Fallido`, con
   sondeo (intervalo y tiempo máximo configurables; los tests usan 0 y una API falsa).
3. Al llegar el PR: baja el diff, lo aplica en la sandbox con `git apply` y deja que el flujo ejecute
   `acepta` localmente. Nunca se fusiona el PR desde aquí.
4. El texto del issue incluye la tarea, el relevo y el criterio `acepta`.

}
#[derive(Debug, Clone, PartialEq, Eq)] pub enum CopilotState { Created(u64), Assigned(u64), PrOpen(u64, u64), DiffApplied(u64), Verified, Failed(String) }
