## Objetivo

1. Crea `copilot_github.rs` con `CopilotState`, `CopilotGitHub` y sus métodos (firmas abajo).
2. `open_pr(job)`: `create_issue(&job.id, &issue_body(job))` → `assign_to_copilot(issue)` → hasta
   `self.max_polls` consultas a `find_linked_pr(issue)` (bucle `for`), durmiendo `self.poll` entre consultas
   con `tokio::time::sleep` (no duermas antes de la primera). Devuelve `(issue, pr)`. Si se agotan las
   consultas: `Err(BackendError::Other(format!("Copilot no abrió un PR para el issue #{issue} tras
   {max_polls} consultas")))`.
3. `states(job)`: igual que `open_pr` pero devuelve la lista de estados por los que pasa, para el informe y los
   tests: `Created(issue)`, `Assigned(issue)`, `PrOpen(issue, pr)`; si no llega el PR, el último es
   `Failed(mensaje)`.
4. `impl Backend`: `id()` = `"copilot-github"`; `caps()` con `needs_network: vec!["api.github.com".into()]` y
   `reads_agents_md: true`. `run(job, sandbox)`: `open_pr`; `pr_diff(pr)`; escribe el diff en la sandbox y lo
   aplica con un solo `sandbox.run_capture` de
   `sh -c 'printf "%s" "$1" > .pcode-pr.diff && git apply .pcode-pr.diff; r=$?; rm -f .pcode-pr.diff; exit $r'`
   pasando el diff como `$1` (mismo truco que `MockBackend`). Devuelve `BackendResult { exit: código,
   final_message: "PR #<pr> del issue #<issue> aplicado" (o "…: el diff no se aplicó" si el código no es 0),
   transcript: vec![], usage: None }`. La aceptación la ejecuta después el flujo; aquí NO se fusiona ni se
   cierra nada.
5. `lib.rs`: añade `pub mod copilot_github;`.

```rust
// crates/pcode-backends/src/copilot_github.rs
use crate::github_api::GitHubApi;
use crate::types::*;

/// Pasos del trabajo con Copilot coding agent.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum CopilotState { Created(u64), Assigned(u64), PrOpen(u64, u64), Failed(String) }

/// Backend asíncrono: issue → PR de Copilot → diff aplicado en la sandbox.
pub struct CopilotGitHub<A: GitHubApi> {
    pub api: A,
    /// Espera entre consultas.
    pub poll: std::time::Duration,
    /// Consultas como máximo.
    pub max_polls: u32,
}

impl<A: GitHubApi> CopilotGitHub<A> {
    /// Crea el issue, lo asigna y espera al PR: (issue, pr).
    pub async fn open_pr(&self, job: &Job) -> Result<(u64, u64), BackendError>;
    /// Estados recorridos (para informes y tests).
    pub async fn states(&self, job: &Job) -> Vec<CopilotState>;
}

#[async_trait::async_trait]
impl<A: GitHubApi> Backend for CopilotGitHub<A> { /* id, caps, run */ }
```

## Ejemplo (entrada y resultado esperado)

```
api = FakeGitHub { pr_after_polls: 2, ..Default::default() }; poll = Duration::ZERO; max_polls = 5
open_pr(&Job::new("T1", "haz X")) → Ok((1, 101)); el issue guardado tiene título "T1" y está en `assigned`
states(..) → [Created(1), Assigned(1), PrOpen(1, 101)]
con pr_after_polls 0 y max_polls 3 → open_pr da Err("Copilot no abrió un PR para el issue #1 tras 3 consultas") y polls == 3
```

## Tests (con estos nombres)

- `copilot_gh_flujo_feliz`: el primer caso del ejemplo devuelve (1, 101) y deja el issue asignado
- `copilot_gh_estados`: states devuelve los tres estados del ejemplo
- `copilot_gh_sin_pr_agota_consultas`: sin PR devuelve el error del ejemplo tras exactamente 3 consultas
- `copilot_gh_cuerpo_issue_lleva_acepta`: el cuerpo del issue creado contiene la orden de aceptación del Job
- `copilot_gh_error_de_la_api_se_propaga`: con fail en la API falsa, open_pr devuelve ese error
- `copilot_gh_aplica_el_diff_en_la_sandbox`: con un diff que crea hola.txt, run deja el archivo en los cambios de la sandbox (se salta sin namespaces de usuario)
