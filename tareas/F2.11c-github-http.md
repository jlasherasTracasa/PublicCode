## Objetivo

1. `Cargo.toml` de `pcode-backends`: añade `reqwest.workspace = true` (ya está en el workspace con `rustls-tls`
   y `json`).
2. Crea `github_http.rs` con `GitHubHttp` (firmas abajo). `lib.rs`: `pub mod github_http;` y
   `pub use github_http::GitHubHttp;`.
3. `from_env`: token de la variable `GITHUB_TOKEN` (si falta o está vacía:
   `Err(BackendError::Other("falta la variable GITHUB_TOKEN".into()))`); base de `PCODE_GITHUB_API` o, si no
   está, `https://api.github.com`.
4. Todas las peticiones llevan `Authorization: Bearer <token>`, `User-Agent: pcode`,
   `X-GitHub-Api-Version: 2022-11-28` y `Accept: application/vnd.github+json` (salvo `pr_diff`). Una respuesta
   que no sea 2xx → `Err(BackendError::Other(format!("GitHub {status}: {primeros 200 caracteres del cuerpo}")))`.
   El token no aparece nunca en errores ni en logs.
5. Peticiones (rutas relativas a `<base>/repos/<owner>/<repo>`):
   - `create_issue`: `POST /issues` con `{"title", "body"}` → campo `number` de la respuesta;
   - `assign_to_copilot`: `POST /issues/<n>/assignees` con `{"assignees": [COPILOT_ASSIGNEE]}`;
   - `find_linked_pr`: `GET /issues/<n>/timeline` → primer elemento del array con
     `event == "cross-referenced"` cuyo `source.issue.pull_request` no sea nulo → `source.issue.number`;
   - `pr_diff`: `GET /pulls/<n>` con `Accept: application/vnd.github.diff` → el cuerpo como texto;
   - `comment`: `POST /issues/<n>/comments` con `{"body"}`.
6. Tests con un servidor falso en `127.0.0.1` (puerto 0) que atiende UNA conexión, devuelve una respuesta fija
   y entrega la petición recibida (línea de petición, cabeceras y cuerpo) para comprobarla.

## Ejemplo (entrada y resultado esperado)

```
servidor falso responde `201` con {"number": 7}:
  GitHubHttp::new(url, "acme", "app", "t0k").create_issue("T1", "cuerpo") → Ok(7)
  la petición recibida empieza por "POST /repos/acme/app/issues " y contiene "authorization: Bearer t0k" (sin distinguir mayúsculas) y "\"title\":\"T1\""
servidor falso responde `200` con [{"event":"labeled"},{"event":"cross-referenced","source":{"issue":{"number":12,"pull_request":{"url":"x"}}}}]:
  find_linked_pr(7) → Ok(Some(12))
servidor falso responde `404` con {"message":"Not Found"}: comment(7, "hola") → Err cuyo texto empieza por "GitHub 404" y no contiene "t0k"
```

## Tests (con estos nombres)

- `crea_issue_y_lee_el_numero`: el primer caso del ejemplo, con la ruta, el token y el título en la petición
- `asigna_a_copilot`: la petición va a /issues/7/assignees y su cuerpo contiene COPILOT_ASSIGNEE
- `encuentra_el_pr_enlazado`: la cronología del ejemplo devuelve Some(12)
- `sin_pr_enlazado`: una cronología sin referencias cruzadas a un PR devuelve None
- `diff_del_pr_como_texto`: pr_diff pide con Accept application/vnd.github.diff y devuelve el cuerpo tal cual
- `error_http_sin_token`: una respuesta 404 da un error que empieza por `GitHub 404` y no contiene el token
- `from_env_sin_token`: sin GITHUB_TOKEN (pásalo por una función interna que reciba los valores, sin tocar el entorno del proceso) devuelve el error de la variable

## No hagas

- No hagas peticiones a github.com en los tests: solo a 127.0.0.1
- No escribas ningún token real en tests ni fixtures
- No añadas más dependencias que `reqwest`
- No pongas reintentos ni esperas sin tiempo máximo (usa un timeout de 30 s en el cliente)

## Notas

Para probar `from_env` sin modificar variables de entorno (los tests corren en paralelo), separa la lógica en
una función privada `from_values(owner, repo, token: Option<String>, base: Option<String>)` y prueba esa.
