## Objetivo

Hoy `pcode mcp` lista los servidores MCP configurados. Se le añade una opción para hacer lo contrario: servir las
tools de PublicCode a otro agente. Sin `--servir`, todo sigue igual.
1. `Cargo.toml` de pcode-cli: añade `pcode-mcp = { path = "../pcode-mcp" }` en `[dependencies]`.
2. `main.rs`: en la variante `Mcp` añade `#[arg(long = "servir")] serve: bool` (doc: «Sirve las tools de PublicCode
   por MCP en stdio») y `#[arg(long = "politica")] policy: Option<std::path::PathBuf>` (doc: «TOML con una sección
   `[politica]` que restringe las tools»). Declara `mod mcp_serve;`. En el `match`: si `serve`,
   `std::process::exit(mcp_serve::run(policy.as_deref()).await?)`; si no, lo de ahora.
3. `mcp_serve.rs` con la función de *Firmas*: `root = std::env::current_dir()?`; política
   `Policy::new(Capabilities::interactive_defaults())` y, si hay `--politica`, `.child(crate::run::load_capabilities(p))`;
   `McpServer::new(&pcode_tools::native_registry(), policy, ToolContext { root, timeout: Duration::from_secs(120) })`;
   `serve(tokio::io::BufReader::new(tokio::io::stdin()), tokio::io::stdout())`; devuelve `Ok(0)`. Nada de `println!`
   (stdout es el canal del protocolo).
4. Test de integración `tests/mcp_servir.rs` con `assert_cmd` (`current_dir` en un tempdir, `write_stdin` con las
   líneas JSON terminadas en `\n`, `timeout` de 30 s).
