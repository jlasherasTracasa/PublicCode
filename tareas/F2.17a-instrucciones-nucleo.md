## Objetivo

`AGENTS.md` es la fuente única. De él salen `GEMINI.md` y `.github/copilot-instructions.md` (copias con
cabecera) y se garantiza que `CLAUDE.md` lo importa.

1. Crea `instructions.rs` con `GENERATED_HEADER`, `render_derived`, `ensure_claude_import` y
   `sync_instructions` (firmas abajo).
2. `render_derived(agents_md, existing)`: `GENERATED_HEADER` + `"\n\n"` + `agents_md` sin espacios
   finales + `"\n"`. Si `existing` contiene una sección entre `<!-- skills:inicio -->` y
   `<!-- skills:fin -->` y `agents_md` NO contiene `<!-- skills:inicio -->`, añade al final `"\n"` + esa
   sección (marcadores incluidos) + `"\n"`. Así no se pierde lo que escribió la exportación de skills.
3. `ensure_claude_import(claude_md)`: si la primera línea (sin espacios) ya es `@AGENTS.md`, devuelve el
   texto igual; si el texto está vacío, devuelve `"@AGENTS.md\n"`; si no, devuelve
   `"@AGENTS.md\n\n"` + el texto original.
4. `sync_instructions(repo_root, check_only)`: lee `AGENTS.md` (si no existe:
   `SkillError::Invalid("AGENTS.md".into(), "no existe".into())`). Calcula el contenido deseado de
   `CLAUDE.md` (con `ensure_claude_import` sobre el actual, o cadena vacía si no existe), `GEMINI.md` y
   `.github/copilot-instructions.md` (con `render_derived` sobre el actual o cadena vacía). Devuelve, en
   ese orden, las rutas RELATIVAS de los archivos cuyo contenido actual difiere del deseado. Si
   `check_only` es false, además los escribe (creando `.github/` si hace falta).
5. `lib.rs`: `pub mod instructions;` y
   `pub use instructions::{GENERATED_HEADER, ensure_claude_import, render_derived, sync_instructions};`.
6. Tests en `instructions.rs`, siempre sobre un `tempfile::tempdir()`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-skills/src/instructions.rs
/// Primera línea de los archivos derivados.
pub const GENERATED_HEADER: &str = "<!-- generado desde AGENTS.md por pcode; no editar -->";

/// Contenido de un archivo derivado (`GEMINI.md`, `copilot-instructions.md`).
pub fn render_derived(agents_md: &str, existing: &str) -> String;

/// `CLAUDE.md` con `@AGENTS.md` en la primera línea y el resto intacto.
pub fn ensure_claude_import(claude_md: &str) -> String;

/// Sincroniza (o solo comprueba) los archivos derivados; devuelve los desfasados, relativos a la raíz.
pub fn sync_instructions(repo_root: &std::path::Path, check_only: bool)
    -> Result<Vec<std::path::PathBuf>, crate::SkillError>;
```

## Ejemplo (entrada y resultado esperado)

```
render_derived("# Guía\nregla\n", "")
  → "<!-- generado desde AGENTS.md por pcode; no editar -->\n\n# Guía\nregla\n"
ensure_claude_import("## Notas\n- x\n")  → "@AGENTS.md\n\n## Notas\n- x\n"
ensure_claude_import("@AGENTS.md\n\n## Notas\n")  → igual que la entrada
sync_instructions(raíz con solo AGENTS.md, false)
  → ["CLAUDE.md", "GEMINI.md", ".github/copilot-instructions.md"]   (y los tres existen después)
sync_instructions(la misma raíz, false) otra vez → []
```

## Tests (con estos nombres)

- `render_pone_cabecera_y_contenido`: el primer ejemplo da exactamente esa cadena
- `render_conserva_la_seccion_de_skills`: si `existing` tiene una sección `skills:inicio`…`skills:fin`, el resultado la incluye una sola vez
- `claude_anade_la_importacion_y_respeta_el_resto`: el segundo ejemplo; y un texto que ya empieza por `@AGENTS.md` no cambia
- `sync_crea_gemini_y_copilot`: en una raíz con solo AGENTS.md se crean los tres archivos y se devuelven sus tres rutas
- `sync_idempotente`: una segunda llamada devuelve un vector vacío y no cambia los archivos
- `comprobar_detecta_desfase_sin_escribir`: tras cambiar AGENTS.md, `check_only = true` devuelve GEMINI.md y copilot-instructions y GEMINI.md sigue con el contenido viejo
- `sin_agents_md_es_error`: en una raíz vacía devuelve `SkillError::Invalid`
