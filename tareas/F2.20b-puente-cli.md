## Objetivo

1. `main.rs`, enum `Cmd`: añade la variante
   `#[command(name = "__puente", hide = true)] Puente { #[arg(long)] escucha: std::net::SocketAddr, #[arg(long)] socket: std::path::PathBuf, #[arg(long)] listo: Option<std::path::PathBuf> }`
   con el comentario «Uso interno: puente TCP→Unix de la red filtrada de la mini sandbox».
2. `main.rs`, en el `match cli.command`, rama `Some(Cmd::Puente { escucha, socket, listo })`:
   a) `let l = tokio::net::TcpListener::bind(escucha).await?;`
   b) si `listo` es `Some(f)`: escribe en `f` la dirección real (`l.local_addr()?.to_string()`). Ese
      archivo avisa a quien espera de que el puente ya escucha (y dice el puerto si se pidió el 0).
   c) `pcode_sandbox::bridge(l, socket).await?; Ok(())`.
   En plataformas sin Unix (`#[cfg(not(unix))]`) la rama hace `anyhow::bail!("solo disponible en Linux")`.
3. Crea `tests/puente.rs` (solo Unix: `#![cfg(unix)]`). Cada test: crea un `tempfile::tempdir()`, un eco
   en un `std::os::unix::net::UnixListener` atendido en un `std::thread`, lanza
   `std::process::Command::new(assert_cmd::cargo::cargo_bin("pcode"))` con
   `__puente --escucha 127.0.0.1:0 --socket <eco.sock> --listo <dir>/listo`, espera a que `listo` exista
   y no esté vacío (máximo 100 intentos de 50 ms), lee la dirección, conecta con `std::net::TcpStream`
   (con `set_read_timeout` de 5 s) y, al terminar, mata el proceso (`child.kill()`).

Sin firmas: solo añade una variante privada al enum `Cmd` del binario

## Ejemplo (entrada y resultado esperado)

```
pcode __puente --escucha 127.0.0.1:0 --socket /tmp/x/eco.sock --listo /tmp/x/listo
  → /tmp/x/listo contiene «127.0.0.1:41877»; un cliente TCP a esa dirección habla con /tmp/x/eco.sock
```

## Tests (con estos nombres)

- `puente_cli_reenvia_al_socket`: el cliente TCP escribe `hola` y lee `hola` a través del proceso `pcode __puente`
- `puente_cli_escribe_el_archivo_listo`: el archivo `--listo` contiene una dirección `127.0.0.1:<puerto>` con puerto distinto de 0
- `puente_cli_no_sale_en_la_ayuda`: la salida de `pcode --help` no contiene `__puente`

## No hagas

- No dejes procesos vivos: cada test mata el `pcode __puente` que lanzó
- No esperes sin límite a que aparezca el archivo `listo`
