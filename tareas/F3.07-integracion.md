## Objetivo

En un worktree de integración (`git worktree add .pcode/integracion main`), de una en una:
1. Aplica los cambios de la tarea (desde su rama o desde la capa de la sandbox) y hace un commit
   `<id>: <título>` con SOLO las rutas de los cambios (nunca `git add -A`).
2. `git rebase main`. Si hay conflicto SOLO en lockfiles (`Cargo.lock`): toma la versión de main,
   regenera (`cargo metadata --offline >/dev/null` o `cargo update -w --offline`) y continúa.
3. Conflicto en `Cargo.toml` raíz de un workspace con `members = ["lib/*"]` o `["crates/*"]`: si las
   dos partes solo añaden miembros, une las listas; si no → `IntegracionFallo` para el coordinador.
4. Cualquier otro conflicto → `git rebase --abort` e `IntegracionFallo`.
5. Re-ejecuta `acepta` sobre el resultado del rebase; solo si pasa, fast-forward de main.
6. Tests con repos git temporales y un workspace Cargo mínimo.
