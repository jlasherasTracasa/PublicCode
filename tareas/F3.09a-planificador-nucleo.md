## Objetivo

1. Crea `planner.rs` con las firmas de abajo. Lógica pura: ni red ni disco.
2. `should_plan`: true si el número de filas `Cell::Ready` más `Cell::Running` es menor que `min_ready`.
3. `planner_prompt`: texto para el modelo fuerte con: (a) «Eres el planificador. Escribe las tareas que faltan
   para este objetivo.» y `# Objetivo` con `goal`; (b) `# Tareas que ya existen`: una línea `- <id>: <estado>`
   por fila (`hecha`, `en marcha`, `lista`, `esperando`, `coordinador`, `atascada`) para que no las repita y
   pueda depender de ellas; (c) las mismas reglas de tarea apta y el mismo formato de archivo y de respuesta
   (bloques `<<<ID.md` … `>>>`) que `split_prompt`; (d) «Cada tarea lleva una orden `acepta` que falle si la
   tarea no está hecha. Ids nuevos, que no estén en la lista.». Con `repair = Some((anterior, problemas))`
   añade al final `# Tu respuesta anterior`, el texto, y `# Corrige` con un problema por línea.
4. `check_plan`: convierte cada bloque con `crate::task::parse_task(nombre, contenido)`; si falla, problema
   `<nombre>: <error>`; con las que parsean llama a `crate::drafts::check_drafts` y une los problemas. Sin
   ningún bloque: problema `la respuesta no trae ninguna tarea`. Devuelve las tareas parseadas y los problemas.
5. `lib.rs`: añade `pub mod planner;`.

## Ejemplo (entrada y resultado esperado)

```
filas: A Done, B Ready, C Waiting(["B"])

check_plan([], …) → ([], ["la respuesta no trae ninguna tarea"])
check_plan([("T9", "sin cabecera")], …) → ([], ["T9: T9: falta `acepta`"])
```

## Tests (con estos nombres)

- `planifica_si_pocas_listas`: los dos casos de should_plan del ejemplo
- `prompt_lleva_objetivo_y_tareas_existentes`: el prompt contiene el objetivo, las líneas de A y C y la marca `<<<`
- `prompt_de_reparacion`: con repair aparecen `# Corrige` y el problema
- `rechaza_sin_acepta`: un bloque sin cabecera acepta da un problema y ninguna tarea
- `rechaza_id_repetido`: un bloque válido cuyo id ya existe da el problema de id existente
- `rechaza_demasiados_archivos`: una tarea con cinco rutas en Toca da un problema con `[toca]`
- `acepta_valida`: dos tareas válidas (la segunda depende de la primera) dan cero problemas
- `respuesta_vacia`: sin bloques da el problema del ejemplo
