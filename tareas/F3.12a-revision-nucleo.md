## Objetivo

1. Crea `review.rs` con las firmas de abajo. Lógica pura.
2. `rubric`: lista de comprobaciones, en este orden: (a) si `allowed_paths(task)` no está vacío: `Solo cambia
   estos archivos: a, b`; (b) fijas: `No hay claves, tokens ni contraseñas en el diff`; `No desactiva ni borra
   tests para pasar la aceptación`; `No cambia la orden de aceptación ni la configuración de CI`; `No añade
   dependencias que la tarea no pide`; `No ejecuta órdenes, accede a la red ni borra archivos que la tarea no
   pide`; (c) una por test de la tarea: `Existe el test <nombre>` (nombre = lo que precede al primer `:`; se
   saltan los que empiezan por `(`); (d) las de `extra_rules`, tal cual.
3. `review_prompt`: «Revisa este cambio. No lo ejecutes ni lo modifiques.», `# Rúbrica` (una línea `- ` por
   comprobación), `# Diff` (el diff en un bloque de código) y el formato: responde SOLO con un JSON
   `{"aprobado": true|false, "problemas": [{"gravedad": "alta|media|baja", "archivo": "ruta", "linea": 12,
   "descripcion": "…", "seguridad": true|false}]}`.
4. `parse_verdict`: toma el texto desde la primera `{` hasta la última `}` y lo parsea con `serde_json`. Si no
   hay llaves o no parsea → `Undetermined(motivo)`. Si algún problema tiene `seguridad == true`, `gravedad ==
   "alta"` y evidencia (`diff_has`) → `NeedsCoordinator(todos los problemas)`. En cualquier otro caso →
   `Approved(problemas)`: el veredicto nunca bloquea por sí solo.
5. `diff_has(diff, file, line)`: true si el diff contiene la línea `+++ b/<file>` y, cuando `line` es Some, ese
   número cae dentro de algún bloque `@@ -a,b +c,d @@` de ese archivo (`c <= line < c + d`; sin `,d`, d = 1).
6. `lib.rs`: añade `pub mod review;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/review.rs
use crate::task::TaskDef;

/// Un problema señalado por el revisor.
#[derive(Debug, Clone, PartialEq, serde::Deserialize, serde::Serialize)]
pub struct Issue {
    #[serde(rename = "gravedad")]
    pub severity: String,
    #[serde(rename = "archivo", default)]
    pub file: String,
    #[serde(rename = "linea", default)]
    pub line: Option<u32>,
    #[serde(rename = "descripcion", default)]
    pub description: String,
    #[serde(rename = "seguridad", default)]
    pub security: bool,
}

/// Veredicto de la revisión.
#[derive(Debug, Clone, PartialEq)]
pub enum Verdict { Approved(Vec<Issue>), NeedsCoordinator(Vec<Issue>), Undetermined(String) }

pub fn rubric(task: &TaskDef, extra_rules: &[String]) -> Vec<String>;
pub fn review_prompt(diff: &str, rubric: &[String]) -> String;
pub fn diff_has(diff: &str, file: &str, line: Option<u32>) -> bool;
pub fn parse_verdict(text: &str, diff: &str) -> Verdict;
```

## Ejemplo (entrada y resultado esperado)

```
diff = "--- a/src/a.rs\n+++ b/src/a.rs\n@@ -1,2 +10,3 @@\n+let k = \"sk-123\";\n"
diff_has(diff, "src/a.rs", Some(11)) → true     diff_has(diff, "src/a.rs", Some(40)) → false     diff_has(diff, "src/b.rs", None) → false
parse_verdict("Aquí va:\n{\"aprobado\": false, \"problemas\": [{\"gravedad\": \"alta\", \"archivo\": \"src/a.rs\", \"linea\": 10, \"descripcion\": \"clave\", \"seguridad\": true}]}", diff)
  → NeedsCoordinator([..])
El mismo JSON con "archivo": "src/otro.rs" → Approved([..])       parse_verdict("no sé", diff) → Undetermined(..)
```

## Tests (con estos nombres)

- `rubrica_incluye_toca`: una tarea con dos rutas permitidas empieza por `Solo cambia estos archivos: …`
- `rubrica_incluye_tests_y_reglas_extra`: aparece `Existe el test crea_a` y, al final, la regla extra
- `prompt_lleva_rubrica_diff_y_formato`: el prompt contiene las comprobaciones, el diff y `"aprobado"`
- `veredicto_aprobado`: un JSON con aprobado true y sin problemas da Approved con lista vacía
- `seguridad_alta_con_evidencia_va_a_coordinador`: el caso del ejemplo da NeedsCoordinator
- `seguridad_sin_evidencia_no_bloquea`: el mismo problema sobre un archivo que no está en el diff da Approved
- `gravedad_media_no_bloquea`: seguridad true con gravedad media da Approved
- `json_roto_indeterminado`: un texto sin llaves o con JSON inválido da Undetermined
- `evidencia_por_linea`: los tres casos de diff_has del ejemplo
