## Objetivo

1. En `context.rs` añade la constante `CONTEXT_TOOL`, la función `context_spec` y el método
   `ContextLedger::handle` (firmas abajo). No cambies lo que ya hay en el archivo.
2. `context_spec()`: nombre `contexto`; descripción EXACTA: «Gestiona tu contexto. Cada resultado de
   tool empieza por un id como [r7]. op "soltar": sustituye por una línea los resultados de `ids` que ya
   no necesitas. op "fijar": marca los resultados de `ids` para que la compactación no los resuma.
   op "lista": qué resultados siguen en el contexto.»; parámetros
   `{"type":"object","properties":{"op":{"type":"string","enum":["soltar","fijar","lista"]},"ids":{"type":"array","items":{"type":"integer"}}},"required":["op"]}`.
3. `handle(args, messages)` devuelve el texto del resultado de la tool:
   - `ids` = los enteros positivos de `args["ids"]` (si falta o no es una lista, vacío).
   - `op == "soltar"`: si `ids` está vacío devuelve `faltan ids, p. ej. {"op":"soltar","ids":[3]}`; si no,
     llama a `drop_results` y devuelve `soltados {n} de {m} (los fijados y los ya soltados no se tocan)`,
     con `m = ids.len()`.
   - `op == "fijar"`: si `ids` está vacío, el mismo mensaje con `fijar`; si no, llama a `pin` y devuelve
     `fijados: r1, r4` con TODOS los fijados en orden ascendente (o `fijados: ninguno`).
   - `op == "lista"`: una línea por mensaje con rol `Tool` que empiece por `[r{id}] ` (los soltados no
     salen): `r{id}{marca} {n} caracteres: {primera}`, donde `marca` es ` (fijado)` o nada, `n` es
     `content.chars().count()` y `primera` la primera línea tras el prefijo recortada a 60 caracteres.
     Sin resultados: `no hay resultados de tools en el contexto`.
   - Otro valor o sin `op`: `op no válida: usa "soltar", "fijar" o "lista"`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-core/src/context.rs (añadir)
/// Nombre de la tool con la que el agente gestiona su contexto.
pub const CONTEXT_TOOL: &str = "contexto";

/// Especificación de la tool `contexto`.
pub fn context_spec() -> pcode_models::ToolSpec;

impl ContextLedger {
    /// Ejecuta una llamada a `contexto` sobre el historial y devuelve el texto del resultado.
    pub fn handle(&mut self, args: &serde_json::Value, messages: &mut [Message]) -> String;
}
```

## Ejemplo (entrada y resultado esperado)

```
historial: Tool "[r1] uno", Tool "[r2] dos\nmás", Tool "[r3] tres"
handle({"op":"fijar","ids":[1]})        -> "fijados: r1"
handle({"op":"soltar","ids":[1,2]})     -> "soltados 1 de 2 (los fijados y los ya soltados no se tocan)"
handle({"op":"lista"})                  -> "r1 (fijado) 8 caracteres: uno\nr3 9 caracteres: tres"
handle({"op":"borrar"})                 -> "op no válida: usa \"soltar\", \"fijar\" o \"lista\""
```

## Tests (con estos nombres)

- `tool_spec_tiene_nombre_y_op_obligatoria`: context_spec().name es contexto y required contiene op
- `tool_soltar_y_fijar_como_en_el_ejemplo`: la secuencia del ejemplo da exactamente esos textos
- `tool_lista_omite_soltados_y_marca_fijados`: tras soltar r2, lista devuelve solo r1 (fijado) y r3
- `tool_sin_ids_explica_el_formato`: soltar sin ids devuelve el mensaje que empieza por `faltan ids`
- `tool_op_desconocida`: op borrar y args vacíos devuelven el mensaje de op no válida
