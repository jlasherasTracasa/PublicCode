## Objetivo

1. Crea `roles.rs` con `AgentRole`, `RoleInputs`, `build_context` y `role_capabilities` (firmas abajo).
   En `lib.rs` añade `pub mod roles;` (después de `pub mod memory;`). El enum se llama `AgentRole` para
   no chocar con `pcode_models::Role`.
2. `build_context(role, i)` devuelve SIEMPRE dos mensajes: `Message::system(texto del rol)` y
   `Message::user(secciones)`. Nunca recibe ni copia el historial de otro agente.
3. Texto de sistema de cada rol (constantes privadas, texto EXACTO):
   - Explorer: «Eres un explorador de código de solo lectura. Responde a la pregunta con rutas y líneas
     concretas; no propongas cambios ni edites nada.»
   - Implementer: «Eres el implementador de una tarea. Haz solo lo que pide la tarea, respeta las notas
     de los archivos y comprueba el resultado antes de terminar.»
   - Reviewer: «Eres un revisor independiente. Juzga el diff solo con la tarea y la rúbrica: no conoces
     la conversación de quien lo escribió. Responde a cada punto de la rúbrica y da un veredicto.»
   - Critic: «Eres un crítico de planes. Di qué restricción incumple el plan o qué caso deja sin cubrir;
     no reescribas el plan entero.»
4. Secciones del mensaje de usuario: cada una es `# {título}\n{contenido}\n`, separadas por una línea
   en blanco, en este orden y SOLO las de su rol (las demás se ignoran aunque vengan rellenas):
   - Explorer: `Tarea` (task), `Mapa del repositorio` (repo_map), `Pregunta` (question).
   - Implementer: `Tarea`, `Relevo` (handoff), `Notas de los archivos` (facets), `Skills` (skills_index).
   - Reviewer: `Tarea`, `Diff` (diff), `Rúbrica` (rubric).
   - Critic: `Tarea`, `Plan propuesto` (plan), `Restricciones` (constraints).
   Una sección cuyo dato es `None`, cadena vacía o lista vacía se omite. Las listas (`rubric`,
   `constraints`) se escriben con una línea `- elemento` por elemento. El contenido se usa sin los
   espacios de los extremos.
5. `role_capabilities(role)`: para Explorer, Reviewer y Critic,
   `Capabilities { deny_effects: vec![Effect::Write, Effect::Exec, Effect::Network, Effect::Irreversible], ..Default::default() }`;
   para Implementer, `Capabilities::default()`. Se usa como capa hija: `policy.child(role_capabilities(r))`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-core/src/roles.rs
use pcode_models::Message;
use pcode_policy::Capabilities;

/// Rol de un subagente.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum AgentRole { Explorer, Implementer, Reviewer, Critic }

/// Lo que puede entrar en el contexto inicial de un subagente (cada rol usa solo lo suyo).
#[derive(Debug, Clone, Default)]
pub struct RoleInputs {
    pub task: String,
    pub question: Option<String>,
    pub handoff: Option<String>,
    pub repo_map: Option<String>,
    pub facets: Option<String>,
    pub skills_index: Option<String>,
    pub diff: Option<String>,
    pub rubric: Vec<String>,
    pub plan: Option<String>,
    pub constraints: Vec<String>,
}

/// Mensajes iniciales (sistema y usuario) de un subagente con ese rol.
pub fn build_context(role: AgentRole, i: &RoleInputs) -> Vec<Message>;

/// Capa de política del rol: los roles que solo leen no pueden escribir, ejecutar ni usar la red.
pub fn role_capabilities(role: AgentRole) -> Capabilities;
```

## Ejemplo (entrada y resultado esperado)

```
let i = RoleInputs { task: "Arregla el parser".into(), handoff: Some("secreto del implementador".into()),
                     diff: Some("+ fn a() {}".into()), rubric: vec!["compila".into(), "tiene tests".into()],
                     ..Default::default() };
build_context(AgentRole::Reviewer, &i)[1].content ==
  "# Tarea\nArregla el parser\n\n# Diff\n+ fn a() {}\n\n# Rúbrica\n- compila\n- tiene tests\n"
build_context(AgentRole::Implementer, &i)[1].content ==
  "# Tarea\nArregla el parser\n\n# Relevo\nsecreto del implementador\n"
```

## Tests (con estos nombres)

- `revisor_no_ve_historial`: el primer caso del ejemplo; el texto no contiene `secreto del implementador`
- `implementador_incluye_relevo`: el segundo caso del ejemplo, carácter a carácter
- `explorador_con_mapa_y_pregunta`: con repo_map y question salen las secciones Tarea, Mapa del repositorio y Pregunta en ese orden
- `critico_lista_restricciones`: constraints [a, b] da la sección Restricciones con dos líneas `- `
- `siempre_sistema_y_usuario`: los cuatro roles devuelven dos mensajes, el primero de sistema y distinto en cada rol
- `explorador_sin_tools_de_escritura`: Policy::new(Capabilities::default()).child(role_capabilities(Explorer)).tool_visible("escribir", &[Effect::Write]) es false y con Implementer es true
