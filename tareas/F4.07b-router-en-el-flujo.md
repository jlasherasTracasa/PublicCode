# F4.07b-router-en-el-flujo — Router en `pcode flow run --router <carpeta>`: elegir backend por el histórico del banco

## Contexto (lee esto y nada más)

- crates/pcode-flow/src/runner.rs (`Runner::tick`: el bloque `let wanted = …` que decide el backend de cada tarea; `RunnerCfg`)
- crates/pcode-flow/src/router.rs (`RouterStats`, `feature`, `choose`, `stats_from_runs`)
- crates/pcode-cli/src/flow_cmd.rs (rama `Run`: cómo se construyen los backends; los resultados del banco se guardan en archivos `<backend>-<segundos>.jsonl`)

## Objetivo

1. `runner.rs`: campo `pub router: Option<crate::router::RouterStats>` en `RunnerCfg` («Histórico del banco para
   elegir backend.»). Añade la función pública `pick_backend` (firma abajo): si la tarea fija `backend`, ese;
   si hay `router`, `choose(stats, &feature(task), candidates, 0.3, default)`; si no, `default`.
2. En `Runner::tick`, sustituye el cálculo de `wanted` por `pick_backend(tarea, &self.cfg.default_backend,
   self.cfg.router.as_ref(), &candidatos)`, donde `candidatos` son las claves de `self.backends` ordenadas
   alfabéticamente (calcúlalas una vez, antes del bucle).
3. Actualiza todas las construcciones `RunnerCfg { … }` (`grep -rn "RunnerCfg {" crates/`): `router: None` en
   los tests.
4. `flow_cmd.rs`: función `backend_of_file` (firma abajo): del nombre de archivo sin extensión quita el sufijo
   `-<cifras>` si lo tiene. Rama `Run`: flag `--router <carpeta>` («Elige el backend de cada tarea según los
   resultados del banco de esa carpeta.») y flag repetible `--candidato <backend>` (backends adicionales entre
   los que elegir; se construyen con `build_backend` y se añaden al mapa). Con `--router`: lee cada `*.jsonl`
   de la carpeta con `pcode_flow::bench::parse_rows` (los que no parsean se avisan en stderr y se saltan),
   agrupa por `backend_of_file` y pasa `Some(stats_from_runs(&runs, &tareas))`.
5. Tests: `router_elige_*` en el módulo `tests` de `runner.rs`; `router_backend_*` en el de `flow_cmd.rs`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/runner.rs
/// Backend con el que se lanza una tarea: el que fija la tarea, el que recomienda el histórico o el de por defecto.
pub fn pick_backend(
    task: &TaskDef,
    default: &str,
    router: Option<&crate::router::RouterStats>,
    candidates: &[String],
) -> String;

// crates/pcode-cli/src/flow_cmd.rs
/// Backend al que pertenece un archivo de resultados (`glm-1731000000` → `glm`).
pub fn backend_of_file(stem: &str) -> String;
```

## Ejemplo (entrada y resultado esperado)

```
backend_of_file("glm-1731000000") → "glm"     backend_of_file("claude-code-17") → "claude-code"     backend_of_file("glm") → "glm"
pick_backend(tarea con backend Some("x"), "glm", Some(&stats), &cands) → "x"
pick_backend(tarea sin backend, "glm", None, &cands) → "glm"
pick_backend(tarea sin backend cuyo rasgo tiene 4 muestras buenas de claude y 4 malas de glm, "glm", Some(&stats), ["claude","glm"]) → "claude"
```

## Tests (con estos nombres)

- `router_elige_el_backend_de_la_tarea`: una tarea con backend fijado lo conserva aunque el histórico diga otra cosa
- `router_elige_por_historico`: sin backend fijado gana el que recomienda el histórico
- `router_elige_defecto_sin_router`: sin RouterStats devuelve el backend por defecto
- `router_backend_del_nombre_de_archivo`: los tres casos de backend_of_file del ejemplo

## No hagas

- No cambies `next_backend` ni la política de reintentos: el router solo decide el backend inicial
- No toques los tests existentes salvo para añadir el campo nuevo
