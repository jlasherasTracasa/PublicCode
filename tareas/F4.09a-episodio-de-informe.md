# F4.09a-episodio-de-informe — `episodic.rs`: convertir un informe de tarea en un `Episode` y pintarlo compacto (lógica pura)

## Objetivo

1. Crea `episodic.rs` con `Episode`, `parse_report` y `render` (firmas abajo). En `lib.rs` añade
   `pub mod episodic;`. Aquí no se lee el disco.
2. `parse_report(file_stem, text, verified)`:
   - `task`: el texto de la primera línea que empieza por `# ` (sin el `# `); si no hay, lo que va antes
     del primer `-` de `file_stem` (`F2.22-mcp-cliente` → `F2.22`).
   - Las secciones empiezan en una línea `## Título` y acaban en la siguiente `## `. De cada sección
     interesan sus viñetas: líneas que empiezan por `- ` (sin el `- ` y sin espacios en los extremos).
   - `summary`: las viñetas de `## Hecho` unidas con ` · `, recortadas a 300 caracteres.
   - `files`: las viñetas de `## Archivos`, sin acentos graves alrededor.
   - `lessons`: las viñetas de `## Decisiones`, salvo las que en minúsculas son `ninguna` o `ninguna.`.
   - `pending`: las viñetas de `## Pendiente`, salvo `nada` o `nada.`.
   - `source`: `coordinador` si el texto en minúsculas contiene `por el coordinador`; si no, `agente`.
   - `verified`: el parámetro.
3. `render(eps)`: por episodio, como mucho 3 líneas, y una línea en blanco entre episodios:
   - `[{task} · {verificado|NO verificado} · {source}] {summary}`
   - `  archivos: a, b, c` (como mucho 5; si hay más, añade `, …`); se omite si no hay.
   - `  lecciones: l1 · l2` (como mucho 2); se omite si no hay.
   Sin episodios, cadena vacía.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-memory/src/episodic.rs
/// Lo que quedó de una tarea anterior.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Episode {
    pub task: String,
    pub summary: String,
    pub files: Vec<String>,
    pub lessons: Vec<String>,
    pub pending: Vec<String>,
    /// Si la tarea pasó su aceptación.
    pub verified: bool,
    /// Quién lo hizo: `coordinador` (modelo fuerte o persona) o `agente`.
    pub source: String,
}

/// Episodio a partir del texto de un informe (`informes/<id>-<nombre>.md`).
pub fn parse_report(file_stem: &str, text: &str, verified: bool) -> Episode;

/// Episodios como texto compacto para el contexto (3 líneas por episodio como mucho).
pub fn render(eps: &[&Episode]) -> String;
```

## Ejemplo (entrada y resultado esperado)

```
text = "# F9.01\n## Hecho\n- Parser de blame.\n- Tests.\n## Archivos\n- `crates/x/src/blame.rs`\n## Salida de acepta\nok\n## Decisiones\n- El sha se corta a 8.\n## Pendiente\n- nada\n"
parse_report("F9.01-blame", text, true) == Episode {
  task: "F9.01", summary: "Parser de blame. · Tests.", files: ["crates/x/src/blame.rs"],
  lessons: ["El sha se corta a 8."], pending: [], verified: true, source: "agente" }
render(&[&e]) == "[F9.01 · verificado · agente] Parser de blame. · Tests.\n  archivos: crates/x/src/blame.rs\n  lecciones: El sha se corta a 8.\n"
```

## Tests (con estos nombres)

- `episodio_del_ejemplo`: parse_report del texto del ejemplo da exactamente ese Episode
- `episodio_sin_titulo_usa_el_nombre_del_archivo`: un texto sin línea `# ` y file_stem F2.22-mcp-cliente da task F2.22
- `episodio_del_coordinador`: un informe con la frase `Implementado por el coordinador` da source coordinador
- `episodio_ignora_ninguna_y_nada`: Decisiones con `- ninguna` y Pendiente con `- nada` dan listas vacías
- `episodio_render_compacto`: el render del ejemplo, carácter a carácter; con verified false dice `NO verificado`
- `episodio_render_limita_archivos_y_lecciones`: con 7 archivos salen 5 y `, …`; con 3 lecciones salen 2
