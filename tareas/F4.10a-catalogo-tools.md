## Objetivo

Cada tool anunciada cuesta tokens en CADA petición. Con muchas tools de MCP se anuncian solo las
nativas más `buscar_tools`; lo que el agente encuentra con ella queda visible desde ese momento.
1. Crea `catalog.rs` con lo de las firmas. En `lib.rs` añade `pub mod catalog;` (después de
   `pub mod bm25;`). Todo trabaja sobre `Vec<ToolSpec>` (lo que devuelve `specs_filtered`); no hay E/S.
2. `is_deferrable(spec)`: `spec.description.starts_with("[MCP ")` (las nativas nunca se ocultan).
3. `dedupe(specs)`: clave de una tool aplazable = (descripción normalizada, `parameters.to_string()`).
   La descripción normalizada es la descripción sin el prefijo `[MCP …] ` (hasta el primer `] `
   incluido), en minúsculas y con los espacios colapsados. Si dos aplazables tienen la misma clave y la
   descripción normalizada no está vacía, se queda SOLO la primera (como la entrada viene de menor a
   mayor privilegio, gana la de menor privilegio). Las no aplazables no se tocan. Se conserva el orden.
4. `search_spec()`: nombre `buscar_tools`; descripción EXACTA: «Hay más tools de las que ves. Describe
   lo que necesitas (p. ej. "crear una incidencia") y te devuelvo las que sirven; quedan disponibles a
   partir de la siguiente respuesta.»; parámetros `{"type":"object","properties":{"consulta":{"type":"string"}},"required":["consulta"]}`.
5. `ToolCatalog::visible(specs)`: si `specs.len() <= max_visible`, devuelve `specs` igual (sin
   `buscar_tools`). Si no: las no aplazables, más las aplazables cuyo nombre está en `unlocked`, en su
   orden, y al final `search_spec()`.
6. `ToolCatalog::search(specs, query, k)`: candidatas = las aplazables de `specs`. Índice
   `Bm25::new` con un documento por candidata: `"{name} {description}"`. Toma los `k.clamp(1, 10)`
   mejores, añade sus nombres a `unlocked` y devuelve `Tools disponibles a partir de ahora:\n` más una
   línea `- {name}: {descripción recortada a 200 caracteres}` por cada una. Si la consulta está vacía:
   `falta `consulta``. Si nada coincide: `ninguna tool coincide con «{query}»`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-tools/src/catalog.rs
use pcode_models::ToolSpec;

/// Nombre de la tool de búsqueda de tools.
pub const SEARCH_TOOL: &str = "buscar_tools";
/// A partir de cuántas tools se dejan de anunciar todas.
pub const DEFAULT_MAX_VISIBLE: usize = 20;

/// Si la tool se puede dejar sin anunciar (las de MCP).
pub fn is_deferrable(spec: &ToolSpec) -> bool;
/// Quita las tools de MCP repetidas (misma descripción y mismos parámetros en otro servidor).
pub fn dedupe(specs: Vec<ToolSpec>) -> Vec<ToolSpec>;
/// Especificación de `buscar_tools`.
pub fn search_spec() -> ToolSpec;

/// Qué tools se anuncian al modelo en cada petición.
#[derive(Debug, Clone)]
pub struct ToolCatalog { max_visible: usize, unlocked: std::collections::BTreeSet<String> }

impl ToolCatalog {
    /// Catálogo sin tools desbloqueadas.
    pub fn new(max_visible: usize) -> Self;
    /// Las specs que se anuncian ahora.
    pub fn visible(&self, specs: Vec<ToolSpec>) -> Vec<ToolSpec>;
    /// Busca entre las tools sin anunciar, desbloquea las mejores y devuelve el texto del resultado.
    pub fn search(&mut self, specs: &[ToolSpec], query: &str, k: usize) -> String;
}
```

## Ejemplo (entrada y resultado esperado)

```
specs = [leer (nativa), bash (nativa),
         gh_crear_incidencia  "[MCP gh] Crea una incidencia en el repositorio",
         gl_crear_incidencia  "[MCP gl] Crea una  incidencia en el repositorio"   (mismos parámetros),
         clima_hoy            "[MCP clima] Tiempo de hoy en una ciudad"]
dedupe(specs)                 -> leer, bash, gh_crear_incidencia, clima_hoy
let mut c = ToolCatalog::new(3);
c.visible(dedupe(specs))      -> leer, bash, buscar_tools
c.search(&dedupe(specs), "tiempo ciudad", 5)
   -> "Tools disponibles a partir de ahora:\n- clima_hoy: [MCP clima] Tiempo de hoy en una ciudad"
c.visible(dedupe(specs))      -> leer, bash, clima_hoy, buscar_tools
ToolCatalog::new(20).visible(specs) -> las cinco, sin buscar_tools
```

## Tests (con estos nombres)

- `pocas_tools_todas_visibles`: con max_visible 20 y cinco specs, visible las devuelve todas y sin buscar_tools
- `muchas_tools_solo_nativas_y_buscar`: con max_visible 3, visible devuelve leer, bash y buscar_tools
- `buscar_desbloquea`: la secuencia del ejemplo; tras search, visible incluye clima_hoy
- `buscar_sin_coincidencias_no_desbloquea`: la consulta `zzz` devuelve el texto de ninguna tool coincide y visible no cambia
- `dedupe_prefiere_la_primera`: el caso del ejemplo quita gl_crear_incidencia y conserva el orden
- `dedupe_no_toca_nativas_ni_parametros_distintos`: dos nativas con la misma descripción se conservan, y dos de MCP con la misma descripción y parámetros distintos también
