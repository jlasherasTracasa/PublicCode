## Objetivo

1. `Cargo.toml` de `pcode-server`: añade las dependencias `pcode-flow = { path = "../pcode-flow" }` y
   `pcode-store = { path = "../pcode-store" }`.
2. Crea `flow_api.rs` con las cuatro funciones de abajo. `lib.rs`: añade `pub mod flow_api;`.
3. `task_dtos`: un `TaskDto` por tarea, en el orden de `tasks`. `state`: `done` si el id está en `done`; si no,
   según `state.state(id)`: `Pending` → `pending`, `Running(_)` → `running`, `Accepted` → `accepted`,
   `Integrated` → `integrated`, `Blocked(_)` → `blocked`. `attempts` de `state.attempts` (0 si no consta).
4. `flow_status(repo, running)`: tareas = `pcode_flow::task::load_dir(&repo.join("tareas"))` (si la carpeta no
   existe, lista vacía, sin error); eventos = vacíos si no existe `repo/.pcode/flow.db`; si existe,
   `pcode_store::Store::open`, la sesión cuyo `task == "flujo"` (de `store.sessions(50)`) y
   `pcode_flow::events::load`; `done` = ids con `repo/informes/<id>.md`. `needs_coordinator` = ids de las tareas
   `Mode::Coordinator` cuyo estado no es `done` ni `integrated`. Los errores se devuelven como texto.
5. `changed(prev, now)`: los `TaskDto` de `now` que no están iguales en `prev` (por id; los nuevos también).
6. `request_stop(repo)`: crea `repo/.pcode/` si falta y escribe el archivo vacío `repo/.pcode/STOP`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-server/src/flow_api.rs
use pcode_flow::{FlowState, TaskDef};
use pcode_protocol::{FlowStatusResult, TaskDto};
use std::collections::HashSet;
use std::path::Path;

/// Tareas con su estado, listas para la API.
pub fn task_dtos(tasks: &[TaskDef], state: &FlowState, done: &HashSet<String>) -> Vec<TaskDto>;
/// Estado del flujo del proyecto `repo` (lee `tareas/`, `informes/` y `.pcode/flow.db`).
pub fn flow_status(repo: &Path, running: bool) -> Result<FlowStatusResult, String>;
/// Tareas cuyo estado o intentos cambiaron entre dos lecturas.
pub fn changed(prev: &[TaskDto], now: &[TaskDto]) -> Vec<TaskDto>;
/// Pide parar el flujo (archivo `.pcode/STOP`).
pub fn request_stop(repo: &Path) -> Result<(), String>;
```

## Ejemplo (entrada y resultado esperado)

```
repo temporal con tareas/a.md ("<!-- acepta: true -->\n# a\n"), tareas/b.md (igual, con "<!-- modo: coordinador -->")
e informes/a.md:
  flow_status(repo, false) → tasks [a: done, b: pending], needs_coordinator ["b"], running false
changed([a: pending 0], [a: running 1, b: pending 0]) → [a: running 1, b: pending 0]
changed(x, x) → []
request_stop(repo) → existe repo/.pcode/STOP
```

## Tests (con estos nombres)

- `estado_sin_base_de_datos`: el repo del ejemplo da a hecha, b pendiente y b en needs_coordinator
- `estado_sin_carpeta_de_tareas`: un repo vacío da tasks vacío sin error
- `estado_lee_los_eventos`: tras guardar un Lanzada de a en .pcode/flow.db (Store::open, create_session("flujo", "flujo"), pcode_flow::events::persist), a sale running con 1 intento
- `dto_por_estado`: task_dtos traduce Integrated a `integrated` y Blocked a `blocked`
- `cambios_entre_lecturas`: los dos casos de changed del ejemplo
- `parar_crea_el_archivo`: request_stop crea .pcode/STOP
