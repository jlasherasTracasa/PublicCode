## Objetivo

El flujo no corre dentro del demonio: el demonio lanza `pcode flow run` como una sesión más (igual que
`spec.run`) y vigila `.pcode/flow.db` para emitir `Event::TaskUpdated`.
1. En `server.rs`, añade a `AppState` el método `flow_running` (firma abajo): true si alguna sesión de
   `self.sessions` tiene `backend == "flow"` y `state == SessionState::Running`.
2. Añade `AppState::watch_flow` (firma abajo): `tokio::spawn` de un bucle con
   `tokio::time::interval(Duration::from_secs(1))` y como mucho 86 400 vueltas. En cada vuelta: lee
   `crate::flow_api::flow_status(&repo, true)` con `blocking`; por cada tarea de
   `crate::flow_api::changed(&prev, &now.tasks)` emite `Event::TaskUpdated { task }`; guarda `now.tasks` como
   `prev`; y, DESPUÉS de emitir, si `self.state_of(session) != Some(SessionState::Running)`, termina. `prev`
   empieza vacío: la primera vuelta (inmediata) emite todas las tareas.
3. En el `match` de `rpc`, junto a `methods::WORKSPACE_TASKS`:
   - `methods::FLOW_STATUS`: `ws_reply(id, blocking(move || crate::flow_api::flow_status(&root, running)).await)`
     con `running = st.flow_running()`.
   - `methods::FLOW_RUN`: parámetros `{backend: string, paralelo?: number}`. Sin `backend` →
     `rpc_err(id, -32602, "se esperaba {backend}")`. Si `st.flow_running()` → `rpc_err(id, -32000, "ya hay un
     flujo en marcha")`. Si no: `create_command_session("Flujo de tareas".into(), "flow", args)` con
     `args = ["flow", "run", "--backend", <backend>]` (más `"--paralelo", <n>` si viene), `st.watch_flow(info.id)`
     y responde con el `SessionInfo`.
   - `methods::FLOW_STOP`: `ws_reply(id, crate::flow_api::request_stop(&st.repo).map(|_| true))`.
4. Añade al módulo `tests` los tests de la lista. Usa un `AppState::new(<tempdir>, <binario>, None)` propio (no
   el auxiliar `app`, que usa el directorio temporal del sistema como proyecto).

## Ejemplo (entrada y resultado esperado)

```
proyecto temporal con tareas/a.md = "<!-- acepta: true -->\n# a\n"
flow.status {}                    → result.tasks = [{"id":"a","state":"pending","attempts":0}], result.running = false
flow.run {"backend":"modelo"}     (binario /bin/true) → result.backend = "flow"; llega un evento {"tipo":"taskUpdated","task":{"id":"a",…}}
flow.run {}                       → error.code = -32602
flow.stop {}                      → result = true y existe .pcode/STOP
```

## Tests (con estos nombres)

- `flujo_rpc_status_lista_tareas`: flow.status sobre el proyecto del ejemplo devuelve la tarea a en pending
- `flujo_rpc_run_lanza_sesion_y_emite_task_updated`: con /bin/true como binario, flow.run devuelve una sesión con backend flow y por `st.events.subscribe()` llega un TaskUpdated de a antes de 5 s (tokio::time::timeout)
- `flujo_rpc_run_sin_backend`: flow.run sin parámetros da el error -32602
- `flujo_rpc_stop_crea_el_archivo`: flow.stop devuelve true y crea .pcode/STOP
