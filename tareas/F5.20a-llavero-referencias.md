## Objetivo

Las claves no deben estar en archivos (AGENTS.md, regla 4). Además de `{env:X}`, la configuración admite
`{llavero:nombre}`: el valor se pide a un almacén de secretos. Aquí solo la lógica, probada con un almacén en memoria.
1. Crea `secrets.rs` con lo de *Firmas*. En `lib.rs`: `pub mod secrets;` y la variante nueva de `ConfigError`.
2. `MemoryStore`: un `Mutex<BTreeMap<String, String>>`. `list` devuelve los nombres ordenados, nunca los valores.
3. `expand_secrets(s, store)`: como `expand_env` pero con `{llavero:`; un nombre que el almacén no tiene →
   `Err(ConfigError::MissingSecret(nombre))`; un error del almacén → `Err(ConfigError::Invalid(<mensaje>))`.
   `{llavero:` sin `}` se deja tal cual.
4. `Config::resolve_secrets(&mut self, store)`: aplica `expand_secrets` a la `url`, la `api_key` y el `model` de cada
   proveedor, y a la orden y el entorno de cada `[mcp.*]`. En la `api_key`, si falta el secreto, no falla: deja
   `api_key = None` y `missing_key_env = Some("llavero:<nombre>")` (mismo trato que `{env:X}`). `from_str` no cambia:
   deja `{llavero:…}` sin tocar.
5. `secret_refs(cfg)`: los nombres de todas las referencias `{llavero:…}` que aparecen en esos campos, ordenados y
   sin repetir (para `pcode secreto listar`).

//! Secretos del llavero del sistema: `{llavero:nombre}` en la configuración.
use crate::{Config, ConfigError};

/// Un almacén de secretos (el llavero del sistema o uno en memoria para las pruebas).
pub trait SecretStore: Send + Sync {
    /// El valor del secreto, o `None` si no existe.
    fn get(&self, name: &str) -> Result<Option<String>, String>;
    /// Guarda o sustituye un secreto.
    fn set(&self, name: &str, value: &str) -> Result<(), String>;
    /// Borra un secreto (no es error si no existía).
    fn delete(&self, name: &str) -> Result<(), String>;
    /// Nombres guardados (nunca los valores).
    fn list(&self) -> Result<Vec<String>, String>;
}

/// Almacén en memoria.
#[derive(Debug, Default)]
pub struct MemoryStore { values: std::sync::Mutex<std::collections::BTreeMap<String, String>> }

/// Sustituye cada `{llavero:nombre}` por su valor.

/// Nombres de los secretos que referencia la configuración.
pub fn secret_refs(cfg: &Config) -> Vec<String>;

impl Config {
    /// Resuelve las referencias `{llavero:…}` de proveedores y servidores MCP.
    pub fn resolve_secrets(&mut self, store: &dyn SecretStore) -> Result<(), ConfigError>;

## Tests (con estos nombres)

- `secretos_sustituye_en_config`: MemoryStore con `ant=sk-1` y proveedor con `clave = "{llavero:ant}"` → tras resolve_secrets, `api_key == Some("sk-1")`
- `secretos_falta_en_clave_no_rompe`: secreto inexistente en `clave` → Ok, `api_key == None` y `missing_key_env == Some("llavero:x")`
- `secretos_falta_en_url_es_error`: `{llavero:x}` en la url sin el secreto → `Err(ConfigError::MissingSecret("x"))`
- `secretos_list_no_devuelve_valores`: set de `a`=`1` y `b`=`2` → list da `["a", "b"]`
- `secretos_delete_borra`: set y delete de `a` → get da `None`
- `secretos_referencias`: config con `{llavero:b}` en una clave y `{llavero:a}` en un entorno MCP → secret_refs da `["a", "b"]`
