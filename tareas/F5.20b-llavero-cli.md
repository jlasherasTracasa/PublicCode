## Objetivo

Dependencia nueva permitida en esta tarea: `keyring` (AGENTS.md §7). Servicio del llavero: `publiccode`.
1. `Cargo.toml` de pcode-cli: `keyring = { version = "3", default-features = false, features = ["sync-secret-service",
   "crypto-rust", "vendored", "windows-native", "apple-native"] }`.
2. `secrets.rs` con lo de *Firmas*. `KeyringStore` usa `keyring::Entry::new("publiccode", name)`: `get` →
   `get_password` (`Err(keyring::Error::NoEntry)` → `Ok(None)`), `set` → `set_password`, `delete` →
   `delete_credential` (`NoEntry` → `Ok(())`). El llavero no sabe listar: `list` devuelve
   `Err("el llavero del sistema no permite listar: usa pcode secreto listar")`. Los errores, con `to_string()`.
3. `list_lines(cfg, store)`: una línea por nombre de `secret_refs(cfg)`: `"✓ <nombre>"` si `store.get` da `Some`,
   `"✗ <nombre> (falta)"` si da `None`, `"⚠ <nombre>: <error>"` si falla. Sin referencias:
   `["La configuración no usa {llavero:…}"]`. Nunca escribe un valor.
4. `main.rs`: orden `Secreto(SecretCmd)` con `#[command(subcommand)]` y doc «Claves en el llavero del sistema».
   `SecretCmd`: `Poner { nombre }` (lee el valor de la primera línea de stdin, sin el salto de línea; vacío → error
   «valor vacío»), `Quitar { nombre }` y `Listar { #[arg(long = "config", default_value = "pcode.toml")] config }`
   (carga con `Config::load_layered` e imprime `list_lines`). Todas con `KeyringStore`; códigos 0 bien, 2 error.
5. `provider.rs`, al principio de `build_provider` (después de lo de `PCODE_MOCK_SCRIPT`): trabaja con
   `let mut cfg = cfg.clone();` y `cfg.resolve_secrets(&crate::secrets::KeyringStore)?;` solo si
   `!pcode_config::secrets::secret_refs(&cfg).is_empty()`. En `from_cfg`, si `missing_key_env` empieza por
   `llavero:`, el mensaje es «el proveedor <n> usa la clave {llavero:<x>}, pero no está en el llavero: guárdala con
   `pcode secreto poner <x>`».
6. Tests unitarios en `secrets.rs` con `MemoryStore` (el llavero real no existe en la CI).

## Tests (con estos nombres)

- `secreto_listar_marca_presentes_y_ausentes`: config con `{llavero:a}` y `{llavero:b}` y MemoryStore solo con `a` → `["✓ a", "✗ b (falta)"]`
