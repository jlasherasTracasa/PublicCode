## Objetivo

1. Crea `github.rs` con `PrRequest`, `pr_body`, `check_conclusion` y `publish_task_pr` (firmas abajo).
2. `pr_body(req)`: Markdown con, en este orden: `## Tarea` y el título; `## Informe` y `req.report` (o
   `_sin informe_` si está vacío); `## Aceptación` con la orden en una línea entre comillas invertidas, el
   resultado (`✓ pasa` / `✗ falla`) y las últimas 30 líneas de `req.accept_output` en un bloque de código; y la
   línea final `_PR abierto por PublicCode. No se fusiona automáticamente: revísalo y fusiónalo tú._`.
3. `check_conclusion(ok)`: `"success"` o `"failure"`.
4. `publish_task_pr(api, req)`: `api.create_pr(&req.head, &req.base, &format!("{}: {}", req.task_id,
   req.title), &pr_body(req))`; después `api.create_check_run("pcode acepta", &req.head_sha,
   check_conclusion(req.accept_ok), <primera línea no vacía de accept_output, o «sin salida»>)`; y, si
   `req.review` es `Some(texto)`, `api.comment(pr, &format!("## Revisión cruzada\n\n{texto}"))`. Devuelve el
   número del PR. Los errores de la API se devuelven como texto (`e.to_string()`). Nunca fusiona.
5. `lib.rs`: añade `pub mod github;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/github.rs
use pcode_backends::GitHubApi;

/// Datos del PR de una tarea.
#[derive(Debug, Clone, Default, PartialEq)]
pub struct PrRequest {
    pub task_id: String,
    pub title: String,
    /// Rama con el trabajo (`pcode/<id>`).
    pub head: String,
    /// Rama de destino.
    pub base: String,
    /// Commit de la rama.
    pub head_sha: String,
    /// Informe de la tarea (Markdown).
    pub report: String,
    pub accept_cmd: String,
    pub accept_ok: bool,
    pub accept_output: String,
    /// Texto de la revisión cruzada, si la hubo.
    pub review: Option<String>,
}

pub fn pr_body(req: &PrRequest) -> String;
pub fn check_conclusion(ok: bool) -> &'static str;
/// Abre el PR, publica el check y comenta la revisión. Devuelve el número del PR.
pub async fn publish_task_pr(api: &dyn GitHubApi, req: &PrRequest) -> Result<u64, String>;
```

```
                  accept_output: "test result: ok. 3 passed", review: Some("sin problemas") }
publish_task_pr(&FakeGitHub::default(), &req) → Ok(201)
  state.prs[0] = ("pcode/T1", "main", "T1: Saludo", cuerpo con "## Informe", "`cargo test`" y "✓ pasa")
  state.checks[0] = ("pcode acepta", "abc123", "success", "test result: ok. 3 passed")
  state.comments[0] = (201, "## Revisión cruzada\n\nsin problemas")
```

## Tests (con estos nombres)

- `pr_lleva_informe_y_acepta`: el cuerpo contiene el informe, la orden y `✓ pasa`
- `pr_recorta_la_salida_larga`: con 100 líneas de salida, el cuerpo contiene la última y no la primera
- `check_run_refleja_resultado`: con accept_ok false el check guardado tiene conclusión failure
- `comenta_la_revision_si_la_hay`: con review Some hay un comentario en el PR 201 y con None ninguno
- `error_de_la_api_se_devuelve`: con fail en la API falsa, publish_task_pr devuelve Err con ese texto
- `no_fusiona`: el cuerpo avisa de que no se fusiona automáticamente
