# F5.26c-github-rama-de-tarea — Flujos: integrar una tarea en su propia rama y subirla (sin forzar)

## Objetivo

1. En `integrate.rs`, añade las tres funciones de abajo. Todas usan la función privada `git(repo, args)`.
2. `task_branch(id)`: `pcode/<id>` cambiando por `-` cualquier carácter que no sea letra ASCII, cifra, `.`, `_`
   o `-`.
3. `integrate_on_branch(sb, repo, id, title)`: anota la rama actual (`git rev-parse --abbrev-ref HEAD`); crea
   y cambia a la rama de la tarea (`git switch -c <rama>`; si ya existe, devuelve
   `Err("la rama <rama> ya existe")` sin tocar nada); llama a `integrate(sb, repo, id, title)`; y vuelve
   SIEMPRE a la rama original (`git switch <original>`), también si `integrate` falla. Devuelve
   `(resultado de integrate, nombre de la rama)`.
4. `push_branch(repo, remote, branch)`: `git push <remote> <branch>` (sin `--force`). Devuelve el sha de la
   rama (`git rev-parse <branch>`). Si el push falla, `Err` con el mensaje de git.
5. Tests en el módulo `tests` de `integrate.rs`, con nombres que empiezan por `rama_de_tarea_`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/integrate.rs
/// Nombre de la rama de una tarea: `pcode/<id saneado>`.
pub fn task_branch(id: &str) -> String;
/// Como `integrate`, pero el commit queda en la rama de la tarea y el repo vuelve a la rama en que estaba.
pub fn integrate_on_branch(sb: Sandbox, repo: &Path, id: &str, title: &str) -> Result<(Integrated, String), String>;
/// Sube la rama al remoto (nunca forzado) y devuelve su commit.
pub fn push_branch(repo: &Path, remote: &str, branch: &str) -> Result<String, String>;
```

## Ejemplo (entrada y resultado esperado)

```
task_branch("F1.02-tipos") → "pcode/F1.02-tipos"      task_branch("a b/c") → "pcode/a-b-c"
Repo temporal en `main` con un remoto `origin` que es otro directorio creado con `git init --bare`:
  git branch pcode/T1 && push_branch(repo, "origin", "pcode/T1") → Ok(sha); `git -C <bare> rev-parse pcode/T1` da el mismo sha
  push_branch(repo, "origin", "no-existe") → Err(..)
integrate_on_branch (con sandbox que crea a.txt) → la rama `pcode/T1` tiene el commit `T1: título`, `main` no
  tiene a.txt en su último commit y `git rev-parse --abbrev-ref HEAD` sigue siendo `main`
```

## Tests (con estos nombres)

- `rama_de_tarea_nombre_saneado`: los dos casos de task_branch del ejemplo
- `rama_de_tarea_se_sube_al_remoto`: con un remoto bare local, push_branch devuelve el sha y el remoto tiene la rama (no necesita sandbox)
- `rama_de_tarea_inexistente_falla`: subir una rama que no existe devuelve Err
- `rama_de_tarea_integra_sin_mover_main`: el último caso del ejemplo (se salta sin namespaces de usuario, como los demás tests de integrate)
