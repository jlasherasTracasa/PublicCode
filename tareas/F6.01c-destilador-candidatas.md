# F6.01c-destilador-candidatas — Destilador: tareas candidatas (aceptadas tras 2 o más intentos) desde los eventos del flujo

## Contexto (lee esto y nada más)

## Objetivo

1. Crea `pairs.rs` con `Candidate` y `distill_candidates` (firmas abajo). Función pura sobre la lista
   de eventos (en el orden en que ocurrieron).
2. Una tarea es candidata si tiene un `AceptacionOk` con `intento >= 2`. Para cada candidata:
   - `task`: el id de la tarea;
   - `attempts`: el `intento` del `AceptacionOk` (si hay varios, el mayor);
   - `failures`: el `resumen` de cada `AceptacionFallo` de esa tarea, en orden de aparición;
   - `commit`: el `commit` de su evento `Integrada`, si existe.
3. Las tareas aceptadas al primer intento, las que nunca se aceptaron y los demás tipos de evento se
   ignoran. El resultado va ordenado por `task`.
4. `lib.rs`: `pub mod pairs;` y `pub use pairs::{Candidate, distill_candidates};`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/pairs.rs
/// Tarea de la que se puede aprender: falló al menos una vez y después se aceptó.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Candidate { pub task: String, pub attempts: u32, pub failures: Vec<String>, pub commit: Option<String> }

/// Candidatas a destilar una skill, ordenadas por id de tarea.
pub fn distill_candidates(events: &[crate::FlowEvent]) -> Vec<Candidate>;
```

## Ejemplo (entrada y resultado esperado)

```
eventos: AceptacionFallo{tarea:"B", intento:1, resumen:"test x falla"}, AceptacionOk{tarea:"A", intento:1},
         AceptacionOk{tarea:"B", intento:2}, Integrada{tarea:"B", commit:"abc123"}
salida:  [Candidate { task: "B", attempts: 2, failures: ["test x falla"], commit: Some("abc123") }]
```

## Tests (con estos nombres)

- `candidata_con_dos_intentos`: el ejemplo devuelve solo la tarea B con su fallo y su commit
- `aceptada_a_la_primera_no_es_candidata`: una tarea con `AceptacionOk` de intento 1 no aparece
- `nunca_aceptada_no_es_candidata`: una tarea con dos `AceptacionFallo` y ningún `AceptacionOk` no aparece
- `varios_fallos_en_orden`: una tarea con fallos en los intentos 1 y 2 y acierto en el 3 tiene `attempts` 3 y los dos resúmenes en orden
- `sin_integrar_commit_none`: una candidata sin evento `Integrada` tiene `commit` None
- `eventos_vacios`: una lista vacía devuelve un vector vacío
