# F6.02a-puerta-decision — Puerta de regresión: decidir con los resultados del banco antes y después (lógica pura)

## Objetivo

1. Crea `gate.rs` con `BenchRowLite`, `GateDecision`, `parse_rows` y `decide` (firmas abajo). Puro.
2. `parse_rows(jsonl)`: cada línea no vacía es un objeto JSON del resultado de `pcode bench`. Como el
   crate no tiene `serde_json`, extrae los campos con un lector mínimo propio (función privada
   `field(line, key) -> Option<&str>` que busca `"key":` y devuelve el valor hasta la siguiente `,` o
   `}`; a las cadenas se les quitan las comillas). Campos: `id` (cadena); `ok_first` (o, si no está,
   `ok_primera`) con valor `true`/`false`; `tokens` (o, si no está, la suma de `tokens_in` y
   `tokens_out`; 0 si no hay ninguno). Las líneas sin `id` se ignoran.
3. `decide(baseline, with_skill)` compara por `id` y comprueba en este orden:
   a) `baseline` vacío → `Reject("sin datos de referencia")`;
   b) ids de `baseline` que faltan en `with_skill` → `Reject("faltan resultados de: <ids con coma>")`;
   c) regresión: ids con `ok_first` true antes y false después → `Reject("regresión en: <ids>")`;
   d) mejora: si ningún id pasa de false a true → `Reject("sin mejora")`;
   e) coste: suma de `tokens` después > suma antes × 1,15 (solo si la suma de antes es > 0) →
      `Reject("coste: +<N> % de tokens")` con N redondeado al entero;
   f) si no, `Activate`.
   Los ids se listan en orden alfabético.
4. `lib.rs`: `pub mod gate;` y `pub use gate::{BenchRowLite, GateDecision, decide, parse_rows};`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-skills/src/gate.rs
/// Resultado de una tarea del banco, lo justo para decidir.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct BenchRowLite { pub id: String, pub ok_first: bool, pub tokens: u64 }

/// Decisión de la puerta.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum GateDecision { Activate, Reject(String) }

/// Lee las filas de un archivo de resultados del banco (JSONL).
pub fn parse_rows(jsonl: &str) -> Vec<BenchRowLite>;

/// Activar solo si no hay regresión, hay al menos una mejora y el coste no sube más de un 15 %.
pub fn decide(baseline: &[BenchRowLite], with_skill: &[BenchRowLite]) -> GateDecision;
```

## Ejemplo (entrada y resultado esperado)

```
parse_rows("{\"id\":\"t1\",\"ok_first\":true,\"tokens_in\":100,\"tokens_out\":20}\n")
  → [BenchRowLite { id: "t1", ok_first: true, tokens: 120 }]
antes:   t1 ok 100 · t2 falla 100        después: t1 ok 100 · t2 ok 110   → Activate
antes:   t1 ok 100 · t2 falla 100        después: t1 falla 100 · t2 ok 100 → Reject("regresión en: t1")
antes:   t1 ok 100 · t2 falla 100        después: t1 ok 150 · t2 ok 150   → Reject("coste: +50 % de tokens")
```

## Tests (con estos nombres)

- `decide_activa_si_mejora_sin_regresion`: el primer caso del ejemplo da `Activate`
- `decide_rechaza_regresion`: el segundo caso da `Reject` con el texto `regresión en: t1`
- `decide_rechaza_coste`: el tercer caso da `Reject("coste: +50 % de tokens")`
- `decide_rechaza_sin_mejora`: resultados idénticos antes y después dan `Reject("sin mejora")`
- `decide_rechaza_si_faltan_resultados`: si falta t2 después da `Reject("faltan resultados de: t2")`
- `decide_rechaza_sin_datos`: con `baseline` vacío da `Reject("sin datos de referencia")`
- `filas_con_tokens_separados`: la línea del ejemplo suma `tokens_in` y `tokens_out`
- `filas_con_nombres_en_espanol`: `{"id":"a","ok_primera":false,"tokens":7}` da ok_first false y tokens 7
- `filas_ignora_lineas_sin_id`: una línea vacía y otra sin `id` no producen filas
