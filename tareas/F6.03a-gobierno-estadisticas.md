## Objetivo

1. Crea `governance.rs` con `UseRecord`, `SkillStats`, `parse_uses`, `format_use`, `stats`, `recommend`
   y `retire_candidates` (firmas abajo). Todo puro; el día se pasa como número (días desde 1970-01-01).
2. Formato del registro de uso: una línea por uso con cuatro campos separados por tabulador:
   `skill`, `tarea`, `1` o `0` (la tarea se aceptó o no) y el día. `format_use` escribe esa línea (sin
   salto final); `parse_uses` lee todas e ignora las líneas vacías o mal formadas.
3. `stats(uses)`: una entrada por skill, ordenadas por nombre: `uses` (número de usos), `accepted`
   (usos con tarea aceptada) y `last_day` (el día mayor).
4. `recommend(stats, candidates)`: devuelve `candidates` ordenadas de mayor a menor utilidad observada,
   `(accepted + 1) / (uses + 2)` (una skill sin datos vale 0,5); a igual utilidad, por nombre.
5. `retire_candidates(stats, today, days)`: skills que cumplen alguna de estas dos condiciones:
   `today - last_day > days` (sin uso reciente) o `uses >= 5` y `accepted * 10 < uses * 3` (menos del
   30 % de aciertos). Ordenadas por nombre. Las skills sin ningún uso no están en `stats` y no se proponen.
6. `lib.rs`: `pub mod governance;` y
   `pub use governance::{SkillStats, UseRecord, format_use, parse_uses, recommend, retire_candidates, stats};`.
7. Tests en `governance.rs` con el prefijo `uso_`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-skills/src/governance.rs
/// Un uso de una skill en una tarea.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct UseRecord { pub skill: String, pub task: String, pub accepted: bool, pub day: u64 }

/// Resumen de uso de una skill.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct SkillStats { pub skill: String, pub uses: u32, pub accepted: u32, pub last_day: u64 }

pub fn format_use(u: &UseRecord) -> String;
pub fn parse_uses(text: &str) -> Vec<UseRecord>;
pub fn stats(uses: &[UseRecord]) -> Vec<SkillStats>;
/// `candidates` ordenadas por utilidad observada (mejor primero).
pub fn recommend(stats: &[SkillStats], candidates: &[String]) -> Vec<String>;
/// Skills que conviene proponer para retirada.
pub fn retire_candidates(stats: &[SkillStats], today: u64, days: u64) -> Vec<String>;
```

## Ejemplo (entrada y resultado esperado)

```
format_use(&UseRecord { skill: "banco".into(), task: "F3.13".into(), accepted: true, day: 20400 })
  → "banco\tF3.13\t1\t20400"
stats de [banco ok día 20400, banco fallo día 20410, adr ok día 20000]
  → [ {adr, uses 1, accepted 1, last_day 20000}, {banco, uses 2, accepted 1, last_day 20410} ]
recommend(esas stats, ["banco", "adr", "nueva"]) → ["adr", "banco", "nueva"]   (0,667 · 0,5 · 0,5; empate por nombre)
retire_candidates(esas stats, 20420, 90) → ["adr"]   (420 días sin uso)
```

## Tests (con estos nombres)

- `uso_formato_ida_y_vuelta`: `parse_uses(format_use(u))` devuelve el mismo registro
- `uso_ignora_lineas_rotas`: una línea vacía y otra con tres campos no producen registros
- `uso_estadisticas_por_skill`: el ejemplo de `stats` da esas dos entradas en ese orden
- `uso_recomienda_por_utilidad`: el ejemplo de `recommend` da `adr`, `banco`, `nueva`
- `uso_propone_retirada_por_inactividad`: el ejemplo de `retire_candidates` da solo `adr`
- `uso_propone_retirada_por_pocos_aciertos`: una skill con 10 usos y 2 aciertos usada hoy se propone; con 10 usos y 3 aciertos no
