## Objetivo

1. Crea `regress.rs` con `Regression`, `compare` e `issue_markdown` (firmas abajo). Lógica pura.
2. `compare(prev, now, threshold_pp)`: con `summarize` de cada lado calcula `first_drop_pp = prev.first_pct -
   now.first_pct` y `final_drop_pp = prev.final_pct - now.final_pct` (positivo = empeora). `worse` = ids, en
   orden, que tenían `ok_final` en `prev` y no lo tienen en `now` (solo ids presentes en los dos lados).
   `new_violations` = violaciones de `now` menos las de `prev` (0 si no aumentan). `regressed` = true si alguna
   de las dos caídas es MAYOR que `threshold_pp` o si `new_violations > 0`.
3. `issue_markdown(prev_name, now_name, prev, now, r)`: título `# Regresión en PublicBench`, una línea
   `Aceptación a la primera: −X.X pp · aceptación final: −Y.Y pp · violaciones nuevas: N` (con el signo real:
   una mejora sale como `+X.X pp`), la tabla de `report_markdown(&[(prev_name, prev), (now_name, now)])` y una
   sección `## Tareas que empeoraron` con una línea `- <id>` por cada una (o `ninguna`).
4. `lib.rs`: añade `pub mod regress;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/regress.rs
use crate::bench::BenchRow;

/// Diferencia entre dos ejecuciones del banco.
#[derive(Debug, Clone, PartialEq)]
pub struct Regression {
    pub first_drop_pp: f64,
    pub final_drop_pp: f64,
    pub worse: Vec<String>,
    pub new_violations: u32,
    pub regressed: bool,
}

/// Compara la ejecución anterior con la actual.
pub fn compare(prev: &[BenchRow], now: &[BenchRow], threshold_pp: f64) -> Regression;
/// Texto del aviso (cuerpo de un issue).
pub fn issue_markdown(prev_name: &str, now_name: &str, prev: &[BenchRow], now: &[BenchRow], r: &Regression) -> String;
```

## Ejemplo (entrada y resultado esperado)

```
prev: 10 filas, todas ok_first y ok_final.  now: las mismas, pero T3 falla (ok_first y ok_final false).
compare(prev, now, 3.0) → Regression { first_drop_pp: 10.0, final_drop_pp: 10.0, worse: ["T3"], new_violations: 0, regressed: true }
compare(prev, prev, 3.0) → regressed false, worse []
20 filas con una sola caída (5 pp) y umbral 5.0 → regressed false (no es MAYOR que el umbral)
issue_markdown(..) contiene "# Regresión en PublicBench", "−10.0 pp" y "- T3"
```

## Tests (con estos nombres)

- `detecta_caida_mayor_que_el_umbral`: el primer caso del ejemplo
- `sin_cambios_no_hay_regresion`: comparar una ejecución consigo misma da regressed false
- `caida_igual_al_umbral_no_avisa`: una caída de exactamente el umbral no es regresión
- `violaciones_nuevas_son_regresion`: mismas aceptaciones pero una violación más da regressed true
- `ids_nuevos_no_cuentan_como_peores`: una tarea que solo está en now y falla no aparece en worse
- `aviso_lista_las_que_empeoraron`: el texto contiene el título, la caída con signo y la línea de T3
