## Objetivo

1. Crea `imagen.js` con las tres funciones de las firmas. `isImagePath`: la ruta acaba en `.png`, `.jpg`,
   `.jpeg`, `.gif`, `.webp` o `.svg` (sin distinguir mayúsculas). `dataUrl(mime, base64)`: devuelve
   `"data:" + mime + ";base64," + base64` solo si `mime` es uno de `image/png`, `image/jpeg`, `image/gif`,
   `image/webp`, `image/svg+xml` y `base64` casa con `/^[A-Za-z0-9+/]*={0,2}$/`; si no, `null`.
   `humanSize(bytes)`: `"512 B"`, `"1.5 KB"`, `"2.0 MB"` (divisor 1024, un decimal a partir de KB).
2. Crea `imagen.test.js` con los tests de la lista.
3. `web_assets.rs`: añade `("imagen.js", include_str!("../web/studio/imagen.js")),` a `ASSETS`. `index.html`,
   bloque `<script type="module">` final: `import * as imagen from "/studio/imagen.js"; Studio.imagen = imagen;`.
4. `index.html`, función `abre`: después de leer con `fs.read`, si `f.binary` y
   `Studio.imagen.isImagePath(path)`, pide `rpc("fs.readImage", { path })` dentro de un `try` y guarda el
   resultado en `t.imagen` antes de activar la pestaña. Si falla, sigue como hasta ahora. Un `.svg` es
   texto: se sigue abriendo en el editor (su imagen se ve con la vista previa, paso 6).
5. Debajo de `muestra` añade `pintaBinario(t)`: vacía `#binario`; si `t.imagen` y
   `url = Studio.imagen.dataUrl(t.imagen.mime, t.imagen.base64)` no es `null`, añade un `img`
   (`img.src = url`, `img.alt = t.path`) y `el("div", "meta", t.imagen.mime + " · " + Studio.imagen.humanSize(t.imagen.size))`;
   si no, el texto de siempre: `Archivo binario: no se puede editar aquí.` Llámala desde `muestra` cuando
   `t.binary`. CSS: `.binario img { max-width: 90%; max-height: 80%; object-fit: contain; }` y
   `.binario { align-content: center; justify-items: center; gap: 8px; }`.
6. `pintaPrevia`: después de pintar, para cada `span.img-md` cuyo `dataset.src` sea relativo (sin `:` ni
   `//`) y pase `isImagePath`, resuelve la ruta respecto a la carpeta del Markdown (`dir(t.path)`), pide
   `fs.readImage` y sustituye el `span` por un `img` con ese `data:` URL y `alt`; si falla, deja el `span`.
   En `abrePrevia`, acepta también un archivo `.svg`: su pestaña `previa` la pinta `pintaPrevia` pidiendo
   `fs.readImage` del propio archivo y mostrando un único `img`.

## Ejemplo (entrada y resultado esperado)

```
isImagePath("docs/img/Logo.PNG") -> true        isImagePath("src/main.rs") -> false
dataUrl("image/png", "Zm9v")     -> "data:image/png;base64,Zm9v"
dataUrl("text/html", "Zm9v")     -> null        dataUrl("image/png", "<svg>") -> null
humanSize(512) -> "512 B"        humanSize(1536) -> "1.5 KB"        humanSize(2097152) -> "2.0 MB"
```

## Tests (con estos nombres)

- `rutas_de_imagen`: `Logo.PNG`, `a.jpeg`, `a.svg` y `a.webp` son imágenes; `main.rs` y `png` (sin punto) no
- `data_url_valida`: el primer caso de `dataUrl` del ejemplo
- `svg_se_muestra_como_imagen_no_como_html`: `dataUrl("image/svg+xml", "PHN2Zy8+")` da un `data:image/svg+xml;base64,…` y `dataUrl("text/html", …)` da `null`
- `base64_invalido_se_rechaza`: `dataUrl("image/png", "<svg>")` y `dataUrl("image/png", "a b")` dan `null`
- `tamaño_legible`: los tres casos de `humanSize` del ejemplo

## No hagas

- No insertes el SVG en la página (ni `innerHTML` ni `<object>`): siempre `<img>` con `data:` URL, que no ejecuta scripts
- No cargues imágenes de `http://` o `https://` en la vista previa
