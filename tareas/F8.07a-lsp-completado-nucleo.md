## Objetivo

1. Crea `completion.rs` con las firmas de abajo y sus tests en `#[cfg(test)] mod tests`.
2. `parse_completion(v)`: `v` es un array de items, o un objeto `{"items": [...]}`, o `null` (→ vacío).
   Por cada item JSON:
   - `label` = `item["label"]` (si falta, se ignora el item); `detail` = `item["detail"]` o `""`;
   - `kind` = `kind_name(item["kind"])` (si falta, `"text"`); `sort_text` = `item["sortText"]` o el `label`;
   - `insert_text` = `item["textEdit"]["newText"]`, si no `item["insertText"]`, si no el `label`. Si
     `item["insertTextFormat"] == 2`, pásalo por `strip_snippet`;
   - si hay `textEdit` con `range` (o, si no, `replace`) y su `start.line == end.line`:
     `replace_start = Some(start.character)` y `replace_end = Some(end.character)`; si no, ambos `None`.
   Ordena por `sort_text` (orden estable) y deja como mucho `MAX_ITEMS`.
3. `kind_name`: 2 `method`, 3 `function`, 4 `constructor`, 5 `field`, 6 `variable`, 7 `class`, 8 `interface`,
   9 `module`, 10 `property`, 13 `enum`, 14 `keyword`, 15 `snippet`, 21 `constant`, 22 `struct`; cualquier otro `text`.
4. `strip_snippet` (sin `regex`, recorriendo caracteres): `\$` → `$`; `$` seguido de dígitos → nada;
   `${N:texto}` → `texto`; `${N}` → nada; el resto se copia igual.
5. `lib.rs`: añade `pub mod completion;` debajo del comentario `//!` inicial.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-lsp/src/completion.rs
use serde::Serialize;
use serde_json::Value;

/// Máximo de propuestas que se devuelven al editor.
pub const MAX_ITEMS: usize = 200;

/// Una propuesta de autocompletado lista para el editor.
#[derive(Debug, Clone, PartialEq, Eq, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct CompletionItem {
    pub label: String, pub kind: String, pub detail: String, pub insert_text: String,
    /// Columnas UTF-16 de la línea del cursor que se sustituyen (None = solo la palabra ya escrita).
    pub replace_start: Option<u32>, pub replace_end: Option<u32>, pub sort_text: String,
}
/// Nombre del tipo de propuesta a partir del número del LSP.
pub fn kind_name(kind: u64) -> &'static str;
/// Quita los marcadores de snippet (`$0`, `${1:nombre}`).
pub fn strip_snippet(s: &str) -> String;
/// Lee la respuesta del servidor (array, `{items}` o `null`).
pub fn parse_completion(v: &Value) -> Vec<CompletionItem>;
```

## Ejemplo (entrada y resultado esperado)

```
strip_snippet("doble(${1:x})$0") == "doble(x)"
parse_completion(&json!({"items": [{"label": "doble", "kind": 3, "detail": "fn(u32) -> u32", "insertText": "doble($1)", "insertTextFormat": 2}]}))
  == [CompletionItem { label: "doble", kind: "function", detail: "fn(u32) -> u32", insert_text: "doble()", replace_start: None, replace_end: None, sort_text: "doble" }]
```

## Tests (con estos nombres)

- `lee_un_array_y_un_objeto_con_items`: las dos formas de respuesta dan los mismos items
- `respeta_text_edit`: un item con `textEdit.range` de columnas 4 a 7 da `replace_start` 4, `replace_end` 7 y el `newText` como `insert_text`
- `quita_marcadores_de_snippet`: `doble(${1:x})$0` queda `doble(x)` y `\$a` queda `$a`
- `ordena_por_sort_text_y_limita`: 300 items dan 200 y el de `sortText` menor queda primero
- `null_da_vacio`: `Value::Null` da vector vacío
