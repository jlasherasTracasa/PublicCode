# F8.08c-lsp-aplicar-ediciones — Demonio: aplicar ediciones del LSP a archivos del proyecto, con simulacro

## Contexto (lee esto y nada más)

- crates/pcode-server/src/workspace.rs (funciones `read` y `write`: leen y escriben dentro de la raíz y rechazan rutas de fuera; tipo `WsResult`)
- crates/pcode-lsp/src/workspace_edit.rs (`FileEdits`) y crates/pcode-lsp/src/edits.rs (`apply_edits`)

## Objetivo

1. Crea `lsp_apply.rs` con las firmas de abajo y tests (con `tempfile::tempdir()`) en el mismo archivo.
2. `apply_file_edits(root, files, dry_run)`: en DOS pasadas, para no dejar el proyecto a medias:
   a) por cada `FileEdits`: `crate::workspace::read(root, &f.path)?` (si `binary` es `true`, error
      `"<ruta>: archivo binario"`), calcula el texto nuevo con `pcode_lsp::edits::apply_edits(&contenido.content, &f.edits)`
      (su error se devuelve precedido de `"<ruta>: "`) y guarda `(ruta, texto nuevo)`;
   b) solo si la pasada a) terminó sin errores y `dry_run` es `false`: `crate::workspace::write(root, ruta, texto)?` de cada uno.
   Devuelve un `EditSummary` por archivo, en el mismo orden, con `edits = f.edits.len()`.
3. `lib.rs` de `pcode-server`: añade `pub mod lsp_apply;` debajo de `pub mod assist;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-server/src/lsp_apply.rs
use crate::workspace::WsResult;
use pcode_lsp::workspace_edit::FileEdits;
use std::path::Path;

/// Resumen de lo que cambia en un archivo.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
pub struct EditSummary { pub path: String, pub edits: usize }

/// Aplica (o simula, con `dry_run`) las ediciones. O se escriben todos los archivos o ninguno.
pub fn apply_file_edits(root: &Path, files: &[FileEdits], dry_run: bool) -> WsResult<Vec<EditSummary>>;

// Ya existen: crate::workspace::read(root: &Path, rel: &str) -> WsResult<FileContent>  (campos `content: String`, `binary: bool`)
//             crate::workspace::write(root: &Path, rel: &str, content: &str) -> WsResult<()>
```

## Ejemplo (entrada y resultado esperado)

```
a.rs = "fn doble() {}\n", b.rs = "doble();\n"; ediciones que cambian `doble` por `triple` en los dos
apply_file_edits(root, &files, true)  → Ok([{path:"a.rs",edits:1},{path:"b.rs",edits:1}]) y los archivos NO cambian
apply_file_edits(root, &files, false) → mismo resumen y a.rs = "fn triple() {}\n", b.rs = "triple();\n"
```

## Tests (con estos nombres)

- `simulacro_no_escribe`: con `dry_run = true` devuelve el resumen y los archivos quedan igual
- `aplica_en_varios_archivos`: con `dry_run = false` los dos archivos quedan con el nombre nuevo
- `ruta_fuera_de_la_raiz_se_rechaza`: un `FileEdits` con `path` `../x.rs` da `Err` y no se escribe ningún archivo
- `si_un_archivo_falla_no_se_escribe_ninguno`: con ediciones solapadas en el segundo archivo, el primero queda sin tocar

## No hagas

- No uses `std::fs::write` directamente: siempre `crate::workspace::write` (confina a la raíz)
- No añadas dependencias
