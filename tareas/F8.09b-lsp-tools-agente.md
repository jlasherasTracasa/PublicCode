## Objetivo

1. En `lsp_tools.rs` añade las tres tools y las dos funciones de las firmas. Las tres guardan
   `Arc<pcode_lsp::LspManager>` y un `DiagStore`, y declaran `&[Effect::Read]`.
2. Pasos comunes de `call`: lee `path` (`falta `path``); `full = resolve_in_root(&ctx.root, path)?`;
   `rel = pcode_lsp::rel_path(&ctx.root, &full)`; lee el archivo (`no se pudo leer {path}: {e}`).
3. `diagnosticos` (parámetros `path` y `espera_ms` entero opcional; `required: ["path"]`). Descripción:
   «Errores y avisos del servidor de lenguaje para un archivo, sin compilar el proyecto.»
   `client = manager.client_for(&rel).await` (si falla: `ToolOutput::error(format!("{e}; mientras tanto compila con `bash`"))`);
   `store.clear(&rel)`; `client.sync(&rel, &texto).await`; `client.saved(&rel).await`; después espera a
   que `store.take(&rel)` devuelva algo, mirando cada 50 ms, como mucho `espera_ms` (por defecto 5000,
   máximo 30000). Si llega: `ToolOutput::ok(render_diagnostics(&rel, &d))`. Si no:
   `ToolOutput::ok(format!("{rel}: el servidor aún no ha publicado diagnósticos; repite la llamada en unos segundos"))`.
4. `definicion` y `referencias` (parámetros `path`, `line` entero desde 1 y `symbol`; los tres
   obligatorios). Descripciones: «Dónde se define el símbolo `symbol` que aparece en la línea `line` de
   `path` (exacto, mejor que buscar texto).» y «Todos los usos del símbolo `symbol` que aparece en la
   línea `line` de `path`.» Pasos: `find_position(&texto, line, symbol)` (su error es el de la tool);
   `client_for` como arriba; `client.sync(&rel, &texto).await`; después `client.definition(&rel, l, c)`
   o `client.references(&rel, l, c)`; `Ok(locs)` → `ToolOutput::ok(render_locations(&ctx.root, &locs))`;
   `Err(e)` → `ToolOutput::error(e)`.
5. `lsp_tools(manager, store)` devuelve las tres en este orden: diagnosticos, definicion, referencias.
   `lsp_tools_for(root, overrides)`: `let store = DiagStore::new();`
   `let m = pcode_lsp::LspManager::new(root, overrides, store.sink());` y `lsp_tools(Arc::new(m), store)`.
6. Crea `tests/lsp_tools.rs` con un servidor falso (ejemplo) y los tests de la lista. La raíz del test
   es `tempdir().path().canonicalize()`.

## Ejemplo (entrada y resultado esperado)

```
// tests/lsp_tools.rs: gestor con un servidor falso (no hace falta `initialize`).
async fn write_msg(w: &mut (impl tokio::io::AsyncWrite + Unpin), v: &serde_json::Value) {
    use tokio::io::AsyncWriteExt;
    let b = v.to_string();
    w.write_all(format!("Content-Length: {}\r\n\r\n{b}", b.len()).as_bytes()).await.unwrap();
    w.flush().await.unwrap();
}
fn manager(root: &std::path::Path, store: &DiagStore) -> Arc<pcode_lsp::LspManager> {
    Arc::new(pcode_lsp::LspManager::new(root, HashMap::new(), store.sink()).with_spawner(|root, _cmd, sink| {
        Box::pin(async move {
            let (a, b) = tokio::io::duplex(1 << 16);
            let (cr, cw) = tokio::io::split(a);
            let (sr, mut sw) = tokio::io::split(b);
            let uri = pcode_lsp::path_to_uri(&root);
            tokio::spawn(async move {
                let mut r = tokio::io::BufReader::new(sr);
                while let Some(v) = pcode_lsp::read_msg(&mut r).await {
                    let loc = json!({"uri": format!("{uri}/src/lib.rs"), "range": {"start": {"line": 0, "character": 7}, "end": {"line": 0, "character": 12}}});
                    let out = match v["method"].as_str().unwrap_or("") {
                        "textDocument/didOpen" | "textDocument/didChange" => json!({"jsonrpc": "2.0", "method": "textDocument/publishDiagnostics",
                            "params": {"uri": v["params"]["textDocument"]["uri"], "diagnostics": [{"range": {"start": {"line": 1, "character": 4}, "end": {"line": 1, "character": 9}}, "severity": 1, "message": "tipo incorrecto"}]}}),
                        "textDocument/definition" => json!({"jsonrpc": "2.0", "id": v["id"], "result": [loc]}),
                        "textDocument/references" => json!({"jsonrpc": "2.0", "id": v["id"], "result": [loc.clone(), loc]}),
                        _ if v.get("id").is_some() => json!({"jsonrpc": "2.0", "id": v["id"], "result": null}),
                        _ => continue,
                    };
                    write_msg(&mut sw, &out).await;
                }
            });
            Ok(pcode_lsp::LspClient::from_streams(&root, cr, cw, sink))
        })
    }))
}
// Proyecto: src/lib.rs = "pub fn doble() {}\n"; src/main.rs = "fn main() {\n    doble();\n}\n"
// definicion {"path":"src/main.rs","line":2,"symbol":"doble"} -> "src/lib.rs:1:8  pub fn doble() {}"
// diagnosticos {"path":"src/main.rs"} -> "src/main.rs: 1 errores, 0 avisos\nsrc/main.rs:2:5 error tipo incorrecto"
```

## Tests (con estos nombres)

- `diagnosticos_de_un_archivo`: con el servidor falso, diagnosticos de src/main.rs devuelve el texto del ejemplo
- `definicion_en_otro_archivo`: definicion de doble en la línea 2 de src/main.rs devuelve `src/lib.rs:1:8  pub fn doble() {}`
- `referencias_lista_los_usos`: referencias devuelve dos líneas que empiezan por `src/lib.rs:1:8`
- `simbolo_que_no_esta_en_la_linea_es_error`: definicion con symbol `triple` devuelve is_error y el texto de find_position
- `sin_servidor_explica_que_instalar`: con un spawner que devuelve Err("no se pudo lanzar rust-analyzer"), diagnosticos devuelve is_error y el texto contiene `instala rust-analyzer`
- `archivo_sin_servidor_de_lenguaje`: diagnosticos de `notas.txt` devuelve is_error con `sin servidor de lenguaje`

## No hagas

- No cambies nada en `crates/pcode-lsp` (su `initialize` es privado: el servidor falso no lo necesita)
- No esperes sin tiempo máximo: el sondeo de diagnósticos acaba como mucho en `espera_ms`
- No registres las tools en `native_registry`: necesitan un gestor por proyecto (F8.09c)
