## Contexto (lee esto y nada más)

## Objetivo

1. `chat.rs`, función `prepare`, justo después de `let mut tools = pcode_tools::native_registry();`:
   a) `let lsp_overrides: std::collections::HashMap<String, Vec<String>> = cfg.lsp.iter().filter(|(_, l)| !l.command.is_empty()).map(|(k, l)| (k.clone(), l.command.clone())).collect();`
   b) `for t in pcode_tools::lsp_tools::lsp_tools_for(&root, lsp_overrides) { tools.register(t).expect("nombre único"); }`
   Los servidores de lenguaje no se lanzan aquí: arrancan la primera vez que el agente usa una de las
   tools con un archivo de ese lenguaje. `prepare` la usan el chat y la TUI.
2. `tests/chat.rs`: añade el test `lsp_tools_en_chat`: en un directorio temporal con `notas.txt`
   (contenido `hola` y salto de línea), el guion del proveedor falso llama a `definicion` con
   `{"path": "notas.txt", "line": 1, "symbol": "hola"}` y después responde `no hay servidor`; la
   entrada es `define hola\n/salir\n`. Comprueba que la salida contiene `⏺ definicion` y
   `sin servidor de lenguaje` (un `.txt` no tiene servidor; si la tool no estuviera registrada saldría
   `tool desconocida`).

Sin firmas: no añade API: registro de tres tools ya hechas y un test de integración

## Ejemplo (entrada y resultado esperado)

```
pcode(
    d.path(),
    json!([
        resp("", json!([{"id":"1","name":"definicion","arguments":{"path":"notas.txt","line":1,"symbol":"hola"}}])),
        resp("no hay servidor", json!([])),
    ]),
)
.arg("chat")
.write_stdin("define hola\n/salir\n")
.assert()
.success()
.stdout(predicate::str::contains("⏺ definicion"))
.stdout(predicate::str::contains("sin servidor de lenguaje"));
```

## Tests (con estos nombres)

- `lsp_tools_en_chat`: el agente del chat llama a definicion sobre un .txt y la salida muestra `sin servidor de lenguaje` (la tool está registrada)
