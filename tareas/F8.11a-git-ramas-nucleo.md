## Objetivo

1. Crea `branches.rs` con las firmas de abajo. Los tests van en `#[cfg(test)] mod puro` dentro del mismo archivo
   (el nombre del módulo de tests es `puro` para que `acepta` los filtre).
2. `parse_branches(raw)`: `raw` es la salida de `git branch --format=<BRANCH_FORMAT>`: una línea por rama con tres campos
   separados por tabulador: nombre, `*` si es la actual (vacío o espacio si no) y la rama remota que sigue (puede estar
   vacía → `None`). Las líneas vacías y las que empiezan por `(` (HEAD suelto) se ignoran.
3. `valid_branch_name(name)`: `Ok(())` si el nombre tiene entre 1 y 100 caracteres, solo usa `A-Z a-z 0-9 . _ / -`, no
   empieza por `-` ni por `/`, no termina en `/` ni en `.lock` y no contiene `..`. Si no, `Err("nombre de rama no válido: <name>")`.
4. `push_args(branch, upstream)`: con `upstream` `Some(_)` → `["push"]`; con `None` → `["push", "-u", "origin", branch]`.
   Nunca incluye `--force` ni `-f`.
5. `lib.rs`: añade `pub mod branches;` debajo de `pub mod assist;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-server/src/branches.rs
/// Formato de `git branch` que entiende `parse_branches`.
pub const BRANCH_FORMAT: &str = "%(refname:short)%09%(HEAD)%09%(upstream:short)";

/// Una rama local.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
pub struct Branch { pub name: String, pub current: bool, pub upstream: Option<String> }

pub fn parse_branches(raw: &str) -> Vec<Branch>;
pub fn valid_branch_name(name: &str) -> Result<(), String>;
/// Argumentos de `git push` (sin forzar nunca).
pub fn push_args(branch: &str, upstream: Option<&str>) -> Vec<String>;
```

## Ejemplo (entrada y resultado esperado)

```
parse_branches("main\t*\torigin/main\nfeature/x\t \t\n")
  == [Branch { name: "main", current: true, upstream: Some("origin/main") }, Branch { name: "feature/x", current: false, upstream: None }]
valid_branch_name("feature/x-1") == Ok(());   valid_branch_name("-f").is_err();   valid_branch_name("a..b").is_err()
push_args("feature/x", None) == ["push", "-u", "origin", "feature/x"]
```

## Tests (con estos nombres)

- `parsea_ramas_con_actual_y_remota`: la entrada del ejemplo da dos ramas, la primera actual y con `origin/main`
- `ignora_head_suelto`: una línea `(HEAD detached at a1b2c3d)` no aparece en el resultado
- `nombre_valido_y_no_valido`: `feature/x-1` vale; cadena vacía, `-f`, `a..b`, `x.lock`, `a b` y `rama/` no
- `push_sin_remota_configura_origin`: sin upstream los argumentos son `push -u origin <rama>` y con upstream solo `push`
