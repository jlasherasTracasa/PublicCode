## Objetivo

1. `crates/pcode-protocol/src/lib.rs`, en `pub mod methods`, debajo de `GIT_COMMIT`, añade con su comentario `///`:
   `GIT_CONFLICT = "git.conflict"` (`{path}` → `{segments, conflicts}`) y
   `GIT_RESOLVE_CONFLICT = "git.resolveConflict"` (`{path, choices}` → `true`; escribe el archivo resuelto y lo prepara).
2. `server.rs`, función `rpc`, `match req.method.as_str()`, después del brazo `methods::GIT_COMMIT`:
   - `GIT_CONFLICT`: dentro de `blocking`: `let f = crate::workspace::read(&root, &rel)?;`
     `let segs = crate::conflicts::parse_conflicts(&f.content);` y devuelve
     `Ok(serde_json::json!({"conflicts": crate::conflicts::count_conflicts(&segs), "segments": segs}))`.
   - `GIT_RESOLVE_CONFLICT`: `choices: Vec<String>` leído de `p.get("choices")` como se leen `paths` en el brazo de `GIT_STAGE`.
     Dentro de `blocking`: `read` → `crate::conflicts::resolve(&f.content, &choices)?` → `crate::workspace::write(&root, &rel, &texto)?`
     → `crate::workspace::git_stage(&root, &[rel.clone()], true)`. Después emite `Event::FilesChanged {}` y responde
     `ws_reply(id, r.map(|_| true))`.
3. Test en `mod tests` de `server.rs`: repo temporal con `std::process::Command::new("git")` (`init -q`, `config user.email t@t`,
   `config user.name t`, un commit inicial); escribe a mano `a.txt` con el texto del ejemplo (no hace falta provocar un merge
   real) y comprueba las aserciones de la lista.

## Ejemplo (entrada y resultado esperado)

```
a.txt = "a\n<<<<<<< HEAD\nuno\n=======\ndos\n>>>>>>> rama\nz\n"
git.conflict {path: "a.txt"} → {"conflicts": 1, "segments": [{"kind": "text", "text": "a\n"}, {"kind": "conflict", "ours": "uno\n", "theirs": "dos\n", "base": null, "oursLabel": "HEAD", "theirsLabel": "rama"}, {"kind": "text", "text": "z\n"}]}
git.resolveConflict {path: "a.txt", choices: ["theirs"]} → true  y a.txt = "a\ndos\nz\n"
```
