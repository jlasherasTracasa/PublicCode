## Objetivo

1. Crea `test_results.rs` con las firmas de abajo y tests en el mismo archivo. Solo se parsea texto.
2. `parse_cargo_results(out)`: líneas `test <id> ... ok` → `ok: true`; `test <id> ... FAILED` → `ok: false`. Las que terminan
   en `... ignored` y el resto de líneas se ignoran. El `id` es lo que va entre `test ` y ` ... `.
3. `parse_pytest_results(out)`: salida de `pytest -v`. Líneas con la forma `<id> PASSED …`, `<id> FAILED …` o `<id> ERROR …`
   (el id es la primera palabra y contiene `::`; después puede venir `[ 50%]`). `PASSED` → `true`; `FAILED` y `ERROR` → `false`;
   `SKIPPED` y `XFAIL` se ignoran.
4. `parse_go_results(out)`: salida de `go test -v`. Líneas (quitando espacios iniciales) `--- PASS: <id> (0.00s)` → `true`;
   `--- FAIL: <id> (…)` → `false`; `--- SKIP:` se ignora.
5. `parse_tap_results(out)`: para `npm test` con `node --test` u otro que escriba TAP. Líneas (quitando espacios iniciales)
   `ok <n> - <nombre>` → `true`; `not ok <n> - <nombre>` → `false`; también `✔ <nombre>` → `true` y `✖ <nombre>` → `false`
   (si el nombre termina en ` (<número>ms)`, se quita ese final). Las líneas con `# SKIP` se ignoran.
6. `parse_results(runner, out)`: reparte entre `"cargo"`, `"pytest"`, `"go"` y `"npm"` (TAP); otro →
   `Err(format!("ejecutor de tests desconocido: {runner}"))`. Si un id sale dos veces, vale el último.
7. `lib.rs`: añade `pub mod test_results;` debajo de `pub mod settings;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-server/src/test_results.rs
/// Resultado de un test.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
pub struct TestResult { pub id: String, pub ok: bool }

pub fn parse_cargo_results(out: &str) -> Vec<TestResult>;
pub fn parse_pytest_results(out: &str) -> Vec<TestResult>;
pub fn parse_go_results(out: &str) -> Vec<TestResult>;
pub fn parse_tap_results(out: &str) -> Vec<TestResult>;
/// Reparte según el ejecutor (`cargo`, `pytest`, `go`, `npm`).
pub fn parse_results(runner: &str, out: &str) -> Result<Vec<TestResult>, String>;
```

## Ejemplo (entrada y resultado esperado)

```
parse_cargo_results("running 2 tests\ntest a::uno ... ok\ntest a::dos ... FAILED\ntest a::tres ... ignored\n")
  == [TestResult { id: "a::uno", ok: true }, TestResult { id: "a::dos", ok: false }]
parse_pytest_results("tests/test_a.py::test_x PASSED   [ 50%]\ntests/test_a.py::test_y FAILED   [100%]\n")
  == [TestResult { id: "tests/test_a.py::test_x", ok: true }, TestResult { id: "tests/test_a.py::test_y", ok: false }]
parse_go_results("=== RUN   TestSuma\n--- PASS: TestSuma (0.00s)\n    --- FAIL: TestSuma/negativos (0.00s)\n")
  == [TestResult { id: "TestSuma", ok: true }, TestResult { id: "TestSuma/negativos", ok: false }]
parse_tap_results("ok 1 - suma\nnot ok 2 - resta\n✔ divide (1.2ms)\n")
  == [TestResult { id: "suma", ok: true }, TestResult { id: "resta", ok: false }, TestResult { id: "divide", ok: true }]
```

## Tests (con estos nombres)

- `resultado_marca_fallidos`: el ejemplo de cargo da `a::uno` bien, `a::dos` mal y no incluye el ignorado
- `resultados_de_pytest`: el ejemplo de pytest da un test bien y otro mal; una línea `SKIPPED` no aparece
- `resultados_de_go_con_subtests`: el ejemplo de go da el test y su subtest
- `resultados_tap_y_simbolos`: el ejemplo TAP da tres resultados y quita `(1.2ms)` del nombre
- `id_repetido_vale_el_ultimo`: `test x ... FAILED` seguido de `test x ... ok` da un solo resultado con `ok` verdadero
- `ejecutor_desconocido_en_resultados`: `parse_results("make", "")` da `Err` que contiene `desconocido`
