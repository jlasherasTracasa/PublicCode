## Objetivo

Las órdenes las ejecuta el cliente con el método `terminal.run` que ya existe (con su política y su tiempo máximo); el demonio
solo dice qué orden lanzar y entiende la salida.
1. `crates/pcode-protocol/src/lib.rs`, en `pub mod methods`, debajo de `WORKSPACE_TASKS`, añade con su comentario `///`:
   `TESTS_RUNNERS = "tests.runners"` (`{}` → `{id, label, list?, runAll}[]`),
   `TESTS_COMMAND = "tests.command"` (`{runner, test?}` → orden de shell) y
   `TESTS_PARSE = "tests.parse"` (`{runner, mode: "list"|"run", output}` → tests o resultados).
2. `server.rs`, función `rpc`, `match req.method.as_str()`, después del brazo `methods::WORKSPACE_TASKS`:
   - `TESTS_RUNNERS`: `ws_reply(id, blocking(move || Ok(crate::test_runners::detect_runners(&root))).await)`.
   - `TESTS_COMMAND`: `test = p.get("test").and_then(|v| v.as_str())`;
     `ws_reply(id, crate::test_runners::run_command(&str_param(&p, "runner"), test))`.
   - `TESTS_PARSE`: según `str_param(&p, "mode")`: `"list"` → `crate::test_discovery::parse_list(&runner, &output)` convertido con
     `serde_json::to_value`; `"run"` → `crate::test_results::parse_results(&runner, &output)` igual; otro →
     `rpc_err(id, -32602, "mode debe ser list o run")`.
3. Añade en `mod tests` de `server.rs` el test `rpc_pruebas_ejecutores_orden_y_resultados` con las aserciones de la lista
   (raíz: `tempfile::tempdir()` con un `Cargo.toml` vacío).

## Ejemplo (entrada y resultado esperado)

```

```
