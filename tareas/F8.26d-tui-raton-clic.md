## Objetivo

1. `app.rs`: añade a `App` `pub expanded: std::collections::BTreeSet<usize>` (doc: «Índices de las tools con
   la salida desplegada a mano»), vacío en `App::new`; y a `Event` las variantes `Click { col: u16, row: u16 }`
   y `ToggleEntry(usize)`. En `update`: `ToggleEntry(i)`: si `self.entries.get(i)` es un `Entry::Tool`,
   quita `i` de `expanded` si estaba o lo añade si no; `Click { .. }` no hace nada (lo traduce `run.rs`). Las
   dos devuelven `vec![]`. En el brazo `"nuevo" | "new"` de `submit`, vacía `expanded`.
2. `render.rs`: convierte el cuerpo de `transcript_lines` en una función privada
   `fn transcript_owned(app, width) -> Vec<(usize, Line<'static>)>` que devuelve cada línea con el índice de
   su entrada (la línea en blanco tras cada entrada también lleva ese índice); `transcript_lines` pasa a ser
   `transcript_owned(app, width).into_iter().map(|x| x.1).collect()`. En el cálculo de `max` de una tool usa
   `app.expand_tools || app.expanded.contains(&idx) || *state == ToolState::Err`.
3. `render.rs`: saca a una función pública `body_area(app, area) -> Rect` el cálculo de la zona de la
   transcripción que hoy hace `render` (el `Layout::vertical` con `input_h`, y el recorte de la barra lateral
   si está visible) y úsala en `render`.
4. `render.rs`: añade `entry_at(app, area, col, row) -> Option<usize>`: `None` si `(col, row)` no está dentro
   de `body_area(app, area)`; si no, calcula las líneas con `transcript_owned(app, body.width)`, el mismo
   `offset` que usa `render` y devuelve el índice de entrada de la línea `offset + (row - body.y)` (o `None`
   si no hay línea ahí).
5. `run.rs`, hilo de teclado: en el brazo `TermEvent::Mouse(m)`, con
   `event::MouseEventKind::Down(event::MouseButton::Left)` envía
   `Msg::Ui(Event::Click { col: m.column, row: m.row })`.
6. `run.rs`, bucle principal: justo antes de `app.update(ev)`, si `ev` es `Event::Click { col, row }`,
   sustitúyelo: con `let size = term.size()?;` y
   `crate::render::entry_at(&app, Rect::new(0, 0, size.width, size.height), col, row)`, `Some(i)` →
   `Event::ToggleEntry(i)`; `None` → deja el `Click`.

```rust
/// Índice de la entrada dibujada en esa celda (`None` fuera de la transcripción).

```

## Ejemplo (entrada y resultado esperado)

```
app de `sample()` (tests de render.rs): entradas [User, Assistant, Tool bash con 5 líneas de salida], pantalla 80×24.
La tool se dibuja en la fila 7 ("✓ bash cargo test").
entry_at(&app, Rect::new(0,0,80,24), 5, 7) == Some(2)        entry_at(…, 5, 2) == Some(0)
entry_at(…, 5, 0) == None (cabecera)                          entry_at(…, 5, 23) == None (barra de estado)
app.update(Event::ToggleEntry(2)) -> app.expanded == {2} y la pantalla muestra "    l5"; otra vez -> se pliega ("… +2 líneas")
app.update(Event::ToggleEntry(0)) -> no cambia nada (no es una tool)
```

## Tests (con estos nombres)

- `raton_clic_en_tool_despliega`: `ToggleEntry(2)` sobre `sample()` hace que la pantalla 80×24 contenga `    l5`, y repetirlo vuelve a mostrar `… +2 líneas`
- `raton_clic_fuera_de_tools_no_hace_nada`: `ToggleEntry(0)` y `ToggleEntry(99)` dejan `expanded` vacío
- `raton_entry_at_localiza_la_entrada`: los cuatro casos de `entry_at` del ejemplo
- `raton_entry_at_con_scroll`: con 50 entradas `Info` y `app.scroll = 10`, la fila 18 corresponde a la entrada 44
- `raton_transcripcion_no_cambia`: `transcript_lines` devuelve el mismo número de líneas que antes para `sample()` (12) y los tests de render existentes siguen pasando

## No hagas

- No cambies lo que dibuja `render` cuando `expanded` está vacío
- No abras archivos ni enlaces con el clic
- No dupliques el cálculo del layout: `render` y `entry_at` usan `body_area`
