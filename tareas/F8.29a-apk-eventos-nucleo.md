## Objetivo

1. Crea `probar-jvm.sh` con el contenido exacto del *Ejemplo* y dale permiso de ejecución (`chmod +x`). Compila las
   clases de la app que no importan `android` junto con los tests y los ejecuta con JUnit 4 en la JVM, sin el SDK
   de Android (el SDK no está en los equipos de los agentes; la CI sigue usando gradle).
2. Crea `Eventos.java` (clase `final`, constructor privado, sin `import android`, sin bibliotecas de JSON) con lo de
   *Firmas*.
3. `Eventos.Sse.linea(l)`: quita un `\r` final. Línea vacía: si hay datos acumulados, los devuelve unidos con `\n`
   y vacía el acumulador; si no hay, devuelve `null`. Línea que empieza por `data:`: acumula lo que sigue (quitando
   UN espacio inicial si lo hay) y devuelve `null`. Cualquier otra línea (comentarios `:`, `event:`…): `null`.
4. `Eventos.texto(json, clave)`: busca la PRIMERA aparición de `"clave":` seguida, tras espacios opcionales, de una
   cadena entre comillas; devuelve su contenido deshaciendo los escapes `\"`, `\\`, `\/`, `\n`, `\t`, `\r` y
   `\uXXXX`. Si no está o el valor no es una cadena, `null`.
5. `Eventos.numero(json, clave, porDefecto)`: lo mismo para un entero (cifras con `-` opcional); si no, `porDefecto`.
6. `Eventos.aviso(json)`: con `tipo = texto(json, "tipo")`:
   - `approvalRequested` → `new Aviso("aprobacion", numero(json, "id", -1), texto(json, "action"))`
     (el primer `"id"` del evento es el de la aprobación).
   - `sessionUpdated` con `texto(json, "state")` igual a `done`, `failed` o `stuck` →
     `new Aviso("fin", numero(json, "id", -1), estado)`.
   - cualquier otro caso (incluido `json` nulo) → `null`.
7. `EventosTest.java` con los tests de la lista.

## Firmas (cópialas tal cual)

```java
// apps/android/app/src/main/java/dev/publiccode/app/Eventos.java
package dev.publiccode.app;

/** Eventos del demonio (SSE en /eventos): lectura y decisión de qué se notifica. Lógica pura, sin Android. */
public final class Eventos {
    /** Acumula líneas SSE y devuelve el contenido de `data:` cuando el evento termina. */
    public static final class Sse {
        /** Procesa una línea (sin el salto); devuelve los datos del evento completo o null. */
        public String linea(String l);
    }
    /** Lo que hay que notificar. */
    public static final class Aviso {
        /** "aprobacion" o "fin". */
        public final String tipo;
        /** Id de la aprobación o de la sesión. */
        public final long id;
        /** Acción pendiente o estado final. */
        public final String texto;
        public Aviso(String tipo, long id, String texto);
    }
    /** Valor de cadena de la primera aparición de la clave, o null. */
    public static String texto(String json, String clave);
    /** Valor entero de la primera aparición de la clave, o porDefecto. */
    public static long numero(String json, String clave, long porDefecto);
    /** Aviso que corresponde a un evento, o null si no se notifica. */
    public static Aviso aviso(String json);
}
```

## Tests (con estos nombres)

- `sseDevuelveLosDatosAlTerminarElEvento`: las líneas «data: {"a":1}» y «» devuelven null y luego {"a":1}; dos líneas data seguidas se unen con un salto
- `sseIgnoraComentariosYLineasVaciasSueltas`: «: latido», «event: x» y una línea vacía sin datos devuelven null
- `textoDeshaceEscapes`: de {"a":"l1\nl2 \"x\" \u00f1"} sale la cadena con salto de línea, comillas y ñ; una clave que no está da null
- `numeroLeeEnterosYUsaElValorPorDefecto`: de {"id": 42} sale 42, de {"id":"x"} y de una clave ausente sale el valor por defecto
- `avisoDeAprobacion`: el primer ejemplo da tipo aprobacion, id 3 y texto «bash: rm x»
- `avisoDeFinSoloEnEstadosFinales`: done, failed y stuck dan aviso de tipo fin; running, waitingApproval y cancelled dan null
- `otrosEventosNoAvisan`: un evento transcript, la cadena vacía y null dan null
