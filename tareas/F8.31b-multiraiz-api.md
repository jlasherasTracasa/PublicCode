## Objetivo

1. `lib.rs` de `pcode-protocol`: en `pub mod methods`, después de `WORKSPACE_TASKS`, añade
   `/// Carpetas abiertas: `{}` → `{name, path}[]` (la principal primero).` y
   `pub const WORKSPACE_ROOTS: &str = "workspace.roots";`.
2. `server.rs`, `AppState`: campo nuevo `roots: Mutex<crate::roots::Roots>` (en `new`:
   `Mutex::new(crate::roots::Roots::new(repo.clone()))`) y los métodos `add_root` y `root_of` de las firmas.
   `root_of` lee `p.get("root")` como cadena (ausente = vacía) y llama a `resolve`.
3. `server.rs`, función `rpc`: justo después de `let id = req.id;` calcula la raíz de la petición:
   `let ws_root = match st.root_of(&p) { Ok(r) => r, Err(e) => return rpc_err(id, -32602, e).into_response() };`.
4. En estas ramas del `match`, y solo en estas, sustituye `st.repo.clone()` por `ws_root.clone()`:
   `FS_LIST`, `FS_READ`, `FS_WRITE`, `FS_RENAME`, `FS_DELETE`, `FS_FILES`, `SEARCH_TEXT`, `GIT_STATUS`,
   `GIT_DIFF`, `GIT_STAGE | GIT_UNSTAGE`, `GIT_COMMIT`, `FS_OUTLINE`, `SEARCH_SYMBOLS` y `GIT_LINE_CHANGES`.
   Las demás (`SERVER_INFO`, `WORKSPACE_TASKS`, LSP, puntos de control, actividad, asistente, specs,
   sesiones y terminal) siguen con `st.repo`.
5. Rama nueva `methods::WORKSPACE_ROOTS`:
   `rpc_ok(id, serde_json::to_value(st.roots.lock().unwrap().list()).unwrap_or_default())`.
6. Tests en el módulo `tests` de `server.rs`: crea dos directorios con `tempfile::tempdir()`, el estado con
   `AppState::new(a.path().to_path_buf(), "/bin/true".into(), None)`, añade el segundo con `st.add_root`
   y llama con `call`.

## Ejemplo (entrada y resultado esperado)

```
// raíz principal A con "a.txt" = "soy A"; raíz extra B (nombre nb) con "b.txt" = "soy B"
call(&app, "fs.read", json!({"path": "a.txt"}), None)                  -> result.content == "soy A"
call(&app, "fs.read", json!({"path": "b.txt", "root": nb}), None)      -> result.content == "soy B"
call(&app, "fs.read", json!({"path": "b.txt"}), None)                  -> error (no existe en A)
call(&app, "fs.read", json!({"path": "../a.txt", "root": nb}), None)   -> error (fuera de la raíz B)
call(&app, "fs.read", json!({"path": "a.txt", "root": "zz"}), None)    -> error.code == -32602, "raíz desconocida: zz"
call(&app, "workspace.roots", json!({}), None)                         -> result con 2 elementos; result[1].name == nb
```

## Tests (con estos nombres)

- `multiraiz_dos_raices_no_se_mezclan`: los tres primeros casos del ejemplo (`a.txt` en A, `b.txt` en B con `root`, `b.txt` sin `root` da error)
- `multiraiz_ruta_de_otra_raiz_se_rechaza`: `../a.txt` con `root` de B da error aunque el archivo exista en el disco
- `multiraiz_raiz_desconocida_da_error`: `root` igual a `zz` da el código -32602 y el mensaje `raíz desconocida: zz`
- `multiraiz_lista_las_raices`: `workspace.roots` devuelve dos elementos con la principal primero
- `multiraiz_escribir_en_la_raiz_extra`: `fs.write` con `root` de B crea el archivo dentro de B y no en A
