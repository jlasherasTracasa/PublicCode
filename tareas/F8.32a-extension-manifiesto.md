## Objetivo

1. `crates/pcode-extensions/Cargo.toml`: en `[dependencies]` añade `toml.workspace = true`. En `lib.rs` añade
   `pub mod plugin;` y, en `enum ExtError`, la variante `Plugin(String)` con
   `#[error("pcode-extension.toml no válido: {0}")]` y su `///`.
2. Crea `plugin.rs` con lo de *Firmas* y sus tests. El manifiesto es un TOML como el del *Ejemplo*; las claves van
   en español con `#[serde(rename = "…")]`: `id`, `version`, `descripcion`, `capacidades`, `ordenes`, `skills` y
   las tablas `[mcp.<nombre>]` con `orden` y `entorno`. Todo menos `id` y `version` es opcional
   (`#[serde(default)]`). Claves desconocidas: error (`#[serde(deny_unknown_fields)]`).
3. `parse_manifest(text)`: lee el TOML y valida, devolviendo `ExtError::Plugin(mensaje)` en el primer fallo:
   - `id` con la forma `editor.nombre`: dos partes separadas por un punto, cada una de 1 a 60 caracteres ASCII
     alfanuméricos, `-` o `_` → si no, `id no válido: <id>`.
   - `version` vacía → `falta la versión`.
   - una capacidad que no esté en `CAPABILITIES` → `capacidad desconocida: <c>`.
   - una ruta de `ordenes` o `skills` vacía, absoluta (empieza por `/` o `\` o tiene `:`), o con algún componente
     `..` → `ruta no válida: <ruta>`. Las de `ordenes` deben acabar en `.md` → si no, `la orden debe ser un .md: <ruta>`.
   - un nombre de servidor MCP que no sea de 1 a 30 caracteres `a–z`, `0–9` o `-` → `nombre de servidor no válido: <n>`;
     con `orden` vacía → `el servidor <n> no tiene orden`.
   - cada capacidad de `required_capabilities` debe estar declarada → si falta, `falta declarar la capacidad «<c>»`.
4. `required_capabilities(m)`: `["mcp"]` si declara algún servidor MCP; si no, vacío. (Las órdenes y las skills son
   solo texto: no piden capacidad.)
5. `missing_approval(m, approved)`: capacidades declaradas en el manifiesto que no están en `approved`, en el orden
   del manifiesto y sin repetir.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-extensions/src/plugin.rs
//! Extensiones de PublicCode: una carpeta con `pcode-extension.toml` que declara servidores MCP, órdenes y skills,
//! y las capacidades que necesita. Aquí solo se lee y se valida el manifiesto.
use crate::ExtError;
use std::collections::BTreeMap;

/// Nombre del archivo de manifiesto.
pub const MANIFEST_FILE: &str = "pcode-extension.toml";
/// Capacidades que una extensión puede pedir.
pub const CAPABILITIES: &[&str] = &["mcp", "red", "shell", "escribir"];

/// Un servidor MCP que la extensión arranca en local.
#[derive(Debug, Clone, PartialEq, Eq, Default, serde::Deserialize)]
#[serde(default, deny_unknown_fields)]
pub struct McpDecl {
    #[serde(rename = "orden")]
    pub command: Vec<String>,
    #[serde(rename = "entorno")]
    pub env: BTreeMap<String, String>,
}

/// Manifiesto de una extensión.
#[derive(Debug, Clone, PartialEq, Eq, serde::Deserialize)]
#[serde(deny_unknown_fields)]
pub struct PluginManifest {
    pub id: String,
    pub version: String,
    #[serde(default, rename = "descripcion")]
    pub description: String,
    #[serde(default, rename = "capacidades")]
    pub capabilities: Vec<String>,
    #[serde(default, rename = "ordenes")]
    pub commands: Vec<String>,
    #[serde(default)]
    pub skills: Vec<String>,
    #[serde(default)]
    pub mcp: BTreeMap<String, McpDecl>,
}

/// Lee y valida un manifiesto.
pub fn parse_manifest(text: &str) -> Result<PluginManifest, ExtError>;
/// Capacidades que el contenido del manifiesto obliga a declarar.
pub fn required_capabilities(m: &PluginManifest) -> Vec<String>;
/// Capacidades declaradas que el usuario aún no ha aprobado.
pub fn missing_approval(m: &PluginManifest, approved: &[String]) -> Vec<String>;
```

## Ejemplo (entrada y resultado esperado)

```
id = "ana.herramientas"
version = "1.0.0"
descripcion = "Revisión de SQL y acceso a GitHub"
capacidades = ["mcp", "red"]
ordenes = ["ordenes/revisar-sql.md"]
skills = ["skills/sql"]

[mcp.github]
orden = ["npx", "-y", "@modelcontextprotocol/server-github"]
entorno = { GITHUB_TOKEN = "{env:GITHUB_TOKEN}" }

parse_manifest(ese texto) -> Ok(PluginManifest { id: "ana.herramientas", capabilities: ["mcp", "red"], mcp: {"github": …}, … })
missing_approval(&m, &["mcp".into()]) -> ["red"]
el mismo texto sin "mcp" en capacidades -> Err(Plugin("falta declarar la capacidad «mcp»"))
```

## Tests (con estos nombres)

- `manifiesto_valido`: el TOML del ejemplo se lee con su id, dos capacidades, una orden, una skill y el servidor github con su orden y su entorno
- `manifiesto_minimo`: solo id y version da listas y mapa vacíos y required_capabilities vacío
- `id_y_version_no_validos`: id «sinpunto», id «a.b.c» y version vacía dan Plugin con «id no válido» o «falta la versión»
- `capacidad_desconocida`: capacidades = [«root»] da «capacidad desconocida: root»
- `rutas_no_validas`: una orden «../x.md», una skill «/etc» y una orden «a.txt» dan «ruta no válida» o «la orden debe ser un .md»
- `capacidad_no_declarada_se_deniega`: un servidor MCP sin la capacidad mcp da «falta declarar la capacidad «mcp»»
- `falta_por_aprobar`: missing_approval con [mcp] aprobado devuelve [red]; con las dos aprobadas, vacío
- `clave_desconocida`: una clave «main = "x.js"» en el manifiesto da error

## No hagas

- No toques las funciones de extensiones de VS Code (`parse_package_json`, `install`, `list`…)
- No lances ningún proceso ni leas archivos: `parse_manifest` recibe el texto
- No añadas más dependencias que `toml`
- No aceptes valores de `entorno` con secretos escritos: no hay forma de saberlo aquí, pero no pongas ninguno en los tests (usa `{env:VAR}`)
- Pon `///` en cada campo público (en *Firmas* se han omitido por espacio)
