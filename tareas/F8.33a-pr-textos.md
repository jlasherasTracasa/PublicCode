## Objetivo

1. Crea `pr.rs` con las firmas de abajo. Lógica pura.
2. `pr_prompt(commits, diff)`: «Escribe el título y la descripción de un pull request para estos cambios.»,
   `# Commits` (una línea `- ` por mensaje), `# Diff` (en un bloque de código; si pasa de `MAX_DIFF_CHARS`
   caracteres se corta y se añade `[… diff recortado]`) y el formato de respuesta: primera línea
   `TITULO: <una línea, máximo 70 caracteres, sin punto final>`, después una línea `CUERPO:` y debajo el
   cuerpo en Markdown con las secciones `## Qué cambia`, `## Por qué` y `## Cómo probarlo`.
3. `parse_pr_text(text)`: busca la primera línea que empieza por `TITULO:` y la primera línea `CUERPO:`
   posterior; devuelve `(título sin espacios y recortado a 70 caracteres, todo lo que sigue a CUERPO: con
   trim)`. Si falta alguna de las dos marcas, o el título o el cuerpo quedan vacíos → `None`.
4. `pr_review_prompt(diff)`: «Revisa este pull request. Señala solo problemas reales: errores, riesgos de
   seguridad, tests que faltan.» + el diff (mismo recorte) + formato: una línea por comentario
   `- <archivo>:<línea>: <comentario>`, o `SIN COMENTARIOS`.
5. `parse_review_comments(text)`: cada línea `- archivo:línea: comentario` → `DraftComment`; las líneas que no
   encajan (o cuya línea no es un número) se ignoran; `SIN COMENTARIOS` → vacío.
6. `render_drafts(pr, comments)`: Markdown del borrador: `# Revisión del PR #<pr> (borrador)`, la línea
   `Nada de esto se ha publicado. Edita o borra comentarios y publícalos con: pcode pr revisar <pr> --publicar --si`
   y una línea `- <archivo>:<línea>: <comentario>` por comentario (o `Sin comentarios.`). Debe cumplirse
   `parse_review_comments(&render_drafts(n, &c)) == c`.
7. `lib.rs`: añade `pub mod pr;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-flow/src/pr.rs
/// Caracteres de diff que se envían al modelo como máximo.
pub const MAX_DIFF_CHARS: usize = 60_000;

/// Comentario de revisión en borrador.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DraftComment { pub file: String, pub line: u32, pub body: String }

pub fn pr_prompt(commits: &[String], diff: &str) -> String;
pub fn parse_pr_text(text: &str) -> Option<(String, String)>;
pub fn pr_review_prompt(diff: &str) -> String;
pub fn parse_review_comments(text: &str) -> Vec<DraftComment>;
pub fn render_drafts(pr: u64, comments: &[DraftComment]) -> String;
```

## Ejemplo (entrada y resultado esperado)

```
parse_pr_text("Claro:\nTITULO: Exporta a CSV\nCUERPO:\n## Qué cambia\nAñade csv.rs\n") → Some(("Exporta a CSV", "## Qué cambia\nAñade csv.rs"))
parse_pr_text("solo texto") → None
parse_review_comments("- src/a.rs:12: falta comprobar el vacío\nruido\n- src/b.rs:x: no vale\n")
  → [DraftComment { file: "src/a.rs", line: 12, body: "falta comprobar el vacío" }]
parse_review_comments("SIN COMENTARIOS") → []
```

## Tests (con estos nombres)

- `prompt_de_pr_lleva_commits_diff_y_formato`: el prompt contiene los mensajes, el diff y las marcas TITULO: y CUERPO:
- `prompt_recorta_el_diff_largo`: un diff mayor que MAX_DIFF_CHARS aparece cortado con el aviso de recorte
- `lee_titulo_y_cuerpo`: el primer caso del ejemplo
- `sin_marcas_no_hay_pr`: un texto sin TITULO: o sin CUERPO: da None
- `titulo_largo_se_recorta`: un título de 100 caracteres queda en 70
- `lee_comentarios_e_ignora_el_ruido`: el tercer caso del ejemplo da un solo comentario
- `sin_comentarios`: `SIN COMENTARIOS` da lista vacía
- `borrador_ida_y_vuelta`: parse_review_comments(render_drafts(7, c)) devuelve c
