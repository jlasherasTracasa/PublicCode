## Objetivo

1. `Cargo.toml` de `pcode-server`: añade `uuid = { version = "1", features = ["v4"] }` a `[dependencies]`
   (la misma línea que usa `pcode-cli`).
2. `server.rs`, `AppState`: campo `web: Mutex<crate::web_session::WebSessions>` (en `new`,
   `Mutex::new(Default::default())`) y el método `set_single_use_url` de las firmas.
3. `authorized`: la cabecera `Authorization: Bearer <token>` no cambia. La cookie vale si
   (a) el modo de un solo uso está apagado y es `pcode_token=<token>` (como hoy), o
   (b) es `pcode_sesion=<valor>` y `st.web.lock().unwrap().is_valid(valor)`.
4. `index`: si `authorized` ya es `true`, sirve la página sin tocar cookies. Si no, y hay `?t=` y token
   configurado, llama a
   `st.web.lock().unwrap().redeem(t_presentado, token, format!("{}{}", uuid::Uuid::new_v4().simple(), uuid::Uuid::new_v4().simple()))`:
   - `Redeem::Legacy`: sirve la página con la cookie de hoy (`pcode_token=<token>; HttpOnly; SameSite=Strict; Path=/`);
   - `Redeem::Session(v)`: sirve la página con `pcode_sesion=<v>; HttpOnly; SameSite=Strict; Path=/`;
   - `Redeem::AlreadyUsed`: 401 con el cuerpo de texto
     `Este enlace ya se usó. Vuelve a ejecutar pcode studio para obtener otro.`;
   - `Redeem::Wrong` (o sin `?t=`): 401 como hoy.
   Las cabeceras de seguridad (CSP, `nosniff`, `Referrer-Policy`) no cambian.
5. `main.rs`: añade a `Cmd::Studio` la opción oculta
   `#[arg(long = "enlace-reutilizable", hide = true)] reusable_link: bool,` (para pruebas con varios
   navegadores). En la rama `Cmd::Studio`, tras crear `st`: `st.set_single_use_url(!reusable_link);`. En la
   rama `Cmd::Ide`, tras crear `st`: `st.set_single_use_url(true);`. La rama `Cmd::Daemon` no cambia.
6. `e2e.js` (en `tools/studio/`): en la llamada `spawn(PCODE, ['studio', '--no-abrir', '--puerto', '0'], …)`
   añade `'--enlace-reutilizable'` a la lista (esa prueba abre el mismo enlace en varios navegadores).
7. Tests en el módulo `tests` de `server.rs` (nombres con prefijo `enlace_`).

## Ejemplo (entrada y resultado esperado)

```
// st.set_single_use_url(true) con token "tk"
GET /?t=tk                      -> 200, Set-Cookie: pcode_sesion=<64 hex>; HttpOnly; SameSite=Strict; Path=/
GET /?t=tk   (otra vez, sin cookie) -> 401, cuerpo "Este enlace ya se usó. Vuelve a ejecutar pcode studio para obtener otro."
GET /        con Cookie: pcode_sesion=<ese valor>   -> 200
POST /rpc    con Cookie: pcode_sesion=<ese valor>   -> 200
POST /rpc    con Cookie: pcode_token=tk             -> 401     (la cookie antigua ya no vale en este modo)
POST /rpc    con Authorization: Bearer tk           -> 200     (los clientes de la API no cambian)
```

## Tests (con estos nombres)

- `enlace_de_un_solo_uso_se_canjea_una_vez`: el primer GET `/?t=tk` da 200 con cookie `pcode_sesion=`; el segundo, sin cookie, da 401 y el cuerpo contiene `ya se usó`
- `enlace_la_cookie_de_sesion_autoriza_rpc`: con la cookie devuelta, `server.info` por `/rpc` responde 200; con `pcode_token=tk` responde 401
- `enlace_bearer_sigue_valiendo`: con un solo uso activo y el enlace ya canjeado, `Authorization: Bearer tk` responde 200 en `/rpc`
- `enlace_token_incorrecto_no_lo_gasta`: GET `/?t=mal` da 401 y después GET `/?t=tk` da 200
- `enlace_modo_antiguo_no_cambia`: sin `set_single_use_url`, dos GET `/?t=tk` seguidos dan 200 (como `web_con_token_pone_cookie`)
