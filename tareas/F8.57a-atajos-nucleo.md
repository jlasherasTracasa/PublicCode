## Objetivo

Una combinación se escribe en forma canónica: modificadores en el orden `Ctrl`, `Alt`, `Shift`, unidos
con `+`, y al final la tecla: `Ctrl+Shift+P`, `Alt+ArrowUp`, `F6`. Los atajos del usuario son un objeto
`{ "Ctrl+Alt+S": "Guardar" }` (combinación → nombre de la orden de la paleta; cadena vacía = desactivar).
1. Crea `atajos.js` con las cinco funciones de las firmas.
2. `combo(e)`: recibe un objeto como un evento de teclado (`key`, `ctrlKey`, `metaKey`, `altKey`,
   `shiftKey`). `metaKey` cuenta como `Ctrl`. Tecla: una sola letra va en mayúscula; el espacio es
   `Space`; el resto, tal cual (`Enter`, `ArrowUp`, `F6`, `/`). Si la tecla es un modificador (`Control`,
   `Shift`, `Alt`, `Meta`), devuelve `null`.
3. `parseCombo(text)`: normaliza lo que escribe el usuario: parte por `+`, recorta espacios, acepta
   `ctrl`, `control`, `cmd`, `alt`, `shift` y `mayús`/`mayus` en cualquier caja y devuelve la forma
   canónica. Debe quedar exactamente una tecla que no sea modificador; si no, `null`.
4. `resolve(bindings, c)`: `bindings[c]` si la clave existe (puede ser la cadena vacía); si no, `undefined`.
5. `setBinding(bindings, c, command)`: copia con `c` asignado a `command`; con `command` `null`, sin esa clave.
6. `conflicts(bindings, defaults)`: `defaults` es `{ combinación: orden }` de los atajos de fábrica.
   Devuelve `[{ combo, was, now }]` para cada combinación del usuario que también está en `defaults` con
   otra orden, en el orden de las claves de `bindings`.
7. Crea `atajos.test.js` con los tests de la lista.

## Ejemplo (entrada y resultado esperado)

```
combo({ key: "p", ctrlKey: true, shiftKey: true })       -> "Ctrl+Shift+P"
combo({ key: "s", metaKey: true })                       -> "Ctrl+S"
combo({ key: "ArrowUp", altKey: true })                  -> "Alt+ArrowUp"
combo({ key: " ", ctrlKey: true })                       -> "Ctrl+Space"
combo({ key: "Shift", shiftKey: true })                  -> null
parseCombo(" ctrl + mayús+p ")                           -> "Ctrl+Shift+P"
parseCombo("alt+F6")                                     -> "Alt+F6"
parseCombo("ctrl+")                                      -> null          parseCombo("a+b") -> null
resolve({ "Ctrl+I": "" }, "Ctrl+I") -> ""                resolve({}, "Ctrl+I") -> undefined
setBinding({ "Ctrl+I": "" }, "Ctrl+Alt+S", "Guardar")    -> { "Ctrl+I": "", "Ctrl+Alt+S": "Guardar" }
setBinding({ "Ctrl+I": "" }, "Ctrl+I", null)             -> {}
conflicts({ "Ctrl+S": "Terminal", "Ctrl+Alt+S": "Guardar" }, { "Ctrl+S": "Guardar" })
                                                         -> [{ combo: "Ctrl+S", was: "Guardar", now: "Terminal" }]
```

## Tests (con estos nombres)

- `combinacion_canonica`: los cuatro primeros casos de `combo` del ejemplo
- `solo_modificador_es_null`: `Shift`, `Control`, `Alt` y `Meta` dan `null`
- `lo_que_escribe_el_usuario_se_normaliza`: los dos primeros casos de `parseCombo` del ejemplo
- `combinacion_invalida_es_null`: `ctrl+`, `a+b` y la cadena vacía dan `null`
- `resolver_distingue_desactivado_de_ausente`: los dos casos de `resolve` del ejemplo
- `asignar_y_quitar_no_modifican_la_entrada`: los dos casos de `setBinding` del ejemplo y el objeto original no cambia
- `conflictos_con_los_de_fabrica`: el caso de `conflicts` del ejemplo; sin coincidencias devuelve `[]`
