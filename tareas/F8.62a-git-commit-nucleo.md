## Objetivo

1. Crea `commit_view.rs` con las firmas de abajo y tests en el mismo archivo.
2. `parse_commit(raw)`: `raw` es la salida de `git show --no-color --numstat --format=<SHOW_FORMAT> <rev>`. Hasta el carácter
   `\u{1e}` va la cabecera, con seis campos separados por `\u{1f}`: sha, autor, correo, segundos, asunto y cuerpo (el cuerpo se
   recorta con `trim`). Después van las líneas de `--numstat`: `añadidas<TAB>borradas<TAB>ruta`; en archivos binarios los dos
   números son `-` → `None`. Las líneas vacías se ignoran. Si no hay `\u{1e}` o faltan campos → `None`. `short` = 8 primeros caracteres.
3. `git_commit_info(root, rev)`: si `!crate::history::valid_rev(rev)` → `Err("revisión no válida".into())`. Lanza
   `crate::workspace::git(root, &["show", "--no-color", "--numstat", &format!("--format={SHOW_FORMAT}"), rev])` y devuelve
   `parse_commit(&salida).ok_or_else(|| "no se pudo leer el commit".to_string())`.
4. `lib.rs`: añade `pub mod commit_view;` debajo de `pub mod blame;`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-server/src/commit_view.rs
use crate::workspace::WsResult;
use std::path::Path;

/// Formato de `git show` que entiende `parse_commit` (campos con U+001F y fin de cabecera con U+001E).
pub const SHOW_FORMAT: &str = "%H%x1f%an%x1f%ae%x1f%at%x1f%s%x1f%b%x1e";

/// Un archivo tocado por un commit.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
pub struct FileStat { pub path: String, pub added: Option<u32>, pub deleted: Option<u32> }

/// Un commit completo (sin el diff).
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
pub struct CommitInfo { pub sha: String, pub short: String, pub author: String, pub email: String, pub time: i64, pub subject: String, pub body: String, pub files: Vec<FileStat> }

pub fn parse_commit(raw: &str) -> Option<CommitInfo>;
pub fn git_commit_info(root: &Path, rev: &str) -> WsResult<CommitInfo>;
```

## Ejemplo (entrada y resultado esperado)

```
raw = "a1b2c3d4e5f6a7b8c9d0a1b2c3d4e5f6a7b8c9d0\u{1f}Ana\u{1f}ana@x.es\u{1f}1700000000\u{1f}arregla x\u{1f}Detalle largo.\n\u{1e}\n3\t1\tsrc/a.rs\n-\t-\tlogo.png\n"
parse_commit(raw) == Some(CommitInfo { sha: "a1b2…c9d0", short: "a1b2c3d4", author: "Ana", email: "ana@x.es", time: 1700000000, subject: "arregla x",
  body: "Detalle largo.", files: [FileStat { path: "src/a.rs", added: Some(3), deleted: Some(1) }, FileStat { path: "logo.png", added: None, deleted: None }] })
```

## Tests (con estos nombres)

- `parsea_cabecera_y_archivos`: el ejemplo da autor, asunto, cuerpo recortado y dos archivos
- `binario_sin_numeros`: la línea con guiones da `added` y `deleted` en `None`
- `entrada_sin_cabecera_es_none`: un texto sin el carácter U+001E da `None`
- `commit_real_de_un_repo_temporal`: `git_commit_info(root, "HEAD")` falla por revisión no válida, y con el sha de `git rev-parse HEAD` da el asunto `inicio`

## No hagas

- No aceptes revisiones que no sean hexadecimales (ni `HEAD`, ni nombres de rama): así no se cuelan opciones de git
- Los tests usan un repo temporal
- No añadas dependencias
