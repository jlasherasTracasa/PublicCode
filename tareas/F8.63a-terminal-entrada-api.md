# F8.63a-terminal-entrada-api — API: `terminal.run {interactive}` y `terminal.input` (escribir en la entrada de una orden en marcha)

## Contexto (lee esto y nada más)

- crates/pcode-server/src/server.rs (campo `inputs` de `AppState` y método `AppState::write_input`: cómo se guarda y se usa el `ChildStdin` de una sesión; es el patrón que hay que imitar)
- crates/pcode-server/src/server.rs (función `rpc`: brazos `methods::TERMINAL_RUN` y `methods::TERMINAL_KILL`; test `workspace_por_rpc_y_terminal_con_eventos`: cómo se leen los eventos de la terminal en un test)

## Objetivo

1. `crates/pcode-protocol/src/lib.rs`, en `pub mod methods`: cambia el comentario de `TERMINAL_RUN` a
   `/// Lanza una orden en la terminal integrada: `{command, interactive?}` → `{id}`.` y añade debajo de `TERMINAL_KILL`:
   `/// Escribe en la entrada de una orden interactiva en marcha: `{id, text, eof?}` → `true`.` y
   `pub const TERMINAL_INPUT: &str = "terminal.input";`.
2. `server.rs`, struct `AppState`: añade el campo
   `terminal_inputs: Mutex<HashMap<u64, Arc<tokio::sync::Mutex<tokio::process::ChildStdin>>>>,` e inicialízalo en
   `AppState::new` con `Mutex::new(HashMap::new())`, junto a `terminals`.
3. `run_terminal`: añade el parámetro `interactive: bool`. Sustituye `.stdin(std::process::Stdio::null())` por
   `piped()` si `interactive` y `null()` si no. Justo después de lanzar el proceso (tras el `match cmd.spawn()`), si es
   interactiva: `if let Some(i) = child.stdin.take() { me.terminal_inputs.lock().unwrap().insert(id, Arc::new(tokio::sync::Mutex::new(i))); }`.
   Donde hoy se hace `me.terminals.lock().unwrap().remove(&id);` al terminar, añade también
   `me.terminal_inputs.lock().unwrap().remove(&id);`.
4. Añade a `impl AppState` el método `terminal_input` (firma abajo), imitando `write_input`: saca el `Arc` del mapa (si no está →
   `Err("esa orden no acepta entrada o ya terminó".into())`), hace `write_all(text.as_bytes())` y `flush()` (si fallan, `Err` con
   el texto del error) y, si `eof`, quita la entrada del mapa (al soltarse el último `Arc`, el proceso ve el fin de la entrada).
5. Función `rpc`: en el brazo `methods::TERMINAL_RUN` pasa
   `p.get("interactive").and_then(|v| v.as_bool()).unwrap_or(false)`; añade después de `TERMINAL_KILL` el brazo
   `methods::TERMINAL_INPUT`: lee `id` como en `TERMINAL_KILL`, `text = str_param(&p, "text")`, `eof` (bool, por defecto `false`) y
   responde `ws_reply(id, st.terminal_input(t, &text, eof).await.map(|_| true))`.
6. Tests nuevos en `mod tests` (con `#[cfg(unix)]`), imitando `workspace_por_rpc_y_terminal_con_eventos`; toda espera de eventos
   va dentro de `tokio::time::timeout(Duration::from_secs(10), …)`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-protocol/src/lib.rs, en `pub mod methods`
pub const TERMINAL_INPUT: &str = "terminal.input";

// crates/pcode-server/src/server.rs, en `impl AppState`
fn run_terminal(self: &Arc<Self>, command: String, interactive: bool) -> Result<u64, String>;
/// Escribe `text` en la entrada de la orden `id`; con `eof` cierra después la entrada.
async fn terminal_input(&self, id: u64, text: &str, eof: bool) -> Result<(), String>;
```

## Ejemplo (entrada y resultado esperado)

```
terminal.run {"command": "cat", "interactive": true}           → {"id": 1}
terminal.input {"id": 1, "text": "hola\n", "eof": true}        → true
eventos: terminalOutput {id: 1, text: "hola\n"} y terminalExit {id: 1, code: 0}
terminal.run {"command": "echo x"} y después terminal.input {"id": 2, "text": "a"} → error "esa orden no acepta entrada o ya terminó"
```

## Tests (con estos nombres)

- `terminal_interactiva_recibe_entrada`: `cat` lanzado con `interactive: true` devuelve por `terminalOutput` el texto enviado con `terminal.input` y termina con código 0 al mandar `eof`
- `terminal_interactiva_solo_si_se_pide`: `terminal.input` sobre una orden lanzada sin `interactive` devuelve un error que contiene `no acepta entrada`

## No hagas

- No cambies el comportamiento por defecto: sin `interactive` la entrada sigue cerrada (órdenes como `grep` sin archivos se quedarían esperando)
- No quites la comprobación de política (`check_command`) ni el tiempo máximo de 30 minutos
- No añadas dependencias (no hay pseudoterminal: es una tubería)
