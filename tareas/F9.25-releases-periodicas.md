# F9.25-releases-periodicas — Releases periódicas: versión, CHANGELOG y etiqueta tras cada bloque de tareas aceptadas

**Fase** F9 · **Ejecutor** coordinador · **Depende de** F9.01-push-por-tarea

> Generado desde `tareas/plan.toml`. Sigue `AGENTS.md` y la skill `tarea-haiku`.

## Toca (los únicos archivos que puedes crear o modificar, más tu informe)

- `Cargo.toml`
- `CHANGELOG.md`
- `tools/release.sh`
- `informes/F9.25-releases-periodicas.md`

## Contexto (lee esto y nada más)

- .github/workflows/release.yml (se dispara con etiquetas v*)
- CHANGELOG.md

## Objetivo

Cadencia: una release menor cuando cierra un bloque de F9 (base · IDE completo · extensiones y depurador) y un parche
cuando se corrige algo visible. `tools/release.sh X.Y.Z` comprueba que el árbol está limpio, que `cargo test
--workspace` pasa y que `CHANGELOG.md` tiene `## X.Y.Z`; cambia `version` en `[workspace.package]`, hace commit
`release: vX.Y.Z`, crea la etiqueta anotada y la empuja (`git push origin HEAD vX.Y.Z`). `--comprobar` solo valida que
la versión del Cargo.toml tiene su sección en el CHANGELOG. La release la publica el workflow.

## Tests (con estos nombres)

- `(sin tests unitarios)`: la aceptación valida el script y el CHANGELOG

## Aceptación (ejecútala una vez al final)

```bash
sh -n tools/release.sh && tools/release.sh --comprobar
```

Después: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, informe en `informes/F9.25-releases-periodicas.md` y commit `git add <toca> informes/F9.25-releases-periodicas.md && git commit -m "F9.25-releases-periodicas: …"`.
