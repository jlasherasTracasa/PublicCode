# F9.25-releases-periodicas — Releases periódicas: versión, CHANGELOG y etiqueta tras cada bloque de tareas aceptadas

**Fase** F9 · **Ejecutor** coordinador · **Hito** 1.2 · **Talla** S · **Depende de** F9.01-push-por-tarea

> Generado desde `tareas/plan/`. Sigue `AGENTS.md` y la skill `tarea-haiku`.

> **Por qué es del coordinador:** Publicar una release empuja una etiqueta `v*` al remoto (necesita permiso de push de etiquetas) y dispara el workflow que publica binarios: es una decisión del propietario y no se puede deshacer

## Toca (los únicos archivos que puedes crear o modificar, más tu informe)

- `Cargo.toml`
- `Cargo.lock`
- `CHANGELOG.md`
- `informes/F9.25-releases-periodicas.md`

## Contexto (lee esto y nada más)

- tools/release.sh (ya existe: `tools/release.sh X.Y.Z` publica; `tools/release.sh --comprobar` solo valida)
- .github/workflows/release.yml (se dispara con etiquetas `v*` y publica binarios, APK y SHA256SUMS)
- CHANGELOG.md (cada versión tiene su sección `## [X.Y.Z] — fecha`)

## Objetivo

El script ya está hecho. Esta tarea es publicar la primera release con él (v1.2.0) y dejar la cadencia escrita.
1. Comprueba que el hito 1.2 está cerrado: `tools/tareas/generar.py --estado` no debe listar tareas abiertas del
   hito 1.2 (salvo esta).
2. `CHANGELOG.md`: revisa que la sección `## [1.2.0]` cuenta lo que entra (IDE nativo, depurador, remoto,
   extensiones declarativas, modo opencode) y pon la fecha del día.
3. Árbol limpio (`git status --porcelain` vacío) y en la rama principal al día con el remoto.
4. Ejecuta `tools/release.sh 1.2.0`: pasa `cargo test --workspace`, cambia `version` en `[workspace.package]` de
   `Cargo.toml`, actualiza `Cargo.lock`, hace el commit `release: v1.2.0`, crea la etiqueta anotada `v1.2.0` y
   ejecuta `git push origin HEAD v1.2.0`.
5. Sigue el workflow `release` en GitHub hasta que el job `verify-install` termine bien. Si falla, corrige y publica
   un parche (`1.2.1`); nunca muevas ni borres una etiqueta ya empujada.
6. Cadencia a partir de aquí: una versión menor al cerrar cada hito (1.3, 1.4…) y un parche cuando se corrige algo
   visible para el usuario. Escríbelo en el informe.
