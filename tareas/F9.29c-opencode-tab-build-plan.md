## Objetivo

El modo plan ya existe (`App.plan`, Mayús+Tab, `Command::SetPlan`). En opencode se cambia con Tab.
1. `app.rs`, `key_main`: el brazo `KeyCode::Tab` pasa a ser: si `self.input.is_empty()`, haz exactamente lo
   mismo que el brazo `KeyCode::BackTab` (cambia `self.plan`, añade el `Entry::Info` y devuelve
   `Command::SetPlan`); si la entrada tiene texto, inserta los cuatro espacios como ahora. Para no duplicar,
   saca el cuerpo de `BackTab` a un método privado `fn toggle_plan(&mut self) -> Vec<Command>`.
2. `i18n.rs`: añade al final de `ES` y de `EN` (mismo orden) las claves
   `mode_build` = `" ▶ Construir · Tab cambia "` / `" ▶ Build · Tab switches "` y
   `mode_plan` = `" ◆ Plan · Tab cambia "` / `" ◆ Plan · Tab switches "`.
3. `render.rs`, caja de la entrada: añade al `Block` un título inferior con
   `.title_bottom(Span::styled(t(app.lang, clave), estilo))`, con `mode_plan` y `th.warning()` si `app.plan`,
   o `mode_build` y `th.dimmed()` si no.

Sin firmas: No añade API pública: un método privado en App, dos claves de i18n y un título en el dibujo

## Ejemplo (entrada y resultado esperado)

```
entrada vacía + Tab          -> [Command::SetPlan(true)] y app.plan == true; otro Tab -> [Command::SetPlan(false)]
entrada "a" + Tab            -> input == "a    " y ningún Command
pantalla 80×24, modo normal  -> la fila 22 empieza por "╰ ▶ Construir · Tab cambia"
pantalla 80×24, modo plan    -> la fila 22 empieza por "╰ ◆ Plan · Tab cambia"
```

## Tests (con estos nombres)

- `modo_tab_con_entrada_vacia_alterna_plan`: dos Tab seguidos devuelven `SetPlan(true)` y luego `SetPlan(false)`
- `modo_tab_con_texto_inserta_espacios`: con `a` escrito, Tab deja `input == "a    "` y no devuelve órdenes
- `modo_tab_se_ve_en_el_borde_80x24`: la fila 22 empieza por `╰ ▶ Construir` y, con `app.plan = true`, por `╰ ◆ Plan`
