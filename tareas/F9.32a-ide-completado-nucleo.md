# F9.32a-ide-completado-nucleo — IDE: leer las propuestas de `lsp.completion`, filtrarlas y convertirlas en fragmentos (lógica pura)

## Objetivo

1. Crea `completion.rs` con `Item`, `parse_items`, `filter` y `to_snippet` (firmas abajo) y sus tests. En `lib.rs`
   añade `pub mod completion;` en orden alfabético.
2. `parse_items(v)`: `v` es la respuesta de `lsp.completion`. Acepta una lista de objetos o un objeto con la lista
   en `items`; cualquier otra cosa da vector vacío. De cada objeto: `label` (cadena, obligatoria: sin ella se salta);
   `detail` (cadena, por defecto vacía); `insert` = el primero que exista de `textEdit.newText`, `insertText` y
   `label`; `snippet` = `true` si `insertTextFormat == 2` o si `snippet == true`. Como mucho `MAX_ITEMS` elementos.
3. `filter(items, word)`: los que tienen un `label` que empieza por `word` sin distinguir mayúsculas (con `word`
   vacía, todos), en el mismo orden, como mucho 50.
4. `to_snippet(item)`: `Snippet { prefix: label, description: detail, body }`. Si `item.snippet` es `true`, el
   cuerpo es `insert` tal cual (ya viene con huecos `$1`). Si es `false`, es texto literal: cada `$` de `insert` se
   escribe `\$` para que `expand` no lo tome por un hueco.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-ide/src/completion.rs
//! Autocompletado del servidor de lenguaje: lectura de la respuesta de `lsp.completion`.
use crate::snippets::Snippet;
use serde_json::Value;

/// Máximo de propuestas que se leen.
pub const MAX_ITEMS: usize = 200;

/// Una propuesta de autocompletado.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Item {
    /// Texto que se muestra.
    pub label: String,
    /// Detalle (tipo o firma).
    pub detail: String,
    /// Texto que se inserta.
    pub insert: String,
    /// Si `insert` usa la sintaxis de fragmentos (`$1`, `${1:x}`).
    pub snippet: bool,
}

/// Propuestas de la respuesta de `lsp.completion`.
pub fn parse_items(v: &Value) -> Vec<Item>;
/// Las propuestas cuyo `label` empieza por `word` (sin distinguir mayúsculas).
pub fn filter(items: &[Item], word: &str) -> Vec<Item>;
/// La propuesta como fragmento, para insertarla con `snippets::insert`.
pub fn to_snippet(item: &Item) -> Snippet;
```

## Ejemplo (entrada y resultado esperado)

```
parse_items(&json!([{"label": "println!", "detail": "macro", "insertText": "println!(\"$1\")", "insertTextFormat": 2},
                    {"label": "push", "textEdit": {"newText": "push_str"}}, {"detail": "sin label"}]))
   -> [Item { label: "println!", detail: "macro", insert: "println!(\"$1\")", snippet: true },
       Item { label: "push", detail: "", insert: "push_str", snippet: false }]
parse_items(&json!({"items": [{"label": "a"}]})) -> [Item { label: "a", detail: "", insert: "a", snippet: false }]
filter(&items, "PU") -> [el de «push»]
to_snippet(&Item { label: "$HOME".into(), detail: "".into(), insert: "$HOME".into(), snippet: false }).body -> "\\$HOME"
   (y `snippets::expand` de ese cuerpo devuelve el texto «$HOME»)
```

## Tests (con estos nombres)

- `lee_lista_y_objeto_con_items`: los dos primeros ejemplos; null, un número y una cadena dan vector vacío
- `text_edit_gana_a_insert_text`: con textEdit.newText e insertText a la vez, insert es el de textEdit
- `limite_de_propuestas`: una lista de 300 objetos válidos da MAX_ITEMS elementos
- `filtra_por_prefijo_sin_mayusculas`: «PU» encuentra push; la palabra vacía los devuelve todos; «zz» ninguno
- `texto_literal_escapa_el_dolar`: el último ejemplo; al pasar el cuerpo por snippets::expand sale $HOME
- `fragmento_del_servidor_conserva_los_huecos`: con snippet = true el cuerpo es igual a insert

## Notas

Contrato de F8.07: `lsp.completion` devuelve una lista de `{label, kind, detail, insertText, replaceStart?,
replaceEnd?, sortText}`, con `insertText` ya en texto plano (sin huecos). `kind`, `sortText` y `replaceStart/End` no
se usan aquí: el IDE sustituye la palabra que hay antes del cursor. La lectura acepta además las formas crudas del
LSP (`{items}`, `textEdit`, `insertTextFormat`) por si el demonio cambia.
