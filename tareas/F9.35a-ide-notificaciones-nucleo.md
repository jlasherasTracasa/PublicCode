# F9.35a-ide-notificaciones-nucleo — IDE: qué evento merece una notificación y cómo se envía con `notify-send` (tras un trait)

## Objetivo

1. Crea `notify.rs` con lo de *Firmas* y sus tests. En `lib.rs` añade `pub mod notify;` en orden alfabético (después
   de `pub mod lsp_pos;`).
2. `notice_for(ev, session)`: si `ev["tipo"] == "approvalRequested"` → `Some(Notice::Approval(texto de
   ev["approval"]["action"]))`. Si `ev["tipo"] == "turnFinished"` y `ev["session"]` es un entero igual a `session`
   (que debe ser `Some`) → `Some(Notice::Finished)`. Cualquier otro caso, `None`.
3. `should_notify(enabled, focused)`: `enabled && !focused` (si la ventana está delante, basta con lo que se ve).
4. `command(title, body)`: `["notify-send", "--app-name=PublicCode", "--icon=pcode", "--", title, body]`, con `body`
   recortado a 200 caracteres (`chars().take(200)`). El `--` evita que un texto que empiece por guion se tome por
   una opción.
5. `trait Notifier` con un solo método `notify(&self, title, body) -> bool`. `NotifySend` lo implementa: lanza
   `command(title, body)` con `std::process::Command` (`spawn`, sin esperar; stdin, stdout y stderr a
   `Stdio::null()`) y devuelve `true` si se pudo lanzar. En Windows y donde no esté `notify-send`, devuelve `false`
   sin más.
6. `send(notifier, notice, approval_title, finished_title)`: para `Approval(action)` llama a
   `notifier.notify(approval_title, &action)`; para `Finished`, a `notifier.notify(finished_title, "")`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-ide/src/notify.rs
//! Notificaciones de escritorio: qué evento avisa y cómo se manda (hoy con `notify-send`, tras un trait).
use serde_json::Value;

/// Lo que se le cuenta al usuario fuera de la ventana.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Notice {
    /// El agente pide aprobación para esta acción.
    Approval(String),
    /// El agente terminó su turno.
    Finished,
}

/// El aviso que corresponde a un evento del demonio (`session` = conversación abierta en el IDE).
pub fn notice_for(ev: &Value, session: Option<i64>) -> Option<Notice>;
/// Si hay que avisar: avisos activados y la ventana no tiene el foco.
pub fn should_notify(enabled: bool, focused: bool) -> bool;
/// Orden de `notify-send` para un aviso.
pub fn command(title: &str, body: &str) -> Vec<String>;

/// Quien sabe mostrar una notificación de escritorio.
pub trait Notifier {
    /// Muestra la notificación; `false` si no se pudo.
    fn notify(&self, title: &str, body: &str) -> bool;
}
/// Notificaciones con `notify-send` (Linux).
pub struct NotifySend;
impl Notifier for NotifySend { /* … */ }

/// Manda `notice` con `notifier`, con los títulos ya traducidos.
pub fn send(notifier: &dyn Notifier, notice: &Notice, approval_title: &str, finished_title: &str) -> bool;
```

## Tests (con estos nombres)

- `aprobacion_avisa_siempre`: el primer ejemplo da Approval con la acción, con session None y con Some(1)
- `fin_de_turno_solo_de_mi_sesion`: los tres ejemplos de turnFinished dan Finished, None y None
- `otros_eventos_no_avisan`: filesChanged, assistantDelta y un objeto vacío dan None
- `solo_si_no_tiene_el_foco`: los tres casos de should_notify
- `orden_de_notify_send`: el ejemplo de command; un cuerpo de 500 caracteres queda en 200
- `send_usa_los_titulos`: con un Notifier de prueba que apunta lo que recibe, Approval(«x») llama a notify(«A», «x») y Finished a notify(«F», «»)
