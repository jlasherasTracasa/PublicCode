# F9.40a-ide-tema-de-extension-nucleo — IDE: convertir un tema de color de VS Code en la paleta del IDE (lógica pura)

## Contexto (lee esto y nada más)

- crates/pcode-extensions/src/lib.rs (`pub fn strip_jsonc(text: &str) -> String`: quita comentarios y comas finales de un JSON de VS Code)

## Objetivo

1. Crea `theme_ext.rs` con `parse_color`, `is_dark` y `palette_from_theme` (firmas abajo) y sus tests. En `lib.rs`
   añade `pub mod theme_ext;` después de `pub mod theme;`.
2. `parse_color`: acepta `#rgb`, `#rrggbb` y `#rrggbbaa` (hexadecimal, mayúsculas o minúsculas). `#rgb` duplica cada
   cifra. Devuelve `Color32::from_rgba_unmultiplied(r, g, b, a)` (a = 255 si no viene). Cualquier otra cosa, `None`.
3. `is_dark(ui_theme)`: `false` para `"vs"` y `"hc-light"`; `true` para todo lo demás (`vs-dark`, `hc-black`, vacío).
4. `palette_from_theme(json, base)`: pasa `json` por `pcode_extensions::strip_jsonc` y lo lee con `serde_json`. Si no
   es JSON válido o no tiene un objeto `colors`, `None`. Si lo tiene, parte de una copia de `base` y, para cada
   campo, usa el primer color que exista y sea válido de esta tabla (si ninguno, se queda el de `base`):
   `editor` ← `editor.background` · `side` ← `sideBar.background` · `input` ← `input.background` ·
   `border` ← `panel.border`, `sideBar.border` · `fg` ← `editor.foreground`, `foreground` ·
   `fg_dim` ← `descriptionForeground` · `accent` ← `focusBorder`, `button.background` ·
   `on_accent` ← `button.foreground` · `hover` ← `list.hoverBackground` ·
   `active` ← `list.activeSelectionBackground` · `selection` ← `editor.selectionBackground` ·
   `line_number` ← `editorLineNumber.foreground` · `error` ← `editorError.foreground` ·
   `warning` ← `editorWarning.foreground` · `git_modified` ← `gitDecoration.modifiedResourceForeground` ·
   `git_added` ← `gitDecoration.untrackedResourceForeground` · `git_deleted` ← `gitDecoration.deletedResourceForeground`.
   `bubble_user` y `code_bg` se quedan como en `base`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-ide/src/theme_ext.rs
//! Temas de color de extensiones de VS Code: de su JSON (`colors`) a la paleta del IDE.
use crate::theme::Palette;
use eframe::egui::Color32;

/// Color de `#rgb`, `#rrggbb` o `#rrggbbaa`.
pub fn parse_color(s: &str) -> Option<Color32>;

/// Si un `uiTheme` de VS Code es oscuro.
pub fn is_dark(ui_theme: &str) -> bool;

/// Paleta a partir del JSON de un tema; lo que el tema no define se toma de `base`.
pub fn palette_from_theme(json: &str, base: &Palette) -> Option<Palette>;
```

## Ejemplo (entrada y resultado esperado)

```
parse_color("#fff")       -> Some(Color32::from_rgba_unmultiplied(255, 255, 255, 255))
parse_color("#1e1e2e80")  -> Some(Color32::from_rgba_unmultiplied(0x1e, 0x1e, 0x2e, 0x80))
parse_color("rojo")       -> None
palette_from_theme(r##"{ // comentario
  "colors": { "editor.background": "#101010", "foreground": "#eeeeee" } }"##, &DARK)
   -> Some(p) con p.editor = rgb(0x10,0x10,0x10), p.fg = rgb(0xee,0xee,0xee) y p.side == DARK.side
```

## Tests (con estos nombres)

- `colores_hex`: #fff, #1e1e2e y #1e1e2e80 dan los colores del ejemplo; «rojo», «#12» y «#gggggg» dan None
- `oscuro_segun_ui_theme`: vs y hc-light son claros; vs-dark, hc-black y la cadena vacía son oscuros
- `tema_con_comentarios`: el JSON del ejemplo cambia editor y fg y deja side como en la base
- `primera_clave_valida_gana`: con editor.foreground y foreground a la vez, fg toma editor.foreground
- `sin_colors_no_hay_paleta`: «{}» y «esto no es json» dan None

- No leas archivos: la función recibe el texto del JSON
