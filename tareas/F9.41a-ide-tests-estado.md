## Objetivo

El demonio (F8.14) no ejecuta los tests: dice qué orden lanzar y entiende su salida. El IDE lanza la orden con
`terminal.run`, junta la salida que llega por eventos y se la devuelve al demonio para que la interprete. Este
módulo guarda ese estado; no hace peticiones.
1. Crea `tests_view.rs` con lo de *Firmas* y sus tests. En `lib.rs` añade `pub mod tests_view;` en orden alfabético
   (después de `pub mod terminal;`).
2. `parse_runners(v)`: lista de `{"id", "label", "list"?, "runAll"}` (respuesta de `tests.runners`). `parse_items(v)`:
   lista de `{"id", "name", "group", "runner"}`. `parse_results(v)`: lista de `{"id", "ok"}` → `(id, ok)`. En las
   tres, lo que no sea una lista da vector vacío y los elementos sin `id` se saltan.
3. Captura de una orden. `expect()` avisa de que se va a lanzar una orden cuyo identificador aún no se conoce: pone
   `waiting = true` y vacía `backlog`. Mientras `waiting`, `apply(ev)` guarda una copia de cada evento
   `terminalOutput` o `terminalExit` en `backlog` (como mucho 2000; los siguientes se descartan) y devuelve
   `Applied::No` (otros módulos también los ven).
4. `begin(terminal, runner, mode)`: crea `capture` con ese identificador, pone `waiting = false`, y repasa `backlog`
   en orden aplicando solo los eventos cuyo `id` es `terminal` (por si la salida llegó antes que el identificador);
   después vacía `backlog`. Si entre ellos estaba el `terminalExit`, devuelve `Some(captura terminada)` y deja
   `capture` en `None`; si no, `None`.
5. `apply(ev)` con una captura en marcha y `ev["id"]` igual a su `terminal`: `terminalOutput` añade `ev["text"]` a
   `output` (si pasa de `MAX_OUTPUT` bytes, deja de añadir) y devuelve `Applied::Captured`; `terminalExit` saca la
   captura (`take`) y devuelve `Applied::Finished(captura)`. Cualquier otro evento, `Applied::No`.
6. `set_items(runner, items)`: sustituye los tests de ese ejecutor (los de otros se conservan) y borra los estados
   de los identificadores que ya no existen. `set_results(results)`: pone `Status::Ok` o `Status::Fail` a cada
   identificador (aunque no esté en `items`).
7. `status_of(id)`: su estado o `Status::Pending`. `groups()`: los tests agrupados por `group`, grupos en orden
   alfabético y tests en el orden en que están. `counts()`: `(total, correctos, fallidos)` sobre `items`.
   `mark(status)`: `"✓"`, `"✗"` o `"·"`.

## Firmas (cópialas tal cual)

```rust
// crates/pcode-ide/src/tests_view.rs
//! Explorador de tests del IDE: ejecutores, tests, resultados y captura de la salida de la terminal.
use serde_json::Value;
use std::collections::BTreeMap;

/// Tamaño máximo de la salida capturada de una orden.
pub const MAX_OUTPUT: usize = 1024 * 1024;

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Runner { pub id: String, pub label: String, pub list: Option<String>, pub run_all: String }
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct TestItem { pub id: String, pub name: String, pub group: String, pub runner: String }
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Status { Pending, Ok, Fail }
/// Para qué se lanzó la orden: listar los tests o ejecutarlos (es el `mode` de `tests.parse`).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Mode { List, Run }
impl Mode { /** `"list"` o `"run"`. */ pub fn as_str(self) -> &'static str; }
/// Salida de una orden de tests que se está juntando.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Capture { pub terminal: u64, pub runner: String, pub mode: Mode, pub output: String }
/// Qué hizo `apply` con un evento.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Applied { No, Captured, Finished(Capture) }

pub fn parse_runners(v: &Value) -> Vec<Runner>;
pub fn parse_items(v: &Value) -> Vec<TestItem>;
pub fn parse_results(v: &Value) -> Vec<(String, bool)>;
pub fn mark(s: Status) -> &'static str;

#[derive(Debug, Default)]
pub struct TestsState {
    pub runners: Vec<Runner>, pub items: Vec<TestItem>, pub status: BTreeMap<String, Status>,
    pub capture: Option<Capture>, pub waiting: bool, backlog: Vec<Value>,
}
impl TestsState {
    pub fn expect(&mut self);
    pub fn begin(&mut self, terminal: u64, runner: &str, mode: Mode) -> Option<Capture>;
    pub fn apply(&mut self, ev: &Value) -> Applied;
    /// Si hay una orden lanzada o en marcha (no se puede lanzar otra).
    pub fn busy(&self) -> bool;
    pub fn set_items(&mut self, runner: &str, items: Vec<TestItem>);
    pub fn set_results(&mut self, results: &[(String, bool)]);
    pub fn status_of(&self, id: &str) -> Status;
    pub fn groups(&self) -> Vec<(String, Vec<&TestItem>)>;
    pub fn counts(&self) -> (usize, usize, usize);
}
```

## Ejemplo (entrada y resultado esperado)

```
parse_runners(&json!([{"id": "cargo", "label": "Rust (cargo)", "list": "cargo test -- --list --format terse", "runAll": "cargo test"},
                      {"id": "npm", "label": "npm test", "runAll": "npm test"}]))
   -> [Runner { id: "cargo", list: Some("cargo test -- --list --format terse"), run_all: "cargo test", … }, Runner { id: "npm", list: None, … }]

let mut s = TestsState::default();
s.expect();                                                                  // se va a lanzar una orden
s.apply(&json!({"tipo": "terminalOutput", "id": 7, "text": "test a::uno ... ok\n"})) -> Applied::No   (guardado en backlog)
s.begin(7, "cargo", Mode::Run)                                               -> None; s.capture.output == "test a::uno ... ok\n"
s.apply(&json!({"tipo": "terminalOutput", "id": 7, "text": "fin\n"}))        -> Applied::Captured
s.apply(&json!({"tipo": "terminalOutput", "id": 9, "text": "otra orden"}))   -> Applied::No
s.apply(&json!({"tipo": "terminalExit", "id": 7, "code": 0}))
   -> Applied::Finished(Capture { terminal: 7, runner: "cargo", mode: Mode::Run, output: "test a::uno ... ok\nfin\n" }); s.busy() == false

s.set_items("cargo", vec![uno (group "a"), dos (group "a"), suelto (group "")]);  s.set_results(&[("a::uno".into(), true), ("a::dos".into(), false)]);
s.counts() -> (3, 1, 1)     s.groups() -> [("", [suelto]), ("a", [uno, dos])]     mark(s.status_of("a::dos")) -> "✗"
```

## Tests (con estos nombres)

- `lee_ejecutores_tests_y_resultados`: el ejemplo de parse_runners; parse_items y parse_results con una lista válida; null da vector vacío en las tres
- `captura_la_salida_de_su_orden`: tras begin(7…), los terminalOutput con id 7 se juntan en orden y los de otro id dan Applied::No
- `termina_con_terminal_exit`: terminalExit del id capturado da Finished con toda la salida y deja capture en None
- `salida_que_llega_antes_que_el_identificador`: el ejemplo con expect, un terminalOutput y begin: la salida anterior no se pierde
- `orden_que_acaba_antes_de_begin`: con expect, terminalOutput y terminalExit de id 7 y después begin(7…), begin devuelve Some(captura) con la salida
- `sin_expect_no_guarda_nada`: sin expect ni captura, apply da No y begin posterior empieza con salida vacía
- `resultados_y_recuento`: el último bloque del ejemplo (counts, groups y mark)
- `set_items_sustituye_solo_su_ejecutor`: los tests de otro ejecutor se conservan y los estados de tests que desaparecen se borran
- `salida_con_tope`: tras añadir más de MAX_OUTPUT bytes, output.len() no pasa de MAX_OUTPUT más el tamaño del último trozo admitido
