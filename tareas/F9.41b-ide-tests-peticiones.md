## Objetivo

1. `app.rs`: en `struct Ide`, campo `tests: crate::tests_view::TestsState` (`Default::default()` en `Ide::new`). En
   `enum Msg`, con `///`: `TestRunners(Value)`, `TestStarted(u64, String, Mode)` (identificador de la terminal,
   ejecutor y modo) y `TestParsed(String, Mode, Value)` (ejecutor, modo y respuesta de `tests.parse`).
2. Tres métodos nuevos en `impl Ide`. Como todavía no los llama nadie (la vista es F9.41c), ponles encima
   `#[allow(dead_code)] // los llama la vista de tests (F9.41c)`:
   - `fn tests_load(&self)`: con `self.spawn`, `c.call("tests.runners", json!({}))` → `Msg::TestRunners(v)`; si
     falla, `Msg::Toast(e, true)`.
   - `fn tests_discover(&mut self, runner: &str)`: si `self.tests.busy()`, no hace nada. Busca el ejecutor en
     `self.tests.runners`; si su `list` es `None`, no hace nada. Si es `Some(orden)`: `self.tests.expect()` y
     `self.tests_launch(orden, runner, Mode::List)`.
   - `fn tests_run(&mut self, runner: &str, test: Option<String>)`: si `self.tests.busy()`, no hace nada. Llama a
     `self.tests.expect()` y, con `self.spawn`: `c.call("tests.command", json!({"runner": runner, "test": test}))`
     (devuelve la orden como cadena), después `c.call("terminal.run", json!({"command": orden}))` y devuelve
     `Msg::TestStarted(id, runner, Mode::Run)`. Si alguna de las dos llamadas falla, devuelve
     `Msg::TestParsed(runner, Mode::Run, Value::Null)` (el paso 5 lo trata).
3. Método auxiliar `fn tests_launch(&self, command: String, runner: &str, mode: Mode)`: con `self.spawn`,
   `c.call("terminal.run", json!({"command": command}))`; el identificador es `v["id"].as_u64()`; devuelve
   `Msg::TestStarted(id, runner, mode)` o, si falla, `Msg::TestParsed(runner, mode, Value::Null)`.
4. `fn on_event`: justo antes de `if self.problems.apply(&ev) || self.term.apply(&ev)`, añade:
   `match self.tests.apply(&ev) { Applied::Finished(cap) => { self.tests_parse(cap); return; } Applied::Captured => return, Applied::No => {} }`.
   Método `fn tests_parse(&self, cap: Capture)`: con `self.spawn`,
   `c.call("tests.parse", json!({"runner": cap.runner, "mode": cap.mode.as_str(), "output": cap.output}))` →
   `Msg::TestParsed(cap.runner, cap.mode, v)`; si falla, `Msg::Toast(e, true)`.
5. `fn on_msg`: `Msg::TestRunners(v)` → `self.tests.runners = parse_runners(&v)`. `Msg::TestStarted(id, runner,
   mode)` → `if let Some(cap) = self.tests.begin(id, &runner, mode) { self.tests_parse(cap); }`.
   `Msg::TestParsed(runner, mode, v)`: primero `self.tests.waiting = false;` (por si la orden no llegó a lanzarse);
   después, con `Mode::List` → `self.tests.set_items(&runner, parse_items(&v))`; con `Mode::Run` →
   `self.tests.set_results(&parse_results(&v))`.

## No hagas

- No llames a `self.term.start` para estas órdenes: su salida no va a la terminal integrada, va a `self.tests`

- No interpretes la salida en el IDE: siempre `tests.parse`

## Notas

Cuando una orden no llega a lanzarse, `Msg::TestParsed(…, Value::Null)` hace que el paso 5 ponga `waiting = false`
sin cambiar ningún resultado.
Cada cadena que entra en un cierre de `self.spawn` hay que copiarla antes (`let runner = runner.to_string();`).
Importa lo que uses con `use crate::tests_view::{Applied, Capture, Mode, parse_items, parse_results, parse_runners};`.
