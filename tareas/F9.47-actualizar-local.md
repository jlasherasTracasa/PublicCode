## Objetivo

Quien desarrolla en su propio equipo repite siempre lo mismo: traer cambios, compilar e instalar. Una orden lo hace
en orden y para en el primer fallo, sin trucos de git que puedan perder trabajo.
1. Crea `tools/actualizar-local.sh` (`#!/usr/bin/env sh`, `set -eu`, bit de ejecución) que hace `cd` a la raíz del repo
   (`"$(dirname "$0")/.."`) y ejecuta en este orden los pasos de *Firmas*: `git pull --ff-only`,
   `sh tools/compilar-ligero.sh`, `sh install.sh --local target/ligero` y `"${PCODE_DIR:-$HOME/.local/bin}/pcode" --version`.
2. Opciones: `--sin-pull` se salta el pull (para instalar lo que ya hay); `--en-seco` no ejecuta nada y escribe por
   stdout cada orden en una línea, en el orden en que se ejecutaría, con el prefijo `+ `; pueden ir juntas en
   cualquier orden. Otro argumento: `uso: tools/actualizar-local.sh [--sin-pull] [--en-seco]` por stderr y código 2.
3. Antes del pull, si `git status --porcelain` no está vacío, escribe `Hay cambios sin commit: se compila lo que hay
   sin hacer pull` por stderr y se salta el pull (nunca `stash`, `reset` ni `checkout`). En `--en-seco` esta
   comprobación también se hace.
4. Crea `tools/instalar/test_actualizar.py` (con `#!/usr/bin/env python3` y bit de ejecución) con los tests de la
   lista; ejecutan el script con `--en-seco` desde la raíz real del repo con `subprocess.run(..., timeout=30)` y solo
   miran la salida, así que no compilan ni usan red.
5. En `docs/instalacion.md`, sección «13. Actualizar y desinstalar», añade: «Si compilas desde el código:
   `tools/actualizar-local.sh` (trae los cambios, compila con el perfil ligero e instala)».

## Firmas (cópialas tal cual)

```sh
# tools/actualizar-local.sh [--sin-pull] [--en-seco]
paso() { if [ "$seco" = 1 ]; then echo "+ $*"; else "$@"; fi; }
# pasos, en este orden:
paso git pull --ff-only                       # salvo --sin-pull o árbol con cambios
paso sh tools/compilar-ligero.sh
paso sh install.sh --local target/ligero
paso "${PCODE_DIR:-$HOME/.local/bin}/pcode" --version
```
